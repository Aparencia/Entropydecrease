### 顺带修复（探测链路时发现的潜藏缺陷）

- **荧光笔实际无样式**：v0.14 B 的 `remarkMarkHighlight` 产出 mdast `mark` 节点但未给 `data.hName`——mdast-util-to-hast 的 `defaultUnknownHandler` 把未知节点落成 `div`，`NoteMarkdown` 的 `components.mark` 按 hast tagName 匹配**从未命中**，`==文本==` 实际渲染为无样式的裸 div。REQ-239 一并修对（hName/hProperties 注入）并锁定端到端测试。
- **App.css 从未被引入**（模板残留；`ed-low-confidence` / `chatBlink` / 暗色 :root 均为死样式）——未动（引入会改变全局暗色观感），登记为后续项。

## 设计要点

### ① 图片插入（REQ-238）

```
Decoration.replace({ widget })            // 一律内联（无 block:true）
   ▲
   └─ CM6 ViewPlugin decorations 经 disallowBlockEffectsFor 校验——
      block:true → RangeError（用户实测：插入本地图片即报失败）
```

修复原则：**不碰 CM 内部语义、只去违规标志**；独立行图片由"所在行除图片语法外仅空白"天然独占一行。回归测试挂 `RichEditorView.test.tsx`（独立行图片渲染为 widget、不抛 RangeError、语法文本不残留）。

### ② 正文多色（REQ-239）

```
解析层（纯函数）：==(?:\[[a-z]+\])?([^=\n]+)==
   ├─ [色id] ∈ 12 色板（colorPalette.isColorId 校验）→ mark{colorId}
   ├─ 无前缀 → mark{}（默认黄 —— 存量 ==文本== 零迁移）
   └─ 未知色 id / 未闭合 / 跨行 / 代码块 → 原样保留（不猜色、不吞内容）
渲染层：mdast data { hName:"mark", hProperties.className:["note-mark","note-mark-{id}"] }
   → mdast-util-to-hast applyData 落 <mark class>（修复 hName 缺失）
样式层：note-mark.css —— 默认黄 #fde68a（沿用旧值）+ 12 色 × 双主题
   （前景按 WCAG AA ≥4.5:1 取黑/白；scripts/gen-mark-css.mjs 生成，防手工漂移）
编辑层：🖍 荧光按钮（RichEditorView + NoteEditView 降级版同入口）
   → 色板（NoteColorPicker 复用）→ wrapSelectionCommand ==[色]…== / ==…==
```

### ③ 对话转笔记（REQ-240）

```
顶栏「📄 转笔记」（整段）· AI 消息「📄 存为笔记」（至该条）
   → ChatSaveNoteDialog（标题默认取首条提问首行 ≤60 字；目标组下拉可选）
   → buildConversationMarkdown（纯函数）
        user → > **🧑 你（HH:MM）** + 逐行 > 引用块
        assistant → **🤖 AI（模型 · HH:MM）** + 正文（aborted 标注已停止）
        failed / 空内容跳过（失败内容无知识价值）
   → create_note { title, content, source:"manual", group_id? }
   → 成功态「在笔记页打开」（onOpenNote 现链）
```

### ④ 任务对话化（REQ-241）

```
聊天视图工具条 [✨ 发起任务 ▾] + Composer '/refine|/enrich' → TaskLaunchDialog
   ├─ 目标：会话列表（精修）/ 笔记列表（补充=九子项全选 d1~d3+b1~b6）
   ├─ 授权红线：ai_get_settings.authorized == false → confirm 同意 → ai_set_authorized
   ├─ 成本：ai_refine_estimate / ai_enrich_estimate → confirm（预估失败仅提示未知成本）
   └─ ai_refine_start / ai_enrich_start → onStarted → reloadTasks + selectTask
任务卡（TaskThreadCard，聊天线程内）：
   ├─ 进行中 pending/running：实时（排队/进行中文案 + 片数 + 查看轨迹）
   └─ 完成（succeeded/partial_failed，10 分钟窗口）：
        「💬 在对话中追问」→ buildTaskFollowUpPrompt（背景引用块 + 结果 800 字截断 + 开放引导）
        预填 Composer → 用户发送 → 继续在聊天线程对话
会话页精修启动 → onTaskStarted(sessionId, taskId) → App setPage("chat") + focusTaskId
   → ChatPage effect selectTask(focusTaskId)（任务视图选中，进度/轨迹即时可见）
```

### ⑤ 工作台深链（REQ-242）

```
TaskConversationView 任务卡（refine & succeeded）
   → onOpenRefineWorkbench(refId, taskId)
   → App：setFocusSessionId + setFocusRefineTaskId + setPage("sessions")
   → SessionsPage → SessionDetailPanel（autoTaskId 到达 → setViewMode("preview")）
   → NotePreviewView → AiRefineCard autoTaskId：
        挂载即 invoke ai_refine_result(taskId) → result + phase=done + 工作台直接展开
        （取回失败 → onAutoTaskMissing 回调——父层提示并清焦点）
```

### ⑥ 右键菜单（REQ-243）与元素去除（REQ-244）

```
host 侧（Windows 唯一可靠通道——DOM preventDefault 不保证抑制 WebView2 原生菜单）：
   with_webview → PlatformWebview.controller()
     → ICoreWebView2Controller::CoreWebView2() → ICoreWebView2::Settings()
     → SetAreDefaultContextMenusEnabled(false)          // 失败仅日志（降级不阻断）
前端：
   BrowserChrome 组件（App 壳挂载）：
     ① window contextmenu preventDefault（兜底 + 开发浏览器同效）
     ② input/textarea 右键 → 应用内小菜单（剪切/复制/粘贴/全选）
        - 粘贴 = clipboard.readText → setRangeText(光标处) + 补发 input 事件（驱动受控组件）
        - .cm-editor 除外（CM 自有编辑事务；Ctrl+V 主路径不受影响）
    自绘菜单（笔记行/组行/会话行）各自 stopPropagation——事件到不了 window，无竞争
```

## 验收标准

1. 插入本地图片/外链图/剪贴板图片不再报 RangeError，图片以 widget 内联渲染（独立行独占一行）
2. 编辑态「🖍 荧光」选色包裹选区；阅读态 `==[red]重点==` 呈红色底、`==重点==` 呈默认黄（深色主题双变体）
3. 会话顶栏「📄 转笔记」保存整段对话（提问引用 + 回答全文）；AI 消息「存为笔记」保存至该条的完整上文；可归组；保存后可跳笔记页
4. 聊天内「✨ 发起任务」/`/refine` `/enrich` 启动精修/补充；线程任务卡实时显示进行中任务；完成 10 分钟内可「在对话中追问」（Composer 预填结果要点）；会话页精修启动自动跳 AI 对话页
5. AI 任务段精修成功任务卡有「🛠 打开精修工作台」→ 会话页自动展开工作台（结果免重跑）
6. 全应用右键**无浏览器原生菜单**；笔记行右键菜单完整可用；组行右键打开 ⓘ 组管理；会话行右键打开详情；文本输入右键有应用内剪切/复制/粘贴/全选
7. 全量回归通过（cargo check / vitest 481 / tsc）
