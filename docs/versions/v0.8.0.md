## 三、核心技术架构决策

### 决策 1：自定义标题栏方案

**现状**：v0.7.0 已实现 BrowserWindow `frame: false` + CustomTitlebar 组件，但拖拽区域使用内联 style 存在维护问题，部分交互元素未正确设置 `no-drag`。

**方案**：
- BrowserWindow 保持 `frame: false` 配置
- 拖拽区域必须通过 **CSS 类**（非内联 style）设置 `-webkit-app-region: drag`
- 所有交互元素（按钮、输入框、下拉菜单等）通过 CSS 类设置 `-webkit-app-region: no-drag`
- CustomTitlebar 组件增强：品牌 Logo + 页面标题动态展示 + 窗口控制按钮
- 双击标题栏可最大化/还原
- 窗口控制 IPC：`window:minimize`、`window:maximize`、`window:close`、`window:isMaximized`

**关键文件**：`client/electron/windowManager.ts`（frame:false）、`client/electron/main.ts`、`client/src/components/layout/CustomTitlebar.tsx`、`client/electron/preload.ts`、`client/src/components/layout/AppLayout.tsx`

### 决策 2：CSP 安全策略

**现状**：Electron 应用未配置 Content Security Policy，存在 XSS 注入风险；IPC handler 无来源校验；WebSocket 连接无 JWT 校验。

**方案**：
- **IPC sender 验证**：所有 IPC handler 通过 `event.sender.id` 验证仅接受主窗口调用，非主窗口调用直接拒绝并记录告警日志
- **CSP 策略**：在 `main.ts` 中通过 `session.defaultSession.webRequest.onHeadersReceived` 注入 CSP header，开发环境使用宽松模式（`default-src 'self' 'unsafe-inline' 'unsafe-eval'`），生产环境使用严格白名单
- **WebSocket JWT 校验**：WebSocket 连接建立时携带 JWT token，服务端校验 token 有效性后建立连接

**关键文件**：`client/electron/preload.ts`、`client/electron/main.ts`、`client/electron/ipcUtils.ts`

### 决策 3：音效分类体系

**现状**：音效系统已集成但为单一开关控制，无法按类型独立管理音量和开关状态。

**方案**：
- 4 类音效独立控制：操作音效 / 成就音效 / AI 音效 / 番茄钟音效
- 每类音效独立开关 + 独立音量滑块（0-100%）
- 全局静音按钮一键生效（覆盖所有分类）
- 每个音效可单独点击预览播放
- 音效配置持久化到 settingsStore
- SoundSettings 页面集成到设置中心

**关键文件**：`client/src/lib/audio/SoundPlayer.ts`、新建 `client/src/lib/audio/audioConfig.ts`、新建 `client/src/pages/settings/SoundSettings.tsx`

### 决策 4：UI 设计系统——深海静谧主题

**现状**：v0.6.0 引入了橙+青双色系和 Framer Motion 动效，但全局色板不统一，组件间视觉风格不一致，缺乏系统性的设计规范。

**方案**：
- **色板统一**：深海静谧主题——极夜深青/深空蓝紫（深色模式）、晨曦砂白（浅色模式），功能色（专注蓝、认知琥珀金、苔藓绿、赛博青）
- **4px 基准网格**：所有间距、尺寸遵循 4px 倍数，确保视觉节奏一致
- **Tailwind 设计令牌**：在 `tailwind.config.js` 中统一定义色彩、间距、圆角、阴影等设计令牌
- **基础组件重做**：Button / Card / Input / Modal 等核心组件按新设计系统视觉重做
- **Framer Motion 动效规范**：页面转场（fade + slide, 300ms ease-out）、卡片翻转（rotateY + scale, 400ms）、按钮交互（scale 0.97 按压反馈, 150ms）

**关键文件**：`tailwind.config.js`、`client/src/index.css`、`client/src/components/ui/*`

**B1.3 — BUG-007：全局快捷键首次使用无引导**

- **修复方案**：首次触发全局快捷键时显示功能说明 Toast，包含快捷键组合和功能描述文字

**验收标准**：
- AC1：首次触发全局快捷键时显示功能说明 Toast
- AC2：Toast 包含快捷键组合和功能描述文字

**B1.4 — BUG-NEW-001：updater 定时轮询修复**
- **根因**：`updater.ts` 使用 `setInterval` 定时轮询检查更新，存在多次重复触发问题
- **修复方案**：移除 `setInterval`，改为应用启动延迟后仅执行一次 `checkForUpdates()`；保留手动触发 IPC handler

**验收标准**：
- AC1：应用启动延迟后仅执行一次 `checkForUpdates()`
- AC2：代码中无 `setInterval` 轮询（grep 确认）

## 八、被拒绝的替代方案

| 替代方案 | 拒绝理由 |
|---------|---------|
| UI 升级采用 CSS-in-JS 方案（styled-components） | Tailwind 设计令牌方案更轻量，与现有代码库一致，无需引入新依赖 |
| CSP 策略使用 Electron `webSecurity: false` | 严重安全漏洞，违反 Electron 安全最佳实践 |
| CSP 策略推迟至 v0.9.0 不做 | SEC-005 为 Must Have 发版阻塞项，安全加固不可推迟；通过开发环境宽松模式降低风险 |
| 音效分类使用 Web Audio API 直接控制 | 当前 Howler.js 方案已满足需求，Web Audio API 增加复杂度但无显著收益 |
| 关闭窗口确认使用系统原生 `dialog.showMessageBox` | 原生对话框样式不统一且无法自定义选项；React 组件方案更灵活且与深海静谧主题一致 |
| updater 使用 `setInterval` 但增加防重入锁 | 根本问题是轮询模式不适合桌面应用；启动单次检查 + 手动触发更简洁可靠 |
| IPC 安全使用 `contextBridge` 全量暴露 API | 应遵循最小权限原则，仅暴露必要的 IPC channel |
