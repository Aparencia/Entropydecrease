## 三、关键设计决策

1. **净化可逆优先**（延续 REQ-081/082 单一管线双出口）：所有净化/纠错/删除只作用于产物层（kept/filtered/merged 记录），原料 segments/ocr_blocks 表不动；被滤内容带原因/时间进 filtered 供预览对照复查。
2. **净化顺序**：UI 垃圾 → 碎片 → 低置信（既有五步链）→ **口语净化 + 结巴折叠** → **Filler-only 删除** → 相邻重复合并（净化后文本才做精确去重）。净化发生在 AI 三态判定（REQ-085）之前——规则层先净，AI 只判边界。
3. **接线优先于新建**（头脑风暴决策 4）：A1 复用 verbal_normalize/symbol_normalize（已有代码）、B1 扩充 ui_junk 黑名单机制、B3 复用 glossary——新代码量集中在 D2/E1/E2/E3。
4. **OCR 净化保守原则**：单字符丢弃需"非公式/表格上下文"豁免（region_kind 保护）；数字量词正则 `^[\d.]+万?$` 仅匹配独立短串（防误杀正文数字）；阈值 0.5→0.7 必须跑黄金语料回归验证不误杀。
5. **停止残留修复三件套**（会话31 实证驱动）：
   - R1：`audio_loopback::stop()` 从裸 `handle.join()` 改为 `is_finished()` 轮询 + 2s 超时 detach——**兑现模块注释"join 超时保护"的承诺**（原实现注释与代码不符）。
   - R2：前端全局徽标不再单一依赖 `live:status` 事件——`session:fusing` 到达即视为采集已停（融合开始 = 采集已停的天然信号），停止 invoke 成功后再拉 `live_session_status` 确认兜底。
   - R3：`list_sessions` 装配层检测"status=recording 但 manager 无活动会话"→ 调用 `mark_interrupted_sessions` 语义的单会话版（标 failed + ended_at），避免必须重启应用才翻案。
6. **元数据兼容**：notes 加列用 `ensure_column` 幂等迁移（ADR-014 先例）；旧笔记 rule_version/purify_stats 为 NULL 不猜不填（诚实降级）。
7. **标题**：沿用会话标题 +「（会话）」后缀（标题优化 E4 留后续，低价值）。
