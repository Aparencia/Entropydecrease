## 三、核心技术架构决策

### 决策 1：FEAT-017 学习启动仪式方案

**现状**：DashboardPage 已有基础学习概览卡片，但无任何"学习启动仪式"入口。用户打开应用后直接进入仪表盘，缺乏从"生活状态"过渡到"学习状态"的仪式感桥梁。

**方案**：
- 新增 `client/src/features/dashboard/components/StartupRitual.tsx` — 三步启动仪式组件
- **Step 1 — 回顾闪回（60s）**：从 Dexie 读取上次笔记末尾摘要（最后 200 字）+ 标题，展示"上次学到"卡片；支持标记掌握状态（已掌握/模糊/未掌握），间隔提取效应（Carpenter 2012）
- **Step 2 — 设定微目标（30s）**：输入框"本次我要完成____"+ 5 个常用快选标签（来自最近笔记标题）；Locke 目标设定理论 + 蔡格尼克效应
- **Step 3 — Box Breathing（60-90s）**：方形呼吸引导动画，严格 4-4-4-4 节奏（吸气 4s → 屏息 4s → 呼气 4s → 屏息 4s）；海军海豹突击队压力管理技术，等长节奏维持警觉+放松平衡
- DashboardPage 集成：首次每日打开应用时自动弹出（可跳过），设置项"不再显示"持久化到 Dexie `appSettings`
- 总时长硬限制 ≤ 90s（Step 1 + Step 2 可快速跳过，Step 3 可提前结束）

**关键文件**：新建 `client/src/features/dashboard/components/StartupRitual.tsx`、修改 `client/src/features/dashboard/pages/DashboardPage.tsx`

### 决策 2：FEAT-011 记忆锚点策略方案

**现状**：NoteEditPage 已集成 TipTap 编辑器，但无 AI 自动生成要点功能。后端 `summarize_chain.py` 可生成摘要，但无"实时编辑过程中定时触发"机制。

**方案**：
- 新增 `client/src/features/notes/components/AnchorPoint.tsx` — 记忆锚点侧边栏组件
- 编辑器计时器：NoteEditPage 新增编辑活跃度追踪（基于 `onUpdate` 回调），每累计 10-15 分钟活跃编辑触发一次锚点生成
- 后端新增 `POST /api/v1/ai/anchor-point` 路由 + `server/ai-gateway/chains/anchor_point_chain.py` + `server/ai-gateway/prompts/anchor_point_v1.txt`
- AI Chain 输入：当前笔记全文 + 最近 3 条已有锚点（避免重复）；输出：一句话核心要点（≤ 50 字）
- 前端展示：侧边栏锚点时间线（按生成时间倒序），正文中仅在 TipTap 文档对应位置插入不可见标记（`data-anchor-id` 属性），不干扰编辑流
- 离线时 LocalFallback：展示友好提示"AI 锚点将在联网后自动生成"+ 缓存上次成功结果

**关键文件**：新建 `client/src/features/notes/components/AnchorPoint.tsx`、`server/ai-gateway/chains/anchor_point_chain.py`、`server/ai-gateway/prompts/anchor_point_v1.txt`、修改 `client/src/features/notes/pages/NoteEditPage.tsx`

### 决策 3：FEAT-029 自适应番茄钟 AI 增强

**现状**：v0.7.0 已实现本地规则引擎（`adaptiveEngine.ts`），基于最近 7 天加权平均推荐时长。但缺少 AI 增强——无法综合考虑用户学习科目难度、疲劳模式等多维因素。

**方案**：
- 增强 `client/src/features/pomodoro/lib/adaptiveEngine.ts`：本地规则引擎优先（低延迟），联网时请求 AI 增强
- 增强 `server/ai-gateway/chains/recommend_chain.py`：新增 `mode=pomodoro` 参数，输入最近 14 天番茄钟历史（工作时长、完成率、中断次数、科目分布），输出推荐时长 + 理由
- 推荐变化约束：每次推荐与上次差异 ≤ ±5 分钟（防止剧烈波动）
- 本地规则引擎 fallback：AI 请求失败或超时（> 3s）时使用本地计算结果
- PomodoroSettingsPage 展示："AI 推荐 30 分钟（基于你最近 14 天数据）" + 手动微调滑块

**关键文件**：修改 `client/src/features/pomodoro/lib/adaptiveEngine.ts`、`client/src/features/pomodoro/store/usePomodoroStore.ts`、`client/src/features/pomodoro/pages/PomodoroSettingsPage.tsx`、`server/ai-gateway/chains/recommend_chain.py`

### 决策 4：FEAT-022 AI 启发式学习模式

**现状**：FeynmanSessionPage 已实现费曼学习法四步流程，但缺少"先发散后收敛"的 AI 引导。后端无苏格拉底追问 Chain。

**方案**：
- 新增 `client/src/features/feynman/pages/SocraticSessionPage.tsx` — 苏格拉底式学习会话页面
- 新增 `client/src/features/feynman/components/BrainstormPanel.tsx` — 头脑风暴面板组件
- **Phase 1（头脑风暴）**：用户输入概念 → AI 生成 ≥ 5 个发散角度（类比/反例/应用/历史/争议）→ 用户选择感兴趣的方向
- **Phase 2（苏格拉底追问）**：AI 针对选定方向连续追问，默认 5 轮（可在 Settings 中自定义上限 3-10 轮）；每轮用户先回答，AI 再补充/纠正/深化
- 后端新增 `POST /api/v1/ai/socratic` 路由 + `server/ai-gateway/chains/socratic_chain.py`
- 上下文管理：LangChain ConversationBufferWindowMemory，保持最近 N 轮对话（N = 用户设定上限）
- 会话结果可保存为费曼概念笔记（一键创建 FeynmanNote，内容 = 对话精华摘要）

**关键文件**：新建 `client/src/features/feynman/pages/SocraticSessionPage.tsx`、`client/src/features/feynman/components/BrainstormPanel.tsx`、`server/ai-gateway/chains/socratic_chain.py`、新建路由

### 决策 5：FEAT-023 预测驱动学习

**现状**：后端有 `feynman_question_chain.py` 可生成问题，但无"预测题"概念——用户先写猜测，学完后再揭示答案对比。

**方案**：
- 新增 `client/src/features/notes/components/PredictionPanel.tsx` — 预测面板（工具栏触发）
- 新增 `client/src/features/notes/components/PredictionResult.tsx` — 预测结果可视化
- 后端新增 `POST /api/v1/ai/predict` 路由 + `server/ai-gateway/chains/predict_chain.py`
- AI Chain 输入：课程标题 + 已有笔记内容；输出：3-5 个预测题（含预期答案要点）
- 流程：手动触发（NoteEditPage 工具栏"预测"按钮）→ 生成预测题 → 用户逐条写猜测 → 学完后揭示答案 → 预测误差可视化（正确/部分正确/错误，琥珀金高亮，非红色）
- 预测结果持久化到 Dexie `predictions` 表（Schema 升级）

**关键文件**：新建 `client/src/features/notes/components/PredictionPanel.tsx`、`client/src/features/notes/components/PredictionResult.tsx`、`server/ai-gateway/chains/predict_chain.py`

### 决策 6：FEAT-024 卡壳三级救援+孵化建议

**现状**：NoteEditPage 和 FeynmanSessionPage 无任何"卡壳"辅助机制。用户遇到困难时只能自行搜索或放弃。

**方案**：
- 新增全局 `client/src/components/RescuePanel.tsx` — 卡壳救援面板组件
- NoteEditPage / FeynmanSessionPage 集成"卡壳了"按钮（工具栏/快捷键 Ctrl+Shift+H）
- 后端新增 `POST /api/v1/ai/rescue` 路由 + `server/ai-gateway/chains/rescue_chain.py`
- **三级递进救援**：
  - Level 1（简化解释）：用更通俗的语言重新解释当前概念
  - Level 2（拆解子概念）：将复杂概念拆解为 3-5 个子概念，逐个解释
  - Level 3（推荐前置知识）：推荐学习当前内容需要先掌握的前置知识
- 前置知识匹配策略：先检索用户 IndexedDB 笔记（全文搜索关键词匹配），有匹配时优先推荐已有笔记；无匹配时回退通用知识推荐
- 孵化建议：卡壳超过 10 分钟时建议切换活动（联动番茄钟开始休息 / 切换到闪卡复习 / 换个科目）
- 每次救援结果记录到 Dexie，支持回溯查看

**关键文件**：新建 `client/src/components/RescuePanel.tsx`、`server/ai-gateway/chains/rescue_chain.py`、修改 `client/src/features/notes/pages/NoteEditPage.tsx`、`client/src/features/feynman/pages/FeynmanSessionPage.tsx`

### 决策 7：AI 功能离线策略统一方案

**现状**：各 AI 功能的离线处理不统一，部分直接报错，部分有 LocalFallback 但不一致。

**方案**：
- 统一策略：联网模式 + 云端模式可用 AI；本地模式用 LocalFallback 提供友好提示 + 缓存上次成功结果
- 新增 `client/src/lib/ai/aiFallbackManager.ts` — 统一 AI 降级管理器
- 降级层级：①缓存命中（展示上次结果 + "更新于 X 分钟前"）→ ②友好提示（"此功能需要联网，请在设置中切换模式"）→ ③功能隐藏（完全不可用时灰态 + Tooltip）
- 所有新增 AI 功能（启动仪式/锚点/启发式/预测/救援）均接入此管理器

**关键文件**：新建 `client/src/lib/ai/aiFallbackManager.ts`、修改各 AI 功能组件

### 决策 8：数据存储层统一迁移（Dexie → SQLite）

**现状**：当前使用 Dexie.js (IndexedDB) 作为本地主存储，19+ 张表，Schema 版本 8+。随 AI 功能演进（预测引擎、知识图谱、学习统计），对复杂查询、全文搜索、关联分析的需求日益增强，IndexedDB 已无法满足。

**方案**：
- 迁移到 better-sqlite3（Electron 主进程 native addon），利用其同步 API 与原生性能优势
- 渲染进程通过 IPC 调用主进程 SQLite 服务（替代直接 Dexie 访问），确保数据安全与进程隔离
- 利用现有 IRepository 接口抽象实现存储层切换，最小化上层业务代码改动
- 新增 FTS5 虚拟表替代 Dexie 倒排索引，支持中文分词（unicode61 tokenizer）
- 数据迁移脚本：IndexedDB → SQLite 一次性迁移（保留 IndexedDB 降级回退，迁移成功后标记 `migrationComplete` 标志）
- 单文件数据库极大简化备份/迁移/导出，支持用户手动备份数据库文件

**关键文件**：新建 `client/electron/db/sqliteService.ts`（主进程 SQLite 服务）、新建 `client/electron/db/schema.ts`（SQLite Schema 定义）、新建 `client/electron/db/migration.ts`（数据迁移脚本）、新建 `client/electron/db/fts5Search.ts`（FTS5 全文搜索）、修改 `client/src/lib/storage/StorageAdapter.ts`（SQLite 实现）、修改 `client/electron/main.ts`（IPC 注册）、修改 `client/electron/preload.ts`（数据访问 bridge）

### 4.0 Infra.0：存储架构迁移（预计 4-5 周）

**主题**：Dexie → SQLite 统一迁移，为 v1.0.0 AI 功能提供数据层基础设施

| 步骤 | 名称 | 涉及文件 | 风险 |

| I0.3 | IPC 数据访问层改造 | `electron/main.ts`、`electron/preload.ts`、全部 store 文件 | 高 |

**需求详细说明**：

**I0.1 — better-sqlite3 集成与 Electron 构建配置**
- **当前状态**：Electron 主进程未集成任何 SQLite 库，所有数据存储均在渲染进程通过 Dexie 访问
- **v1.0.0 范围**：
  - 安装 better-sqlite3 + 类型定义（`@types/better-sqlite3`）
  - electron-builder.yml 配置 native addon 打包（asarUnpack `*.node` 文件）

| R6 | 卡壳救援前端知识匹配准确率 | 中 | IndexedDB 全文搜索关键词匹配精度低，推荐不相关笔记 | 多关键词 OR 匹配 + TF-IDF 排序；匹配度低于阈值时直接回退通用知识推荐 |
| R7 | 苏格拉底追问 AI 质量不稳定 | 中 | AI 追问逻辑跳跃或重复，用户体验差 | Prompt 工程迭代优化 + 追问质量评估基准（连贯性/引导性/深度）；低质量时 fallback 到预设问题库 |
| R8 | 仪表盘跨模块数据聚合性能 | 低 | 大量历史数据聚合导致仪表盘页面加载缓慢 | Dexie 索引优化 + 数据预聚合（后台 Web Worker 定时计算）+ 分页加载 |

| R10 | better-sqlite3 native addon 跨平台编译问题 | 中 | Windows/macOS/Linux 平台编译失败或版本不兼容，影响构建流程 | electron-rebuild 统一编译流程；CI 多平台矩阵构建验证；锁定 better-sqlite3 稳定版本 |

| R12 | IndexedDB → SQLite 数据迁移完整性 | 高 | 迁移过程中数据丢失、类型转换错误或外键约束冲突，导致用户数据损坏 | 逐表迁移 + 行数校验；迁移前自动备份 IndexedDB；失败回退机制；迁移后数据抽检比对 |

## 八、被拒绝的替代方案

| 替代方案 | 拒绝理由 |
|---------|---------|
| 启动仪式使用 Pomodoro 倒计时替代 Box Breathing | Pomodoro 是工作节奏工具，非放松调频技术；Box Breathing 4-4-4-4 经海军海豹突击队验证，等长节奏维持警觉+放松平衡，更适合学习启动场景 |
| 记忆锚点使用前端本地摘要（无 AI） | 前端无 NLP 能力，无法生成高质量一句话要点；后端 AI Chain 可利用大模型语义理解能力 |
| 苏格拉底追问使用 WebSocket 流式输出 | 当前 AI 网关架构为 REST API + SSE；WebSocket 增加服务端复杂度且当前追问模式无需实时流式（等用户回答后再追问） |
| 卡壳救援使用 RAG 全量检索用户笔记 | 全量检索延迟高且需要向量数据库；IndexedDB 全文搜索 + 关键词匹配足够覆盖 MVP 场景，后续版本可升级 RAG |
| 预测驱动学习使用自动触发（进入笔记自动弹出） | 自动触发打断用户心流；手动触发（工具栏按钮）尊重用户自主权，符合自我决定理论 |
| 仪表盘使用第三方 BI 工具嵌入 | 引入外部依赖增加安装包体积+网络依赖；Recharts 已满足雷达图/热力图/趋势线需求 |
| wa-sqlite (SQLite WASM) 作为主存储 | WASM 版 SQLite 性能不如 native addon；不支持 FTS5 完整功能；与 Supabase 集成不兼容（已有 ADR 记录） |

## 十三、代码审查检查清单

每个 v1.0.0 PR 合并前需通过以下审查项：

### 通用审查项

- [ ] **编译通过**：`npm run build` 无错误
- [ ] **测试通过**：新增/修改代码附带对应测试，`vitest run` 全部 pass
- [ ] **无新增 TODO**：除非 TODO 关联了本版本后续步骤编号（如 `// TODO [v1.0.0-A2.3]`）
- [ ] **无 console.log**：生产代码中不允许 `console.log` 调试输出（logger 除外）
- [ ] **类型安全**：无新增 `any` 类型（除非有注释说明理由）；TypeScript strict 模式无新增 error

### AI 功能审查项（Alpha.1 / Alpha.2 步骤强制）

- [ ] **Token 预算管理**：多轮对话 Chain 有 Token 上限检查；超限时截断历史而非报错
- [ ] **错误处理**：AI 请求失败时 UI 有明确提示；不阻塞主流程；LocalFallback 正确触发
- [ ] **离线降级**：所有 AI 功能接入 `aiFallbackManager`；离线时有缓存/友好提示/功能隐藏三级降级
- [ ] **Provider Fallback**：后端 AI Chain 支持 3 家 Provider fallback；单 Provider 失败自动切换
- [ ] **Prompt 安全**：用户输入经 sanitize 后传入 Chain；防止 prompt injection

### 启动仪式审查项（Alpha.1 步骤强制）

- [ ] **动画性能**：Box Breathing 使用 CSS 动画（GPU 加速）；低端设备不卡顿
- [ ] **节奏精度**：4-4-4-4 节奏误差 < 100ms；使用 `requestAnimationFrame` 或 CSS `animation-duration` 精确控制
- [ ] **持久化**：跳过/不再显示状态正确写入 SQLite `appSettings`

### 存储迁移审查项（Infra.0 步骤强制）

- [ ] **native addon 编译**：better-sqlite3 跨平台编译成功；electron-builder 正确打包 `.node` 文件
- [ ] **Schema 完整性**：19 张表全部迁移到 SQLite；外键约束 + CHECK 约束正确；PRAGMA user_version 管理升级
- [ ] **IPC 安全**：数据访问 IPC handler 有参数校验；不暴露原始 SQL 给渲染进程；防止 SQL 注入
- [ ] **数据迁移**：迁移脚本幂等执行；行数校验一致；失败回退机制验证通过
- [ ] **性能基线**：单次 IPC 查询 < 50ms；批量查询 < 200ms；FTS5 搜索 < 100ms

### 记忆锚点审查项（Alpha.1 步骤强制）

- [ ] **非干扰性**：锚点侧边栏静默展示，不弹窗不打断编辑流
- [ ] **活跃度追踪**：仅累计活跃编辑时间（有 `onUpdate` 回调），挂机不计入
- [ ] **TipTap 标记**：锚点标记为不可见属性（`data-anchor-id`），不影响编辑器视觉

### 数据审查项（Beta.1 步骤强制）

- [ ] **图表性能**：雷达图/热力图/趋势线使用 Recharts 懒加载；大数据量时分页或聚合
