## 一句话

在既有事实源（notes/fragments）旁新增**派生索引**（kb_chunks + FTS5 影子表 kb_fts + kb_meta）：保存/删除/升笔记经生命周期钩子保持索引一致，`reindex_all` 一键兜底，`kb_search` 以 FTS5 全库检索（LIKE 旧链零改动保留）；无 embedding 也完整可用（v0.19.3 前 FTS-only 精度，引擎状态如实展示）。

## 关键校准/实现决定（偏离 spec 草案字面处如实登记）

1. **中文 BM25 切词口径（spec 遗留 spike 项）**：索引 tokenizer 用 **trigram**（非草案默认 unicode61 remove_diacritics）——unicode61 将连续中文句整段视为单 token，整句/子串查询全部落空；trigram 免分词器且 bundled SQLite ≥3.34 已含（FTS5 使能核查同时完成：libsqlite3-sys 0.30.1 bundled 恒编 `-DSQLITE_ENABLE_FTS5`，含运行时测试覆盖）。代价：<3 字符 token 无法入 MATCH → 查询规划把 2 字词（如"配色"）转 kb_chunks LIKE 子串扫描（个人库毫秒级，纯派生表不动 notes 旧链）。
2. **保存钩子时序（spec 草案："保存后 spawn_blocking 静默重索引"）**：改为**保存事务内同步重建**——Db 连接本由 Mutex 串行，异步线程只把毫秒级开销移出事务却引入"同笔记两次快速保存 → 旧内容后写覆盖新内容"的索引乱序竞态；同步事务内重建零竞态且不阻塞 UI 的量级不变。失败仍软记录（error_count/last_error 角标可见），保存不反悔。
3. **chunk 源 = 净化后正文**（notes.content/fragments.text 全部，归档碎片文本仍在库属素材）；标题不在 chunk 源内（ADR-029 决策 2 字面）——标题检索继续由既有 LIKE 链承担。
