## 二、设计：独立结构渲染层（方案 B）

### 架构

```
filter_note（净化，零改动）          structure_note.rs（新增，纯函数）
segments/ocr_blocks ──► NoteFilterResult ──► render_note_structure ──► 带结构的 NoteFilterResult
                      ▲                         │
                      │                         ├─ chapters（章节边界，analyze_session_opt 已有）
                      │                         ├─ outline（章节标题，detect_outline_smart 复用）
                      │                         └─ glossary（术语候选，analyze_session_opt 已有）
```

- `note_filter.rs` / `concat.rs` **零改动**（零回归）
- 新模块 `structure_note.rs`：纯函数、无 IO、单文件 ≤300 行、显式依赖注入
- 与 v0.8.0 AI 精修兼容：AI 版将来以"结构块数组"重写本层输出，规则版=生成结构块，同一协议（精修=整理不创作原则不受影响）

### 核心纯函数

```rust
// structure_note.rs
pub struct NoteStructureConfig {
    pub chapter_headings: bool,    // 章节标题入笔记（默认 true）
    pub glossary_block: bool,      // 词汇表块（默认 true）
    pub glossary_max_terms: usize, // 词汇表条目上限（默认 20，防噪音）
}

pub fn render_note_structure(
    result: &mut NoteFilterResult,
    chapters: &[ChapterBoundary],
    outline: &[OutlineEntry],
    glossary: &[GlossaryCandidate],
    config: &NoteStructureConfig,
) -> StructureStats  // { chapters, titled_chapters, glossary_terms } 并入 purify_stats
```

**章节 → 标题**（`## 章节 N [MM:SS]`）：
- 章节边界 `time_ms` → 在 `## 讲述内容` 内该时刻的段落前插入标题行（段落切分复用 `concat::split_transcript_paragraphs_with` 口径，与净化管线一致）
- 章节名 = 本边界→下一边界窗口内**第一个 outline 条目文本**（OCR 大字块/屏标题，复用 `outline::detect_outline_smart`）；无命中 → 占位"章节 N"
- 边界落在段内 → 段首插（粗粒度边界，不切段——诚实标注不伪造粒度）

**术语表 → 词汇表块**（笔记尾部 `## 词汇表`）：
- 每项 `- 术语（画面 ×N / 语音 ×M）`，按 score 降序，上限 `glossary_max_terms`
- 锚点：术语在 kept 段中首次出现处 → `[MM:SS]` 前缀（回跳语义，复用 REQ-165 锚点风格）

**空输入降级（诚实降级）**：无章节（口播档案）→ 不插标题；无术语 → 不出词汇表；配置全关 → 原样返回。

### 接线（commands_session.rs，双出口同口径）

`convert_to_note` 与 `preview_session_note` 在 `refresh_screen_points` 之后、落库/返回之前调用：
1. 装配 `SessionDetail`（load_note_material 已有 segments/ocr_blocks，补 events——章节真实信号）
2. `analyze_session_opt(detail, profile, ...)` 取 chapters/glossary（profile 从 `session.profile` 解析，回退 Lecture）
3. `outline::detect_outline_smart(ocr_blocks, &result.ocr_screens, ...)` 取章节标题
4. `render_note_structure(...)` 重写 markdown + 更新 stats

**结构渲染实现方式**：章节标题行作为段落数组元素插入（`kept` → `concat::split_transcript_paragraphs_with` 复切段落 → 按章节边界在段落间插入 `## 章节 N` 行 → `concat::assemble_markdown(title, paragraphs, ocr_points)` 复用现有组装 → 尾部追加 `## 词汇表` 块）。与净化管线段落口径一致（同一阈值配置）。

> 预览与落库**同一管线**（REQ-081 契约），结构输出一致性由构造保证。

### 配置（REQ-179）

`NoteStructureConfig`（chapter_headings / glossary_block / glossary_max_terms）**并入 `PurifyConfig`**（嵌套结构字段）：复用现有 JSON 校准与装配链（AppState.purify → PurifyEnv），零新装配点；`structure_note.rs` 消费独立类型，模块边界不破。全关 = v0.7.5 输出逐字节一致。

### 元数据

- `RULE_VERSION` 递增：`note-rules-0.7.5` → `note-rules-0.7.6`（REQ-171：产物可回答"用哪版规则生成"）
- `StructureStats` 并入 `purify_stats` JSON（前端预览统计卡可显示"章节 ×N / 术语 ×M"；旧笔记 NULL 诚实降级）
