## 一、版本概述

### 1.1 v0.26.0 定位

熵减 v0.25.0 已完成品牌迁移（课伴 → 熵减）与全仓规范化重构。学习启动仪式（FEAT-017）已在此前版本交付基础版三步流程（回顾闪回 + 微目标 + Box Breathing），但存在规格缺口与体验天花板：

- **掌握标记是"死数据"**：`StartupRitual.tsx` 中 `mastery` 状态被记录但从未持久化、未参与任何后续调度，"间隔提取效应"数据闭环未形成
- **微目标快选标签缺失**：`MicroGoal.tags` 恒为空数组，规格要求的"5 个常用快选标签"未实现
- **呼吸步骤无参与感**：RAF 每帧触发全组件重渲染（性能隐患）；用户可立即跳过，无"至少 1 圈"软引导
- **可用性缺口**："不再显示"无 UI 入口、无键盘导航/焦点陷阱、无 `prefers-reduced-motion` 支持
- **三步割裂**：三个独立屏幕切换，缺乏"从生活到学习"的连续心理过渡

v0.26.0 以一次完整头脑风暴（25 项创意全采纳，见第二章）为输入，将启动仪式从"三个弹窗"重塑为**"一次被呼吸包裹的连续体验"**，同时让回顾/目标环节产生真实数据闭环，并为老用户提供自适应轻量路径。

## 四、核心技术架构决策

### 决策 1：仪式状态机（useRitualMachine）

**现状**：`StartupRitual.tsx` 用 `useState(step)` 线性推进，243 行单文件，无法承载自适应编排与双路径 A/B。

**方案**：
- 新建 `useRitualMachine.ts` hook：以显式状态机管理仪式流程——输入"编排计划"（步骤数组），输出当前步骤、推进/回退/跳过动作、埋点事件
- 编排计划由 `ritualPlanner.ts` 纯函数生成：输入（上次会话数据有无、连续完成天数、当前时段、用户强度偏好、A/B 分组）→ 输出步骤序列与各步预算时长
- 组件层彻底拆分：`StartupRitual.tsx`（容器 ≤120 行）+ `RitualStepReview.tsx` + `RitualStepGoal.tsx` + `RitualStepBreathing.tsx` + `RitualComplete.tsx`（今日卡/光尘转场出口）
- 全部新文件含 `@ai-context` 中英双语注释，单文件 ≤300 行

### 决策 2：呼吸容器架构（RIT-01）

**现状**：呼吸只存在于第三步，前两步为静态卡片，三屏割裂。

**方案**：
- 新建 `BreathingProvider`（Context + 单一 RAF 源）：全仪式期间持续输出呼吸相位；相位文字状态仅在 phase 切换时更新（16s 内 4 次 setState），振幅类视觉全部走 CSS 变量（`--breath-scale`，由 CSS animation 驱动，GPU 加速）
- 回顾卡/目标输入区通过 CSS 变量订阅呼吸节奏（缩放 1.00~1.015、透明度 0.96~1.00），微弱到不干扰阅读但形成潜意识连续感
- 最后一步为"纯呼吸收尾"：视觉主体放大，完成 RIT-17 一圈点亮逻辑
- `prefers-reduced-motion` 时 Provider 输出静态相位，视觉降级为数字倒计时圆环（RIT-16）

### 决策 3：主题化呼吸生命体（RIT-13）

**现状**：呼吸可视化为抽象方块沿方形路径移动。

**方案**：
- 新建 `BreathingCreature.tsx`：读取 `useSceneTheme()`（已有 hook，`deep-sea` / `aurora-dome`）
- deep-sea：水母形态——径向渐变 + 多层椭圆 CSS 缩放模拟收缩舒张；aurora-dome：极光带——横向渐变带高度涨落
- 纯 CSS/SVG 实现（不引 canvas/WebGL），动画时长严格绑定 4-4-4-4 相位；保留方形虚线轨道作为节奏参照
- 低端设备与 reduced-motion 统一降级为倒计时圆环

### 决策 4：掌握标记与微目标数据闭环（RIT-06/09/10）

**现状**：`mastery` 状态未持久化；`MicroGoal.tags` 恒空；目标完成与否无回收。

**方案**：
- 本地存储新增 `ritualRecords` 仓储：`{ id, date, masteryMark, noteId, goalText, goalTags, goalCompleted, ritualDurationMs, planVariant, createdAt }`
- 掌握标记为"模糊/未掌握"时，经由闪卡 store 现有 API 生成一张复习卡（内容=上次笔记标题+摘要），进入今日待复习队列；结束页反馈"已为你安排 1 张复习卡"
- 目标接力：快选标签第一位固定为最近一条 `goalCompleted=false` 的目标；其余 4 个取自最近 10 条笔记标题高频词
- 目标下压：番茄钟 store 新增 `activeMicroGoal` 字段，计时页顶部展示；番茄钟会话结束时弹一次性确认"完成了吗？"回写 `goalCompleted`
- 全链路本地完成，无网络依赖

### 决策 5：AI 回顾小问与离线降级（RIT-08）

**现状**：回顾闪回为静态摘要展示，无 AI 参与。

**方案**：
- 复用 AI 网关现有问题生成链路，新增 `mode=ritual_recall` 参数：输入上次笔记摘要，输出一个 10 秒可答的小问题 + 参考要点（≤30 字）
- 前端接入统一降级策略：请求超时（>2s）或离线 → 无缝回退 RIT-05 记忆挑战卡（遮罩摘要模式），用户无感知差异
- 结果缓存：当日首次成功结果缓存于本地，重复打开不再请求
- 遵循"AI 功能必须支持离线降级"仓库约定，AI 不可用不阻塞仪式任何环节

### 决策 6：自适应编排系统（RIT-02+04 合并）

**现状**：仪式对所有用户所有时段呈现同一形态。

**方案**：
- `RitualSettings` 扩展：`{ enabled, lastRitualDate, skipToday, intensity: 'light'|'standard'|'deep', autoAdapt: boolean }`
- `ritualPlanner.ts` 编排规则（v0.26.0 交付机制，参数写死为保守初值）：
  - 无上次会话数据 → 裁剪回顾步骤
  - 连续完成 ≥7 天且 `autoAdapt=true` → 默认轻档（呼吸 1 圈 + 目标一行）
  - 22:00 后 → 放松版文案与更暗视觉
  - 手动 `intensity` 始终优先于自动判定
- 每次仪式落库 `planVariant` 与完成/跳过结果，为 v0.27.0 参数调优提供数据

### 决策 7：光尘转场与情感化层（RIT-18/19/20/21）

**方案**：
- 光尘转场：仪式完成后卡片以 CSS 粒子化淡出（30~40 个微光点，`transform` + `opacity` 动画，600ms），随后调用现有 3D 导航 API 触发相机飞向推荐模块；低端设备/reduced-motion 降级为普通淡出
- 仪式火种：`ritualRecords` 连续天数计算，火种图标亮度三档（今日已完成=亮、昨日中断=微光、更久=暗），无惩罚文案
- 呼气寄语：本地语料数组（30 条起步），仅在呼气相位淡入淡出，每次仪式最多 2 条
- 今日学习卡：`RitualComplete.tsx` 定格展示微目标+掌握标记+火种天数，存档入 `ritualRecords`，仪表盘"知识预览"区可回看

### 决策 8：呼吸引导音（RIT-14）

**方案**：
- 复用 `scripts/sound-gen` 音效生成管线新增 4 条引导音（吸气上行音、屏息持续低音、呼气下行音、圈满提示音），产物入 `client/public/sounds/`

## 九、被拒绝的替代方案

| 替代方案 | 拒绝理由 |
|---------|---------|
| 倒置结构（先呼吸后回顾）直接作为默认 | 缺乏数据支撑；降级为 A/B 假设由完成率裁决（冲突裁决 1） |
| 强度自选与自适应编排做成两个独立设置项 | 用户心智负担大且规则可能互相打架；合并为"偏好上限+范围内自动微调"（冲突裁决 2） |
| 呼吸生命体用 WebGL/three.js 实现 | 仪式层叠加在 3D 场景之上，再起 WebGL 上下文成本高；CSS/SVG 足以表达收缩舒张且降级路径简单 |
| AI 小问用流式输出 | 一个 10 秒小问无流式必要；一次性返回 + 2s 超时回退更符合仪式节奏 |
| 强制完成 1 圈呼吸才能开始学习 | 违背"低摩擦"北极星；软引导（一圈点亮）保留用户自主权 |
| 仪式火种与全局连续学习 streak 合并 | 两者语义不同（仪式完成 vs 任意学习行为）；合并会稀释仪式行为锚点价值 |
| 每帧驱动 React 状态实现呼吸同步 | 已被证实为性能反模式（现状问题）；改为 CSS 变量 + 相位事件 |
