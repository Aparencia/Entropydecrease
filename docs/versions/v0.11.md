## 关键决策与纪律

- **绑定粒度从一开始就是"组"**（v4 契约二）：闪卡/复习/结算全部按组，不经历"会话级→再提升"返工。
- **路由误判 ★★★★ 死法防御**（REQ-198）：信号冲突/低结构无领域诚实 NeedConfirm；路由理由 JSON 落组可见；一键改判 route_overridden=1（修改即记忆）。
- **feed 默认关**（v4 §11.3）：功能开关机制 + 后端命令层二次校验，Phase 2 验证前不默认启用。
- **弹性承诺**（路线图裁决 4）：review_logs 无 streak 字段，欠账卡仅按 due_at 排序——不追债不清零（N10 归零暴政防御）。
- **动机App化防御**（★★★★★）：复习面只有卡片与评分，零叙事元素；引擎先有真牙。
- **指标从第一天记**（v4 §8）：metrics_events 随复习/升级/结算同批落库——Phase 4 门控判据（碎片升级率）数据开始积累。
- **FSRS 取代 SM-2**（ADR-018）：crate 引入成功，SM-2 兜底条件未触发，不保留双实现（调度接口稳定可后补）。

## 一、范围（三块）

### 1. 内容分型（N13 续）—— action 卡最小版

- `flashcards.kind` 枚举扩展：fact / action（model 留接口不做）
- 动作卡生成规则（纯函数，golden TDD）：碎片文本含步骤语义信号
  （"第一步/步骤/先…然后/做法"等）→ kind=action；front=动作名（首句），
  back=步骤清单（按句号/序号拆分）；无步骤信号 → 维持 fact
- **不做**：动手闭环 UI（N12 暂停-操作-比对，practice_detect 接线另议）

### 2. 周契约视图 UI（弹性承诺呈现层）

- `contracts` 表（幂等建表）：group_id、week_start（周一零点）、target_days、
  target_cards、created_at——用户声明本周契约，非打卡 KPI
- 命令：`upsert_week_contract`（幂等覆盖本周）/ `week_contract_status`
  （本周承诺 vs 实际——review_logs 按周聚合纯函数）
- 组面板展开区"周契约"卡：本周目标设定 + 完成进度 + 断签不清零视觉 +
  **最小可行日徽标**（本周完成 3 卡即算成立，N9/N11 低谷生存的最轻形态）
- 弹性承诺纪律不变：无 streak、无惩罚、欠账不追

### 3. feed 消费闭环（最小范围，用户裁决）

- **新增** `delete_fragment` 命令（后端，带存在性校验）；`list_group_fragments` /
  `update_fragment_group`（已建未接）接线
- 组面板 feed 组展开区：碎片列表（文本预览 + 图片缩略，图片 resolve 复用
  app_data_dir 先例）+ 删除/移出组操作 + **空态引导**（"捕获几条试试"）
- 复习面/卡片列表"碎片卡"徽标（前端 Flashcard.fragmentId 已有）

## 二、进入论证摘要（feed 最小闭环）

- **半截体验**：原料层已建无消费面——捕获后看不见/删不掉/动不了
- **边际成本低**：学习循环与结算按组实现且不区分地形——是接线不是新建
- **门控死锁**：碎片升级率数据只有真实走通闭环才有——不接通则 Phase 4 永不解锁
- **纪律保持**：开关默认关；零新界面（全部复用组面板/复习面/结算仪式）；
  单句碎片不出卡已防御；碎片→笔记自动升级不做（身份诚实）

## 三、边界（不做清单）

碎片→笔记升级 · 三根柱子（显影/时机/容器层）· 测量层基座（技能地图/盲测/常模）·
feed 专属界面 · 碎片卡 AI 生成 · 动手闭环 UI · 社交见证结构

## 四、测试与验收
