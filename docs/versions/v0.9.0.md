## 三、核心技术架构决策

### 决策 1：三模式架构改造

**现状**：当前模式切换基于 boolean `isLocal`，仅支持本地/联网两态，无法满足云端模式的差异化功能控制。

**方案**：
- 从 boolean `isLocal` 改为枚举三态 `'local' | 'network' | 'cloud'`
- 本地模式：纯本地运行，AI 和同步功能优雅隐藏 + 提示"需要联网模式"
- 联网模式：支持 AI 功能（通过 Electron AI Gateway），无云端同步
- 云端模式：全功能（ AI + 云端同步  冲突解决
- 新增 `hooks/useMode.ts`：导出 `type AppMode = 'local' | 'network' | 'cloud'` + `useMode()` hook
- 新增 `lib/mode/ModeManager.ts`：模式切换逻辑 + 数据迁移协调 + 自动降级策略
- 新增 `settings/ModeSettings.tsx`：设置页三模式 UI + 功能对比表 + 切换确认
- 首次启动引导用户选择模式，选择后锁定；切换需手动触发 + 二次确认
- 网络断开时自动降级到联网→本地模式并 Toast 提示

**关键文件**：新建 `client/src/hooks/useMode.ts`、`client/src/lib/mode/ModeManager.ts`、`client/src/pages/settings/ModeSettings.tsx`

### 决策 2：笔记全文全文搜索方案

**现状**：笔记数据存储在 Dexie 中，缺少全文搜索能力，仅支持标题模糊匹配。

**方案**：
- Dexie 新增 `SearchIndex` 表：`{ id, noteId, tokens: string[], field: 'title'|'content'|'tag', position: number }`
- 笔记写入时异步构建倒排索引：分词 → 去停用词 → 写入 SearchIndex 表
- 搜索时：分词查询 → 多表 JOIN → 按相关度/时间/标题排序
- 搜索栏：实时分词查询，1000 篇笔记全文搜索 < 500ms
- 搜索结果关键词高亮：前端 `<mark>` 包裹匹配词元
- 标签 CRUD：创建/编辑/删除，标签存储在笔记元数据中
- NotesPage 新增搜索栏 + 标签筛选器 + 排序切换

**关键文件**：修改 `client/src/lib/storage/database.ts`（Schema 新增 SearchIndex 表）、`useNoteStore.ts`、`NotesPage.tsx`

### 决策 3：高自信错误追踪

**现状**：复习时仅有评分（是/否）二档，无法区分"高自信但答错"的黄金错误。

**方案**：
- 复习时新增三档自信度选择器（低/中/高），修改 `confidence` 字段
- 黄金错误判定：`confidence === 'high' && score === 'wrong'` → 标记为 `goldenError`
- 黄金错误的 SM-2 间隔缩短 30%（复习频率增加）
- 新增错误追踪面板：按时间线展示错误次数、自信度分布、黄金错误占比趋势图
- 数据层扩展 `useStudySessionStore` 新增 `goldenErrors`、`confidenceHistory` 字段

**关键文件**：修改 `client/src/features/study-session/pages/StudySessionPage.tsx`、`useStudySessionStore.ts`、`types/models.ts`

### 决策 4：生成式复习模式

**现状**：闪复习流程为"看问题→想答案→揭示"，缺少主动回忆和填空模式。

**方案**：
- 先输入回忆内容：文本输入框 →用户先写出记忆中的答案
- 再揭示标准答案：差异对比高亮（逐行 diff，正确绿色、错误红色、缺失灰色）
- 填空模式：基于规则挖空关键词（名词、专有名词、数字   ），离线可用
- 挖空后词用 `<input>` 替换，用户填写后即时校验
- 新建 `GenerativeReviewPage.tsx` 页面组件 + 对应路由

**关键文件**：新建 `client/src/pages/GenerativeReviewPage.tsx`、修改 `useStudySessionStore.ts`

### 决策 5：备份格式与加密

**现状**：无本地备份/恢复机制，数据仅存储在 Dexie 中，存在意外丢失风险。

**方案**：
- 备份格式：`.kban-backup`（ZIP 格式，内含所有 Dexie 表 + 配置文件 JSON）
- 加密备份：`.kban-backup.enc`（AES-256-GCM 加密，用户设置密码）
- 自动备份：保留最近 2 份，可设置自动备份间隔，可关闭
- 手动备份：`dialog.showSaveDialog`  路径
- 恢复：备份选择 dialog → 校验完整性 → 解密（如加密）→ 恢复 Dexie
- 备份元信息 JSON appSettings` 新增 `keban-backup-password`

**关键文件**：修改 `client/electron/main.ts`（IPC）`client/src/lib/storage/exportImport.ts`

## 八、被拒绝的替代方案

| 替代方案 | 拒绝理由 |
|---------|---------|
| 全文搜索使用 SQLite FTS5 | 当前使用 Dexie，引入 SQLite 增加 Electron 安装包体积和复杂度；Dexie 倒排索引方案纯 JS 实现足够 |
| 三模式使用运行时动态切换 | 运行时动态切换增加状态管理复杂度，用户体验不可控；首次锁定 + 手动切换更稳定 |
| 备份格式使用 JSON 明文包 | JSON 明文包体积大且无安全性；ZIP 格式压缩率高 + AES-256 加密可选 |
| 同步冲突使用 Last-Write-Wins | LWW 策略简单但数据丢失风险高；三向对比更安全，用户可精确决策 |
| 生成式复习使用 AI 生成挖空 | AI 生成依赖网络且延迟高；基于规则的离线挖空方案满足离线可用需求 |
| 差异对比使用 Monaco Editor | Monaco Editor 体积过大（>5MB），增加安装包体积；轻量 diff 组件足够 |

## 十三、代码审查检查清单

每个 v0.9.0 PR 合并前需通过以下审查项：

### 通用审查项

- [ ] **编译通过**：`npm run build` 无错误
- [ ] **测试通过**：新增/修改代码附带对应测试，`vitest run` 全部 pass
- [ ] **无新增 TODO**：除非 TODO 关联了本版本后续步骤编号（如 `// TODO [v0.9.0-A12.2]`）
- [ ] **无 console.log**：生产代码中不允许 `console.log` 调试输出（logger 除外）
- [ ] **类型安全**：无新增 `any` 类型（除非有注释说明理由）；TypeScript strict 模式无新增 error

### 三模式架构审查项（Alpha.2 步骤强制）

- [ ] **模式完整性**：三模式（local/network/cloud）切换覆盖所有功能模块

- [ ] **数据迁移**：模式切换时数据迁移有备份 + 失败可回滚

### 学习引擎审查项（Alpha.1 步骤强制）

- [ ] **搜索性能**：1000 篇笔记全文搜索 < 500ms；索引构建不阻塞主线程

- [ ] **离线可用**：填空模式挖空规则离线可用；不依赖网络

- [ ] **更新提示**：Markdown 更新日志渲染正确；下载进度实时展示
