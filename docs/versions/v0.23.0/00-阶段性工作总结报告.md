# Entropy Decrease（熵减 / 课伴）项目阶段性工作总结报告

> **报告基准**：仓库当前状态 · 版本 v0.23.0（2026-07-28）· 许可证 BUSL-1.1
> **项目定位**：面向学生与终身学习者的 AI 智能学习桌面应用，践行费曼学习法与间隔重复，核心理念为 **本地优先（Local-First）+ AI 增强可选**。迁移后客户端包名已更名为 `entropy-decrease`（"熵减 - 跨端学习平台"）。

## 一、项目整体架构概览

### 1.1 四层 Monorepo 结构

| 模块 | 路径 | 职责 | 技术栈 |
|------|------|------|--------|
| 桌面客户端 | `client/` | Electron 主进程（IPC/数据库/截图/托盘/自动更新）+ React 渲染进程 | Electron 35 / React 18 / Vite 8 / TS 6 |
| AI 网关 | `server/ai-gateway/` | 多模型路由、限流、缓存、JWT 鉴权、降级链 | Python / FastAPI / Redis |
| 同步服务 | `server/sync-service/` | CRDT 增量同步 REST + WebSocket 实时通道 | Go 1.25 / Gin / PostgreSQL / Redis |
| 官网 | `website/` | 静态落地页与下载引导 | Next.js 16 / React 19 / Tailwind 4 |

辅助设施：`scripts/`（semantic-release 版本管理、音效生成、学习会话检测）、`docs/`（全生命周期文档）、`.github/workflows/`（5 条 CI/CD 流水线）。

### 1.2 依赖方向与模块关系

```
渲染进程 (React) ──IPC──▶ Electron 主进程 ──▶ SQLite / Ollama / MCP Bridge
      │                          │
      │ (Supabase 认证)          └──▶ 远端 AI Gateway (FastAPI)
      └──HTTP/WS──▶ sync-service (Go) ──▶ PostgreSQL + Redis
```

- 渲染进程按 **features 目录组织** 7 个业务模块（feynman、pomodoro、notes、flashcards、classroom、inspiration、dashboard），每个模块自包含 `pages / components / hooks / store`，通过路由懒加载形成天然模块边界（`client/src/routes/index.tsx`）
- AI 网关中间件链：`RequestId → SecurityHeaders → RateLimit → InputValidation → JWTAuth → CORS`，路由/链/提示词分层为 `routers/`（18 个）、`chains/`（22 个）、`prompts/`（15 个）

## 二、核心功能模块总结

### 2.1 费曼学习法（feynman）— 成熟度：★★★★★

**关键文件**：`client/src/features/feynman/pages/FeynmanSessionPage.tsx` · `hooks/useFeynmanSession.tsx` · `store/useFeynmanStore.ts`

- **四步流程状态机**：选择概念 → 讲解 → 标注薄弱 → 简化重述，数据库层面约束 `current_step BETWEEN 1 AND 4`、`status IN ('not_started','in_progress','completed')`
- **薄弱点系统**：`feynman_weak_points` 表记录文本位置与掌握状态，支持批量转化为闪卡
- **AI 评估**：四维评分（准确度、完整度、逻辑、表达），走 `deepseek → glm → fallback` 降级链
- **测试**：`useFeynmanStore.test.ts` 覆盖 store 逻辑

### 2.2 苏格拉底式学习（socratic）— 成熟度：★★★★☆

以三阶段状态机实现（`client/src/features/feynman/hooks/useSocraticFlow.tsx`），业务逻辑与 UI 完全分离：

```tsx
export type Phase = 'brainstorm' | 'dialogue' | 'deepening';
const MAX_ROUNDS = 4;

/** 默认深化角度（AI 降级时使用） */
const DEFAULT_DEEPENING_ANGLES: DeepeningAngle[] = [
  { key: 'analogy', label: '类比联想', question: '这个概念像什么？...' },
  { key: 'counter', label: '反例验证', question: '什么情况下这个概念不成立？...' },
  // ... apply / history / debate 共 5 个角度
];
```

- **流程**：头脑风暴选方向 → 多轮追问（最多 4 轮，上下文窗口保留最近 5 轮）→ 5 角度深化
- **离线降级**：AI 不可用时使用 `DEFAULT_DEEPENING_ANGLES` 预设角度，贯彻本地优先原则
- **服务端配套**：`server/ai-gateway/chains/socratic_chain.py` + `socratic_evaluate_chain.py`，配置了 `socratic_brainstorm / socratic_evaluate / socratic_deepening` 三条独立降级链
- **待补**：该模块尚无专门测试文件

### 2.3 番茄工作法（pomodoro）— 成熟度：★★★★★

核心为 448 行的 Zustand store（`client/src/features/pomodoro/store/usePomodoroStore.ts`），采用 **动作信号模式** 解耦副作用：

```ts
/** 番茄钟动作信号类型（供 usePomodoroEffects 监听） */
export type PomodoroAction =
  | 'start' | 'pause' | 'exit_immersive'
  | 'tick_5min_warning' | 'tick_final' | 'phase_complete' | null;

type Phase = 'work' | 'short_break' | 'long_break';
type Mode = 'class' | 'self_study';   // 课程/自学双模式
```

- **阶段流转**：work → short_break → …→ long_break（每 4 个番茄），支持自动开始
- **音效体系**：开始/暂停/5 分钟警告/最后 10 秒滴答/完成提示 + 白噪音（`public/sounds/` 42 个音效文件）
- **沉浸模式**：`ImmersiveTimer.tsx` 全屏弧形光带进度 + 呼吸缩放
- **AI 推荐时长**：`recommend` 功能走 `glm → deepseek → fallback`，失败降级本地策略
- **测试**：`usePomodoroStore.test.ts` 覆盖充分

### 3.2 关键架构决策：多模型路由与降级链

`server/ai-gateway/config.py` 集中定义了 **功能 → (provider, model)** 路由与 fallback 链：

```python
PROVIDER_FALLBACK_CHAIN: dict[str, list[str]] = {
    "summarize":        ["glm", "qwen", "fallback"],      # GLM（免费）优先
    "feynman_evaluate": ["deepseek", "glm", "fallback"],  # DeepSeek 为主
    "socratic":         ["qwen", "deepseek", "fallback"],
    "vision_extract":   ["qwen", "glm"],                  # Qwen-VL 优先, GLM-4V 备选
    "video_analyze":    ["gemini", "qwen"],               # 原生视频优先，抽帧降级
    ...
}
```

设计亮点：

- 通过 `contextvars` 透传 feature 名，实现 **按功能独立超时预算** 而无需改动所有签名
- 支持 **用户自带 API Key 优先** 于全局 Key
- `fallback` provider 提供兜底响应（如苏格拉底用预设问题），加上 Ollama 本地推理，形成"云端多模型 → 本地模型 → 静态兜底"三级降级

## 六、数据管理和存储方案

### 6.1 双库分工

| 存储 | 进程 | 用途 |
|------|------|------|
| Dexie.js (IndexedDB) | 渲染进程 | 业务数据快速读写、Web 降级形态（`client/src/lib/storage/database.ts`） |
| better-sqlite3 | Electron 主进程 | 20+ 张结构化表：业务实体、操作日志、CRDT 元数据、搜索索引、离线队列（`client/electron/db/schema.ts`） |

### 6.2 渐进式 Schema 迁移（当前 v4）

```ts
export const SCHEMA_VERSION = 4;
export function initializeSchema(db: Database.Database): void {
  db.exec(SCHEMA_DDL);                       // 幂等建表
  const v = db.pragma('user_version', { simple: true }) as number;
  if (v < 2) { /* FSRS-5 扩展: stability/difficulty 列 */ }
  if (v < 3) { db.exec(SCHEMA_V3_DDL); }     // CRDT 元数据表
  if (v < 4) { /* search_index 增加 entity_id/entity_type */ }
  db.pragma(`user_version = ${SCHEMA_VERSION}`);
}
```

### 6.3 CRDT 同步链路（Automerge v3）

- **上行**：`getChangesSince()` 取增量 → `concatChanges()` 拼接 → Base64 → `POST /api/v1/sync/crdt/changes`
- **下行**：Base64 解码 → `loadIncremental()` 直接应用（原生支持多 chunk）
- **元数据**：`crdt_docs`（每表 snapshot + last_heads 版本向量）、`crdt_changes`（变更序列）
- **可靠性**：`offline_queue`（含 retry_count/next_retry_at 指数重试）+ `sync_conflicts`（四态冲突处理：pending/resolved-local/resolved-remote/resolved-manual）
- **服务端**：Go 服务提供 `push/pull/resolve/status` REST + WebSocket 实时通道（JWT 从 `?token=` 读取以绕过 WS 头限制），Redis 故障时优雅降级

整体形成"**本地先落盘 → 操作日志 → 离线队列 → CRDT 增量同步 → 冲突解决**"的完整 Local-First 链路。
