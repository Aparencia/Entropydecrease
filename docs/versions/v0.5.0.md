## 四、核心技术架构决策

### 决策 1：sync-service 用户数据隔离

**现状**：`sync.go` 的 pull/push 端点未基于 user_id 过滤数据，任何有效 JWT 可拉取全库数据。

**方案**：SyncOperation 模型新增 `user_id` 字段 + `(user_id, entity_type, entity_id)` 联合索引；pull/push handler 从 `request.state.user_id` 注入过滤条件；数据库迁移脚本为存量数据补填 user_id。

**关键文件**：`server/sync-service/models/sync_operation.go`、`server/sync-service/handlers/sync.go`

### 决策 2：JWT APP_ENV 门控降级策略

**现状**：`auth.py` L125-147 当 `SUPABASE_JWT_SECRET` 为空时无条件启用降级模式（不验签），生产环境存在安全风险。

**方案**：引入 `APP_ENV` 环境变量（development/production）。`APP_ENV=production` 时，若 `SUPABASE_JWT_SECRET` 为空则启动失败（快速退出）；`APP_ENV=development` 时维持现有降级行为并打印 WARNING。

**关键文件**：`server/ai-gateway/config.py`、`server/ai-gateway/middleware/auth.py`

### 决策 3：AI 端点输入限制策略

**现状**：summarize/generate-cards/evaluate/recommend 路由无请求体大小限制，可被超大 payload 攻击。

**方案**：新增 `InputValidationMiddleware`，对所有 `/api/v1/ai/*` 路由限制 `Content-Length ≤ 1MB`、文本字段 `≤ 50000 字符`；超限返回 422 + 明确错误信息。

**关键文件**：**新建** `server/ai-gateway/middleware/input_validation.py`

### 决策 4：Dexie Schema v6 渐进迁移

**现状**：Schema v5 已交付（`database.ts` L148-150），新增 `windowCaptures` 表。

**方案**：v6 采用**仅添加索引，不 clear+reinsert**策略——`flashcards` 表新增 `sourceNoteId` 索引、`notes` 表新增 `videoNoteType` 索引。已有数据无需迁移，新字段默认为 undefined。Dexie version(6).stores() 仅声明新索引。

**关键文件**：`client/src/lib/storage/database.ts`、`client/src/types/models.ts`

### 决策 5：生产 Docker 编排

**方案**：新建 `docker-compose.prod.yml`，包含 postgres + redis + ai-gateway（gunicorn）+ sync-service + nginx（反代+SSL）五个服务。ai-gateway 使用 gunicorn + uvicorn workers 替代 `uvicorn main:app --reload`。Nginx 负责 SSL 终端 + 静态资源 + API 反代。

**关键文件**：**新建** `server/docker-compose.prod.yml`、`server/nginx/nginx.conf`、`server/.dockerignore`

### 决策 6：结构化 JSON 日志

**方案**：ai-gateway 使用 `python-json-logger` 替换默认 logging formatter，输出 `{"timestamp","level","module","message","user_id"}` 结构化 JSON。sync-service 使用 `zap` 替换标准 `log`。`LOG_LEVEL` 环境变量控制日志级别（默认 INFO）。

**关键文件**：`server/ai-gateway/main.py`、`server/ai-gateway/config.py`、`server/sync-service/main.go`

- S5：`git diff server/.env` 确认 GLM_API_KEY 已替换为占位符；`.env.example` 中所有 key 值为 `sk-your-*` 或空
- S6：`APP_ENV=production` 时 `GET /docs` 返回 401；`APP_ENV=development` 时 `GET /docs` 返回 200

**里程碑**：M-PA — 安全 P0 全部合并，安全审计回归通过。

## 十、被拒绝的替代方案

| 替代方案 | 拒绝理由 |
|---------|---------|
| Schema v6 采用 clear+reinsert 全量重建 | v5 已用此方式，v6 仅添加索引无需重建；clear+reinsert 对大量数据有丢失风险 |
| 灵感空间使用独立后端微服务 | 当前用户量不需要独立服务；复用 ai-gateway 新增路由即可 |
| 命令面板使用 cmdk 第三方库 | ~8KB gzipped 额外开销；自实现可控性更强且支持命令注册表 |
| 效率分析使用 ECharts 替代 recharts | recharts 已在 v0.3.0 引入；ECharts 全量 ~400KB 过重 |
| 生产环境使用 Traefik 替代 Nginx | 团队 Nginx 经验更丰富；Traefik 动态路由对本项目过度设计 |
| 离线队列使用 Service Worker 后台同步 | Background Sync API 兼容性不足（Firefox 不支持）；IndexedDB 方案更通用 |

## 十四、代码审查检查清单

每个 v0.5.0 PR 合并前需通过以下审查项：

### 通用审查项

- [ ] **编译通过**：`npm run build` / `go build` / `python -m py_compile` 无错误
- [ ] **测试通过**：新增/修改代码附带对应测试，`vitest run` / `go test` / `pytest` 全部 pass
- [ ] **无新增 TODO**：除非 TODO 关联了本版本后续步骤编号（如 `// TODO [v0.5.0-B2.2]`）
- [ ] **无 console.log**：生产代码中不允许 `console.log`/`print` 调试输出（logger 除外）
- [ ] **类型安全**：无新增 `any` 类型（除非有注释说明理由）；TypeScript strict 模式无新增 error

### 安全审查项（Pre-Alpha.0 / Alpha.2 安全步骤强制）

- [ ] **用户隔离**：所有数据库查询包含 `user_id` 过滤条件
- [ ] **输入校验**：新增 API 端点有 Content-Length 和字段长度限制
- [ ] **频率限制**：新增 AI 端点已注册到 `PATH_TO_FEATURE`
- [ ] **密钥安全**：无硬编码密钥；`.env` 变更不提交真实值
- [ ] **日志安全**：日志中不包含 token/key/password 等敏感信息

### 数据层审查项（Alpha.1 / Alpha.2 数据步骤强制）

- [ ] **ExportData 完整**：新增 Dexie 表同步更新 `ExportData` 接口和 `exportAllData()`/`importData()`
- [ ] **Schema 向后兼容**：新索引不要求 clear+reinsert；`version(N)` upgrade 函数处理存量数据
- [ ] **类型同步**：`models.ts` 接口变更与 `database.ts` Schema 一致

### 上云审查项（部署步骤强制）

- [ ] **Docker 构建**：`docker build` 成功；镜像大小合理（< 500MB）
- [ ] **健康检查**：新增服务配置 `healthcheck` 指令
- [ ] **环境变量**：新增配置项在 `.env.example` 中有说明和默认值
