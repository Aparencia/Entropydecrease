## 一、阶段目标

1. **视频类型档案（E9）**：五档案（结构化教学/步骤实操/口播知识/访谈播客/会议汇报）完整定义 + 混合检测（自动候选 + 用户确认 + 记忆偏好）+ 档案驱动管线（采样预算/信号权重/后处理/产物模板按档案生效）——轮 1/2 落地
2. **版面分析先行**：规则版版面分析（区域分类 text/table/formula/code/image/unknown）+ 事件帧触发 + 区域价值采样；**layout 模型 spike 并行**（ORT 兼容性，通过则换引擎，编排零改动）——轮 4 + 追加讨论落地
3. **专项 OCR 完整构建**：表格（SLANet 模型版，spike 通过则模型版、否则规则版线条重建兜底）+ 公式（UniMERNet 模型版，同理规则版上下标重建兜底）——用户指定 0.5.0 完整构建
4. **图片配套**：三层图结构（关键图/参考图集/缩略图走廊）+ 多信号筛选投票 + 用户截图标记 + 图集 UI——轮 3 落地
5. **产物体系**：Artifact 块模型（`ArtifactBlock{kind, refs, payload, order}`）+ 五档案产物模板 + 会话产物视图 + 渲染器升级（LaTeX/表格/图集）+ 一键落笔记——轮 5 落地
6. **补缝式 AI 前置**（轮 6，V1.0 实装）：本地失败判定器 + `ai_candidate` 块 + 返回协议 schema + mock 适配器 + 配额/缓存/审计骨架——协议先行，云端接入留 V1.0

> 本阶段**不做**：补缝式 AI 云端实装（Qwen-VL 接入/计费/授权，V1.0，见七）；PP-Structure 模型组完整版（layout 模型版/SLANet/UniMERNet 统一模型管理，V1.0）；流程图语义重建（AI 补缝类型）；手写公式识别（专用模型）；乐谱（超出范围）；闪卡（REQ-019/020，继续顺延，用户决策）；转写时间轴回放与可编辑（REQ-023，V1.0）；零拷贝（已裁决）；声学模型微调（已否决）。

### M3 规则版版面分析（REQ-047，轮 4 + 追加讨论落地）

> **实施状态（2026-08）**：✅ 已实施——`layout_analyzer.rs`（全局表格检测：孤立横线+竖线交叉 → Table；行投影合并带 → 列区间 → 分类：公式中线长条 > 代码行首对齐+行宽变化 > 文本 > 图像 > unknown）+ `frame_features.rs`（BGRA 帧 → 32×18 灰度网格，Rec.601）+ `layout_cache.rs`（版面指纹 = 行列投影位图 + LRU + TTL 60s，事件帧触发复用）。已接入实时链路全帧分支（run_screen_worker：同版面零重分析，新版面日志可观测区域构成）。`region_sampling_weight` 采样权重表就绪（table 1.0/code 0.9/formula 0.7/text 0.5/image 跳过/unknown 0.2），M4 region_ocr 调度消费。**layout 模型 spike 结论（2026-08）**：编排层已按"区域类型"抽象（LayoutRegion 为唯一接口），规则版→模型版（PP-StructureV3）只换 analyze_layout 实现编排零改动；模型 ORT 兼容性与分发评估留 V1.0（REQ-057 统一管理）。

> 设计原则：**规则版先行 + layout 模型 spike 并行**——编排层按"区域类型"抽象，规则版→模型版只换 `LayoutAnalyzer` 实现。

1. **`layout_analyzer.rs`**（新，纯逻辑为主）：
   - 输入：播放区域内帧（REQ-037 坐标系）
   - 区域分类管线：线条检测（Hough/形态学，区分表格线 vs PPT 装饰线）→ 连通域分析 → 文本密度聚类 → 区域类型判定 `text/table/formula/code/image/unknown`
   - 输出：`Vec<LayoutRegion { kind, bbox, confidence, is_structural }>`
2. **事件帧触发**：帧 diff 变化事件（capture/frame_diff 已有）触发版面分析；同一版面内复用分区，只重识别变化区域；结果带时间戳缓存（版面缓存 = OCR 缓存 M4 的扩展）
3. **区域价值采样**：REQ-039 预算制升级——区域类型 → 采样权重表（table/code 高权重高分辨率；装饰/image 跳过；subtitle 区独立高频 ROI 不进版面分析）
4. **布局模型 spike（并行）**：PP-StructureV3 layout.onnx 在 ort 2.0.0-rc.13 的算子兼容性 + 精度对比（合成帧 + 真实站点样本）；结论归档，通过则 M3 收尾换引擎（编排零改动）
5. **测试**：合成帧（PPT 页/表格页/代码页/白板）分类 golden 测试（G3 扩展）；回退链（分析失败 → 整帧直跑现有管线）

### M4 分区域 OCR 编排（REQ-048）

> **实施状态（2026-08）**：✅ 已实施——`region_ocr.rs`（坐标还原 `map_to_frame` 纯函数含缩放/负偏移边界单测 + 区域裁剪 `crop_region_bgra`（内存 crop 含 12px 边距）+ 最近邻放大 `upscale_bgra`（表格 2x/公式代码 1.5x）+ 区域调度 `schedule_regions`（价值权重排序 + 每帧 ≤4 区封顶））；编排接入 process_frame 全帧分支：版面区域存在 → 分区域裁剪识别 → 坐标还原 + region_kind 标注 → 合并；区域失败标记 unknown 不阻断（诚实降级）；编排失败/无区域回退整帧直跑（现状行为）。DB 迁移：session_ocr_blocks 加 region_kind 列（ensure_column 幂等，兼容旧数据）；OcrBlock/SessionOcrBlock/NewSessionOcrBlock 增 region_kind 字段（None=整帧直跑）。

1. **`region_ocr.rs`**（新，编排器）：区域调度（每帧最多 N 区封顶，防多区域调用失控）；低置信区域局部放大重试一次；再失败 → 低置信标记
2. **坐标还原**：纯函数 `map_to_frame(region_coord, region_bbox, scale) -> frame_coord` + 单测（含边界/缩放/负偏移）
3. **结果扩展**：`OcrBlock` 增加 `region_kind` 字段（DB 迁移：ocr_blocks 表加列，兼容旧数据）
4. **回退链**：layout 失败 → 整帧直跑（现状行为）；区域识别失败 → 该区域标记 unknown → 图片归档候选
