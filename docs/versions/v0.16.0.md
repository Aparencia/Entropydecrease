## 一句话

应用内新增 💬「AI 对话」页：**纯文本多轮聊天**，流式输出、可停止、可重发/编辑重发、会话侧栏管理、每会话模型选择——交互范式照抄 DSH Web GUI，模型供给与密钥/审计/成本全部复用现有 BYOK AI 平台；**不做**工具调用/子代理/工作流/上下文注入。

## 背景

- 现状：AI 平台（v0.11.6）已具备多 Provider（SiliconFlow/DeepSeek/OpenRouter/Ollama 预设）、DPAPI per-provider 密钥、六类错误归一、配额/缓存/审计、成本落库——但只有"任务型"能力（精修/补充/过滤），没有**对话型**能力；REQ-024「AI 多轮问答」长期 P2 挂起
- 用户诉求：像 DeepSeek Web/豆包电脑端那样"打开就能聊"的可对话 AI 界面；采集增强（AI 实时理解/智能切片）**后续再议**（本版登记不进范围）
- 选材：DSH 全套为 Agent Harness（宿主 Node ≥22 + Cordis 插件 + WebSocket + 工具/子代理/工作流/目标/计划/技能），**核心价值在 agent 循环不在聊天**；许可 MIT 可抄

## 设计要点

### 架构（复用而非新建平台）

```
前端 ChatPage/侧栏/列表/输入框
   │ invoke（Tauri 2 Channel 流式）
   ▼
commands_ai_chat.rs ── content_gate（enabled+authorized，默认关）
   │                ── resolve 默认 Provider + per-provider 密钥（现链）
   ▼
ai_chat.rs（新增，≤300 行）
   ├── 纯函数：history→OpenAI messages 组装 · SSE 行解析（data: / [DONE] / 畸形行）
   ├── 流式：ureq into_reader 逐 chunk → Channel::send(Chunk{delta})
   └── CancellationFlag（Arc<AtomicBool>）—— chat_cancel 短路
   ▼
db_ai_chat.rs（新增）── ai_chat_sessions / ai_chat_messages 两表（db_migrations 幂等）
   ▼
审计/用量复用 db_ai_usage / ai_cost / ai_guardrails
```

- 数据流：`chat_send(session_id, content, channel)` → gate → 存 user 消息 → 流式调用 → 逐 delta 推送 → 结束存 assistant 消息（content+usage）→ 推送 `Done{usage, cost}`；`chat_cancel(session_id)` 置取消标志 → 流循环退出 → 消息标 `status=aborted`
- 错误复用 `AiClientError` 六类（Auth/Network/Balance/Quota/Server/Parse）→ 前端映射 + 重试按钮；失败不静默（v0.8 U5 纪律）

### 任务对话视图（REQ-230：精修/补充轨迹）

- **存储**：`ai_tasks` 加列 `trajectory_json TEXT`（ensure_column 幂等迁移）——`[{turn, system, user, response}]`（每片 LLM 调用一条；system=提示词模板构建结果，user=请求 JSON，response=模型原始回答）。精修链路（`ai_refine_task.rs` 各片调用处）收集轨迹，终态时随 `finish_ai_task` 写入；旧任务 NULL → 对话视图显示"升级前任务无轨迹存档"（诚实降级）
- **展示**：AI 对话页侧栏「🤖 AI 任务」段（refine/enrich 列表，复用 `ai_task_history`）；点开 = 只读对话——任务卡（类型/标题/模型/片数/成本/状态/时间）+ 逐 turn 对话（用户=提示词，AI=回答，正文可展开滚动） + **可跳转引用** chips：来源会话 → 会话页（`onOpenSessions` 现链）、来源笔记 → 笔记页（`onOpenNote` 现链）+ 成功结果展开预览（result_json → refined/enriched markdown）；失败任务带"重试"（精修=复用 `ai_refine_start`；补充=笔记页手动）
- **工作台跳转说明（审查核对 2026-08-30）**：精修工作台（RefineWorkbench）深链需跨页路由传递，本版未做——结果预览已在任务对话视图内展开（等价可见），工作台深链登记为后续增强项
- enrich 轨迹同步接入（`ai_note_enrich.rs` 同理收集）；text_filter 轨迹暂不展示（YAGNI，审计可见化已覆盖）

### 交互范式（照抄 DSH 手感）

- 消息：markdown 渲染（代码块/表格/公式——依赖已在）、时间戳、模型标签、复制按钮、失败态重试、编辑后重发
- 流式：打字效果 + 停止按钮（同一时刻仅一条活跃流，新消息需等待/停止）
- 会话：侧栏列表（新建/重命名/删除/搜索），历史落库重启可回看
- 空态：未授权/无密钥 → 引导卡（"开启 AI 对话" → 设置页 AiProviderSettings 一键测试连接）；首次发送前一次性提示"对话内容将发送至 {Provider} 云端"

### 红线合规（AGENTS.md §4）

1. **授权闸门**：与现有 AI 能力同规——enabled + authorized 双条件，**默认关**；空态引导不静默
2. **上传透明**：聊天文本上行，首次发送明确提示（授权语义，延续 ADR-010）
3. **本地兜底**：聊天是增强层不阻塞主链路——失败/离线 → 错误态 + 重试；Ollama Provider 预设天然提供本地端点选项（BYOK 用户自选）
4. **密钥/审计/成本**：密钥仍 DPAPI per-provider；每消息 usage 落库 + 审计可查

### 测试

- Rust：SSE 解析器（多 chunk / chunk 跨行 / `[DONE]` / 畸形行 / 空 delta）、history→payload 组装（含 role 白名单/空 history）、gate 路径、db CRUD + 级联删除、取消标志短路——纯函数 AAA 先写测试
- 前端 Vitest：流式追加/停止态、composer 快捷键（Ctrl+Enter 发送/类 DSH）、侧栏 CRUD 交互（mock invoke）
- 回归：cargo test / clippy / vitest / tsc（现有基线全绿）

## 验收标准

1. 设置页启用 AI 并授权 → AI 对话页可发起多轮聊天，流式输出不卡 UI，可随时停止
2. 停止/失败后消息状态正确（aborted/failed 可见，failed 可重试）；重发/编辑重发正确替换旧消息
3. 侧栏可新建/重命名/删除/搜索会话；重启应用历史消息可回看
4. 每会话可选择模型（预设下拉）；消息显示所用模型与 token/成本
5. **AI 任务段可见精修/补充任务对话：提示词与回答全文可展开查看；引用 chips 可跳转来源会话/笔记；成功结果可展开预览；失败任务可一键重试（精修）**
6. 未授权/无密钥时显示空态引导而非死界面；首次发送有云端提示
7. 全量回归通过（cargo test / clippy / vitest / tsc）
