## 四、核心技术架构决策

### 决策 1：Framer Motion 引入策略

**现状**：项目当前未引入 Framer Motion，动效依赖纯 CSS + 少量 React Transition。

**方案**：
- **按路由懒加载**：Framer Motion 组件使用 `React.lazy()` 包裹，避免首屏 bundle 膨胀
- **`prefers-reduced-motion` 降级**：媒体查询检测到用户偏好时，自动降级为纯 CSS 过渡（无弹簧物理动画）
- **`AnimatePresence` 限制**：仅用于页面级路由过渡，微交互（按钮涟漪、Toast 滑入）优先 CSS `@keyframes`
- **tree-shaking**：仅从 `framer-motion` 导入 `motion`、`AnimatePresence`、`useReducedMotion` 等必要 API，不全量导入

**关键文件**：`client/src/components/layout/`、`client/src/pages/`、新建 `client/src/hooks/useReducedMotion.ts`

### 决策 2：品牌色系替换

**现状**：当前品牌色为蓝色 `#3B82F6`（Tailwind blue-500），设计文档明确要求双品牌色系。

**方案**：
- **主色（活力橙）**：`--color-primary: #FF7F50`、`--color-primary-hover: #FF6347`
- **辅色（智慧青）**：`--color-secondary: #4FB0FF`、`--color-secondary-light: #00D2D3`
- **中性色**：`--color-text-primary: #2C3E50`、`--color-bg-base: #F7F9FC`
- 在 `tokens.css` 中定义完整设计令牌，全局替换 Tailwind 蓝色引用
- 渐变统一方向：`45deg` 从 `#FF7F50` → `#4FB0FF`

**关键文件**：`client/src/styles/tokens.css`、`client/tailwind.config.js`、`client/src/components/ui/`、`client/src/components/layout/`

### 决策 3：数据模式选择增强

**现状**：ModeManager、SyncContext、SyncSettings UI 已实现基础框架。

**方案**：基于现有 `ModeManager` 增强，不重新实现。新增功能灰度展示、AI 按钮"联网可用"态、模式指示器常驻化。

**关键文件**：`client/src/lib/mode/ModeManager.ts`、`client/src/pages/settings/SyncSettings.tsx`

### 决策 4：文件路径设置

**现状**：零路径配置代码，数据目录硬编码。

**方案**：IPC 通信暴露路径选择对话框 + 设置页 UI + 数据迁移逻辑。IndexedDB 数据无法直接移动，需导出→重定向→导入流程。

**关键文件**：`client/electron/main.ts`、`client/electron/preload.ts`、新建 `client/src/pages/settings/DataSettings.tsx`

### 决策 5：自动更新系统

**现状**：electron-updater 未安装、无 publish 配置、无更新 UI。

**方案**：安装 `electron-updater` + 配置 `electron-builder.yml` publish 字段（支持 GitHub/Generic/S3 三种发布源）+ 新建 `client/electron/updater.ts` 模块 + IPC 通知 + 前端更新通知 UI 组件。

**关键文件**：`client/electron-builder.yml`、新建 `client/electron/updater.ts`、新建更新通知 UI 组件

| A1.2 | BUG-002：TipTap 编辑器文本输入验证 | `client/src/features/notes/` 相关编辑器组件 | 中 |

| A1.4 | v0.5.0 技术债务清理（TD-01~TD-03） | `client/package.json`、多处前端文件 | 低 |
| A1.5 | 项目基础设施准备 | `client/package.json`（版本号更新）、依赖安装与审计 | 低 |

**需求详细说明**：

**A1.1 — IPC handler 防御性 removeHandler**
- **当前状态**：`main.ts` 中 `ipcMain.handle()` 在窗口重建时可能重复注册，导致 "Attempted to register a second handler" 崩溃
- **v0.6.0 范围**：实现 `safeHandle(channel, handler)` 工具函数，调用前自动 `ipcMain.removeHandler(channel)`，确保幂等注册；所有现有 `ipcMain.handle` 调用迁移至 `safeHandle`

**A1.2 — TipTap 编辑器文本输入验证**
- **当前状态**：部分用户反馈 TipTap 编辑器出现文本输入异常（光标跳转、内容丢失）
- **v0.6.0 范围**：回归验证文本输入稳定性；检查 TipTap 版本兼容性；添加输入异常边界保护

**A1.3 — 崩溃恢复与文件日志**
- **当前状态**：主进程无全局异常处理，崩溃后无日志可查
- **v0.6.0 范围**：添加 `process.on('uncaughtException')` 和 `process.on('unhandledRejection')` handler；实现文件日志系统（写入 `%APPDATA%/KeBan/logs/`）；崩溃前自动 dump 状态信息

**A1.4 — 技术债务清理**
- TD-01：版本号从 `package.json` 动态读取，UI 通过 IPC 获取版本号，消除硬编码
- TD-02：全局搜索并清理 `console.log/warn/error` 残留，替换为统一 logger
- TD-03：执行 `npm audit`、升级过时依赖

**A1.5 — 项目基础设施准备**
- 更新 `package.json` version 字段至 `0.6.0`
- 依赖安装完整性验证（`npm ci` 无报错）
- 确认 TypeScript 编译无 error

**验收标准**：
- A1.1：连续 3 次快速创建+销毁 BrowserWindow，`ipcMain.handle` 不抛出 "second handler" 错误；`safeHandle` 单元测试覆盖注册/去注册/重注册三种场景
- A1.2：在 TipTap 编辑器中连续输入 500 字符无光标跳转异常；快速粘贴大段文本（>2000 字符）不丢失内容；编辑器在 3 秒内连续切换笔记不出现内容串扰
- A1.3：手动触发 `throw new Error('test')` 后进程不直接退出，日志写入 `logs/crash-YYYYMMDD-HHmmss.log`；日志文件包含错误堆栈 + 时间戳 + 进程状态信息
- A1.4：`grep -r "console.log" client/src/` 结果 ≤ 5 处（均有 `// eslint-disable` 注释说明理由）；UI 版本号与 `package.json` version 字段一致
- A1.5：`npm ci` 无报错；`npx tsc --noEmit` 无 error；`package.json` version = `"0.6.0"`

**里程碑**：M-A1 — 基线验证与基建完成，三大 BUG 修复，债务清理完毕。

## 九、被拒绝的替代方案

| 替代方案 | 拒绝理由 |
|---------|---------|
| 使用 `electron-reloader` 替代 `electron-updater` | electron-reloader 仅支持开发模式热重载，不支持生产环境增量更新 |
| Framer Motion 全量导入 | 全量包 ~120KB gzipped，tree-shaking 后可控至 ≤ 30KB；全量导入严重影响首屏 |
| 音效使用 Howler.js 库 | Howler.js ~7KB gzipped 额外开销；Web Audio API 原生播放 .wav 足够且零依赖 |
| 品牌色使用 Tailwind 默认橙（orange-400 #FB923C） | Tailwind 橙色与设计文档定义的 #FF7F50 不一致；应使用设计令牌精确匹配 |
| 路径设置使用 File System Access API | 仅 Chromium 支持，且持久化权限管理复杂；IPC + dialog 方案更稳定通用 |
| 隐私合规使用第三方 SDK（如 OneTrust） | 桌面应用不需要 Web 端 Cookie 合规 SDK；IndexedDB 存储同意状态足够 |
| 自动更新使用 Squirrel.Windows | electron-builder 已内置 electron-updater 支持；Squirrel 额外增加配置复杂度 |
