## 三、核心技术架构决策

### 决策 1：FEAT-047 灵感空间 AI 整理方案

**现状**：灵感空间已实现低摩擦录入 + Inbox 暂存 + 筛选功能。后端 `sort_inspiration_chain.py` 已有基础版本（179 行），但前端尚未连通分拣链路，AI 分拣结果无法展示给用户，更无转化能力。数据存储在 Dexie `inspirations` 表中（v0.7.0 迁移完成）。

**方案**：
- **增强 `sort_inspiration_chain.py`**：扩展 prompt 以输出结构化 JSON（含分类类型、原因、置信度），支持 5 类分拣目标（待整理/学习笔记/闪卡素材/费曼概念/番茄目标）
- **前端 InspirationPage.tsx 新增"AI 整理"按钮**：调用后端分拣接口，展示归类建议卡片
- **inspirationStore.ts 扩展分拣状态字段**：`sortStatus`（pending/sorted/confirmed/transformed）、`sortResult`（分拣结果 JSON）
- **分拣结果可人工修改覆盖**：用户可手动更改 AI 建议的分类

**关键文件**：修改 `server/ai-gateway/chains/sort_inspiration_chain.py`、`client/src/features/inspiration/pages/InspirationPage.tsx`、`client/src/features/inspiration/store/inspirationStore.ts`

### 决策 2：FEAT-030 灵感空间静默自动分拣模式

**现状**：当前灵感录入后仅存储原始内容，无任何自动处理。用户需手动点击"AI 整理"按钮才能触发分拣。

**方案**：
- 提交灵感后后台自动调用分拣接口（不阻塞 UI）
- 分拣完成后通过 Toast 提醒用户（显示分类结果摘要，如"已归类为：闪卡"）
- 分拣状态持久化到 inspirationStore 的 `sortStatus` / `sortResult` 字段
- 灵感卡片上保留手动分拣入口，可覆盖 AI 结果
- 5 类分拣目标：待整理、学习笔记、闪卡素材、费曼概念、番茄目标
- 后端 `inspiration.py` 路由增强：新增 `POST /api/v1/inspiration/auto-sort` 异步端点

**关键文件**：修改 `client/src/features/inspiration/store/inspirationStore.ts`、`server/ai-gateway/routers/inspiration.py`

### 决策 3：FEAT-033/034 灵感转化与草稿生成方案

**现状**：分拣后的灵感无法直接转化为对应模块内容，用户需手动跳转到目标模块重新创建。

**方案**：
- **就地转化面板**（InspirationTransformPanel.tsx）：在灵感空间内弹出编辑面板，支持将灵感转化为 5 类目标内容（待整理/学习笔记/闪卡素材/费曼概念/番茄目标）
- **默认"学习笔记"模板**：转化面板默认使用学习笔记模板，可在面板中切换为闪卡素材/费曼概念/番茄目标
- **AI 草稿生成**（InspirationDraftPreview.tsx）：按目标类型调用不同 LangChain chain 生成草稿
  - 待整理/学习笔记类型 → `NoteDraftChain`：生成结构化笔记草稿（标题+要点+总结）
  - 闪卡素材类型 → `CardDraftChain`：生成 Q&A 对（复用现有 `card_gen_chain.py` 逻辑）
  - 费曼概念类型 → `FeynmanDraftChain`：生成费曼讲解框架（概念定义+类比+验证问题，复用 `feynman_question_chain.py` 逻辑）
- **草稿可编辑后保存**：草稿生成后在预览面板中可编辑，确认后写入对应模块的 Dexie 表
- **事务性写入**：转化操作使用 Dexie 事务，失败时回滚

**关键文件**：新建 `client/src/features/inspiration/components/InspirationTransformPanel.tsx`、`client/src/features/inspiration/components/InspirationDraftPreview.tsx`、后端新增 `server/ai-gateway/routers/inspiration_transform.py`、`server/ai-gateway/chains/inspiration_draft_chain.py`

## 七、风险矩阵

| # | 变更 | 风险 | 影响 | 缓解措施 |
|---|------|:---:|------|---------|
| R1 | AI 分拣准确率不足 | 中 | 错误归类建议误导用户，降低信任度 | 手动覆盖机制（用户可修改分类）；持续优化 prompt；低置信度时标注"仅供参考" |
| R2 | 灵感转化链路数据一致性 | 中 | 转化过程中写入失败导致灵感状态与实际数据不一致 | 事务性写入（Dexie transaction）；失败回滚 + Toast 提示；灵感状态最后更新 |
| R3 | 草稿生成 Chain 输出格式不稳定 | 中 | AI 输出格式不一致导致草稿预览解析失败 | 后端强制 JSON Schema 校验；解析失败时降级为纯文本展示 |
| R4 | 自动分拣并发请求导致后端压力 | 低 | 大量灵感同时提交时后端响应变慢 | 前端请求队列（最多 3 个并发）；后端超时 10s + 失败降级为"待整理" |

## 八、被拒绝的替代方案

| 替代方案 | 拒绝理由 |
|---------|---------|
| 灵感分拣使用本地 LLM | 桌面端本地模型能力不足，5 分类准确率低；后端 Chain 方案可复用云端模型能力，准确率更高 |
| 灵感转化使用前端纯本地处理（不经过后端） | 草稿生成需要 LangChain 能力，纯前端无法实现；后端统一处理可复用现有 Chain 基础设施 |
| 自动分拣使用 WebSocket 推送结果 | 当前场景分拣延迟可接受（1-3s），轮询/Toast 方案足够；WebSocket 增加架构复杂度但收益不大 |
| 转化面板使用全屏 Modal | 全屏 Modal 阻断上下文感知，用户无法参考原始灵感内容；侧边面板保留灵感列表可见性 |
| 分拣分类体系使用 4 类（不拆分笔记类型） | 用户实际使用中自由笔记与康奈尔笔记场景差异大；5 类（待整理/学习笔记/闪卡素材/费曼概念/番茄目标）覆盖更全面且与目标模块一一对应 |

## 十三、代码审查检查清单

每个 v1.1.0 PR 合并前需通过以下审查项：

### 通用审查项

- [ ] **编译通过**：`npm run build` 无错误
- [ ] **测试通过**：新增/修改代码附带对应测试，`vitest run` 全部 pass
- [ ] **无新增 TODO**：除非 TODO 关联了本版本后续步骤编号（如 `// TODO [v1.1.0-B1.2]`）
- [ ] **无 console.log**：生产代码中不允许 `console.log` 调试输出（logger 除外）
- [ ] **类型安全**：无新增 `any` 类型（除非有注释说明理由）；TypeScript strict 模式无新增 error

### 灵感空间审查项（Alpha.1 / Beta.1 步骤强制）

- [ ] **AI 错误处理**：AI 请求失败时 UI 有明确提示（Toast / 错误卡片）；不阻塞主流程
- [ ] **分拣结果校验**：后端返回 JSON 经 Schema 校验；解析失败时降级为"待整理"分类
- [ ] **事务性写入**：灵感转化操作使用 Dexie 事务；失败时回滚且灵感状态不变更
- [ ] **手动覆盖可用**：AI 分拣/草稿结果始终提供手动修改入口；AI 结果仅作为建议
- [ ] **并发控制**：自动分拣请求有队列限制（最多 3 并发）；超时 10s 降级处理
- [ ] **状态一致性**：`sortStatus` 状态流转严格单向（pending → sorting → sorted → confirmed → transformed）
