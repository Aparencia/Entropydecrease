## 一句话

## 自验证路线（本系列主纲，ADR-030 决策 1/2）

- **参考信道**：外挂/内嵌字幕轨（~100%）> 字幕 OCR 多帧投票（~99%）> 会话内字幕段；无参考素材不进 CER（只做稳定性/画像/回归）。
- **harness** `bin/asr_eval`：批量样本 → 转写（流式/离线、参数矩阵、预处理开关）→ dtw_align 对齐 → cer.rs CER → 同音错对画像 → A/B 对比表 → 回归退出码（CI）。
- fixtures 固化首批有参考样本；**结论只作相对对比与回归**，不宣称绝对指标。

## 行动底座与两区要点

**底座**：md 任务行为唯一真相（v1 不引入新符号）→ `task_index` 增量索引（保存钩子维护，聚合走 SQLite 不走全库扫描）→ 回写原子层（行解析→状态迁移纯函数→写回源行，全入口收敛）→ `completion_history`。

**① 待办功能区（Act）**：产物遗留行归一化（`- ☑️ 待办` → 可裁决条目，可「提炼为任务行」）→ 聚合视图（计划日/搁置）→ 周回顾裁决队列（含"转闪卡/放弃留因"——**不留死尸的机制是裁决不是自动清理**）→ 迁出适配器（保底三件套：复制 todo.txt 行/导出 `.todo.txt`/邮件说明；scheme 通道 Todoist `todoist://quickadd` + 滴答 x-callback 先探测注册；REST+token 二期进 keyring 复用 ADR-016 DPAPI；Google Tasks/MS To Do/Vikunja 自填 endpoint 后置）。

**② SOP 执行功能区（H）**：三源创建模板（课堂素材半自动提炼=复用截图/OCR/转写时间线，Scribe 映射但不做录屏识别）→ 双模式执行 + run 快照档案（`runs`/`run_steps`：轨迹/失败点/耗时，正文保持可复跑）→ 版本化演进 → 个人操作档案。

**③ 学习联动接口（预留，本体归闪卡/复习轮次）**：练习类 Act 节奏化（次数/时长/难度/熟练度=闪卡之外第二条复利曲线）；「该练了」按曲线浮出（不建待办，trane 范式）；失败点→练习卡——本支线只定义数据接口与完成史沉淀。

## 数据模型草稿（v1 · 六张新表 + 复用链，2026-09-05）

**① `task_index`**——正文任务行增量索引（真相仍在 md 行；只作聚合查询缓存，无回写职责）
`id / note_id FK / line_no / task_text(快照去前缀) / status todo|done / disposition generic|learning|practice|sop|export / plan_date NULL / created_at / updated_at · UNIQUE(note_id,line_no)`
维护：note 保存钩子（versioned_save 路径）重扫重建索引——行号漂移由"重扫式刷新"吸收；勾选仍走既有字符级回写（NoteMarkdown 先例）。

**② `practice_items`**——练习条目（内建①类）
`id / note_id NULL / kb_concept_id NULL / text / frequency daily|manual / goal NULL / mastery NULL(1-5) / next_due NULL / status active|paused|archived / created_at / updated_at`
打点 = completion_history 事件（practice_tick）；练习曲线由史聚合，不另建 tick 表（YAGNI）。

**③ `sop_templates`**——SOP 模板 = 段落行范围引用
`id / note_id / name / start_line / end_line / mode readdo|confirm / created_at / updated_at`
无双写：编辑段落=编辑模板；**版本化=复用 notes 既有 versioned_save 版本链**（不建模板独立版本表）。

**④ `sop_runs` + ⑤ `sop_run_steps`**——执行档案
`sop_runs: id / template_id FK / note_id / mode / status active|done|aborted / started_at / finished_at`
`sop_run_steps: id / run_id FK / step_no / text_snapshot / status todo|done|skipped|failed / evidence_path NULL / failure_note NULL / checked_at NULL`

**⑥ `completion_history`**——完成史（统一证据，唯一数据源）
`id / ts / event_type done|abandoned|exported|export_manual_done|practice_tick|sop_run / source_type task_line|practice_item|sop_run|learning_action|export / source_id NULL / note_id NULL / text(快照) / note NULL(放弃原因等) / meta JSON NULL(迁出通道/链接等)`

# 核心处理规划（γ · 分类型特化，2026-09-05 用户裁决定案）

> 定位契约：输入 = 预处理四源初稿（课堂/图文/web/自我编辑，web 见 [web-capture-ingestion-path](../Foresight/web-capture-ingestion-path.md)）；输出 = 8 类语义标注与去向裁定，供后处理裁决漏斗消费。

## 原则

**只为"值得长期调用"的类型建正式机制**——全量强制标注不成立（用户无余力逐段分类），W/Y 等类型靠结构与搜索（不加税）。提炼动作记录的类型标记为副产品（类型视图 P2）。

## 类型 × 机制分工表

| 8 类 | 核心处理动作 | 归属 | 新增量 |
|---|---|---|---|
| W 事实/术语 | 零新增——TermAnchor→kb 概念、Table/Formula/CodeBlock 结构块已覆盖 | kb 体系（已有） | 无 |
| Y 因果 | 零机制——理解即过，整篇可检索 | — | 无 |
