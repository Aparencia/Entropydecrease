# 熵减产品设计理念：学习科学的工程化

> 本文档阐述熵减（Entropydecrease）产品的顶层设计哲学——
> 为什么这样设计、不那样设计、这些设计背后的一致性逻辑。
> 关联：PRD · MVP 画布 · 痛点图谱 · 笔记设计理念 · ADR 系列

---

## 一、产品定位的源起

### 核心洞察

技能自学者的学习链路存在一个**结构性缺口**：

```
视频知识 → [提取难] → 零散笔记 → [遗忘快] → 再次学习
                        ↑                        ↑
                  通义听悟止步于此           Anki/手动
```

市场方案要么只做「提取」（通义听悟、讯飞听见），要么只做「记忆」（Anki、闪卡 App），
要么只做「写作」（Notion、Obsidian）。**没有人把「提取→理解→记忆→应用」作为一条完整链路来设计。**

熵减填的是这个结构性缺口。

### 一句话价值主张

> 帮助技能自学者解决**视频知识提取难、学过即忘**的问题，
> 通过**课堂助手（捕获→转写→结构化）+ 间隔重复闪卡闭环**，
> 不同于云端转写工具（只提取、不持久化、按分钟收费）。

### 目标用户：「技能自学者」

不是「学生」（应试场景有成熟的教辅工具），不是「知识工作者」（他们的需求是文档协作），
而是通过视频自学**实用技能**的人群：
- 化妆教程 → 步骤记不住
- 编程课 → 记了代码但不会用
- 乐理课 → 概念理解了但很快就忘
- 健身教程 → 动作要点看了就忘

这是一个**被现有工具忽视的人群**——他们的学习是动手导向的、非结构化的、需要反复回顾的。

## 二、五个顶层设计原则

### 原则 1：本地优先是架构属性，不是营销话术

**数据不出本机是产品架构的默认值，不是可开关的功能。**

这意味着：
- 所有核心功能（捕获、ASR、OCR、拼接、笔记、编辑、搜索）100% 离线可用
- AI 是可选增强层，且需要用户明确授权后才启用
- 模型文件随安装包分发，推理在本机完成
- 用户的数据主权不可侵犯——不需要依赖任何云服务完成学习闭环

**为什么不做纯云端？**
- 隐私：视频内容包含个人信息，上传第三方不可接受
- 成本：按分钟计费的转写长期使用成本远超一次性安装
- 可靠性：离线环境下学习不能因为网络中断而中断
- 差异化：本地优先是技术壁垒，云端方案无法复制本地推理的零延迟体验

### 原则 2：AI 是增强层，不是依赖层

**AI 在熵减中的角色：** 降本增效而非核心竞争力。

- **核心能力是本地引擎**：ASR（sherpa-onnx）、OCR（PaddleOCR）、
  拼接（纯规则）、搜索（FTS5）——这些是本地的、确定的、可预测的
- **AI 做的是「补缝」**：AI 精修、知识补充、笔记健康度判断——
  这些是增强体验的，但并非核心链路依赖
- **所有云端 AI 能力都有本地兜底**：AI 精修不可用 → 本地规则版预览照常；
  AI 笔记补充不可用 → 笔记可编辑可手动补；AI 问答不可用 → 全文搜索已在

### 原则 3：科学内核决定功能优先级

**26 个认知科学/心理学机制是产品路线图的底层驱动。**

功能优先级不是按「用户想要什么」，而是按「学习科学告诉我们什么有效」：

| 科学机制 | 在产品中的体现 | 优先级 |
|----------|--------------|--------|
| 测试效应（Testing Effect） | 合书测试、生成式复习、闪卡提取 | P0 |
| 间隔重复（Spacing Effect） | SM-2 闪卡调度 | P0 |
| 进展原则（Progress Principle） | 微进展可视化、笔记演化展示 | P0 |
| 序列位置效应 | 记忆锚点策略、时间戳回链 | P1 |
| 自我效能感 | 微进步喂养、健康度正向反馈 | P1 |
| 过度自信修正效应 | 高自信错误追踪 | P1 |

这与传统产品设计的区别：
- 传统：「用户说想要 X → 做 X」
- 熵减：「学习科学告诉我们 Y 能提升学习效果 → 设计 Y 的体验 → 用户自然想要 Y」

### 原则 4：克制是竞争策略

**在什么都做的市场上，知道自己不做什么比知道自己要做什么更重要。**

熵减明确不做的：

| 领域 | 为什么不做 |
|------|-----------|
| 通用工作区（Notion 式） | 我们不是生产力工具，是学习工具 |
| 知识图谱/双链 | 单笔记阶段无输入规模，V1.0 再评估 |
| 社交/排行榜 | 与自我决定理论冲突，外在激励削弱内在动机 |
| 内容供给/课程平台 | 专注学习过程管理，不做内容 |
| 移动端（MVP 阶段） | 视频知识提取的核心场景在桌面端 |
| WYSIWYG 编辑器 | 与 Markdown 存储冲突，增加复杂度无收益 |

**克制基于三层过滤机制**（详见笔记设计理念文档）：
产品定位 → 技术架构 → 范围纪律

### 原则 5：学习链完整性是衡量标准

熵减用一个简单标准判断功能要不要做：**它是否让「知识从视频到大脑」的链条更完整？**

完整的学习链：

```
① 捕获 → ② 转写 → ③ 结构化 → ④ 笔记落库
                                      ↓
                                ⑤ 可用的笔记（读/改/存/找）
                                      ↓
                                ⑥ 好用的笔记（组织/溯源/回链）
                                      ↓
                                ⑦ 离不开的笔记（回顾/问答/健康度）
                                      ↓
                                ⑧ 知识持久化（闪卡 SM-2）
```

每个阶段的功能选择取决于它在这个链条中的位置：
- 捕获→转写→结构化：解决「提取」问题
- 笔记落库→编辑→版本：解决「沉淀」问题
- 回链→回顾→问答：解决「回访」问题
- 闪卡→间隔重复：解决「持久化」问题

**如果一个功能不能明确在链条中找到位置，它就不在这个版本中。**

## 三、设计语言：必要难度（Desirable Difficulties）

熵减的产品设计语言与其他产品的根本区别：

| 维度 | 传统产品设计 | 熵减设计 |
|------|------------|---------|
| 目标 | 让事情更容易 | 在正确的地方制造适当困难 |
| 交互 | 一键完成 | 引导参与 |
| 反馈 | 即时满足 | 延迟揭示（生成式复习） |
| 效率 | 越快越好 | 有效比快重要 |
| 衡量 | 完成率/停留时长 | 掌握度/遗忘曲线 |

这不是故作高深——这是学习科学的要求。

- **测试效应**告诉我们：主动提取比被动阅读效果好 2-3 倍
  → 闪卡先显示正面，用户回忆后再揭示反面（生成式复习），而非一键展示全部
- **生成效应**告诉我们：自己产出的信息记忆效果好 2-5 倍
  → 笔记可编辑可重构，而非只看 AI 生成的终态
- **间隔重复**告诉我们：分散练习优于集中突击
  → 每日复习队列而非考前突击

**熵减不承诺「让学习变得轻松」，它承诺「让学习变得更有效」。
轻松和有效在很多时候是矛盾的，我们选择站在有效这一边。**

## 四、模块关系：数据驱动的有机体

熵减的各功能模块不是并排的独立工具，而是**通过数据流动形成有机整体**：

```
课堂助手（捕获）
     │
     ▼ 会话（转写+OCR+关键帧）
     │
     ├─→ 产物视图（结构化块）
     │      │
     │      ▼
     ├─→ 笔记（Markdown + 证据回链）
     │      │
     │      ├─→ 编辑/版本/AI 精修
     │      │
     │      └─→ 闪卡（SM-2 间隔重复）
     │             │
     │             └─→ 复习（生成式提取）
     │
     └─→ 费曼学习法（深度理解）
            │
            └─→ 卡壳救援 → AI 即时诊断
```

这种结构的特征：
- **数据不重复**：会话的转写段是原料，笔记引用原料（块模型不复制），
  闪卡引用笔记段落
- **能力可叠加**：基础功能全部离线可用，AI 每增加一层就增强一层体验
- **路径可选择**：用户可以走完完整链路，也可以只使用笔记模块

## 五、版本演化哲学

熵减的版本规划遵循「自底向上」原则：

| 阶段 | 聚焦 | 原则 |
|------|------|------|
| v0.1~v0.3 | 捕捉链路地基 | 先让捕获→转写→OCR 跑通，再谈体验 |
| v0.4~v0.6 | 提取质量信任 | 质量可观测、可追踪、可信任 |
| v0.7~v0.9 | 会话体验深度 | 产物体系、AI 精修、视频档案 |
| v0.10 | 笔记能力建设 | 从可用→好用→离不开，单笔记做到极致 |
| V1.0 | 多笔记+闪卡闭环 | 组织/持久化/回顾全面打通 |

每一阶段都在回答一个问题：**「现在的链条在哪里断了？下一段接上。」**

## 六、技术选型哲学

技术选型决策遵循的优先级（2026-08 已裁决）：

1. **本地优先**：所有关键路径的运行不依赖网络
2. **离线全功能**：核心体验从安装第一天起 100% 可用
3. **AI 为增强层**：云端能力能提升体验，但不构成依赖
4. **成熟生态**：选型优先社区活跃、文档完善的方案
5. **避免锁定的原则**：Markdown 存储、SQLite 数据、标准格式导出

具体技术栈：Tauri 2 + React + TypeScript + Rust；sherpa-onnx（ASR）；
PaddleOCR（OCR）；SQLite（rusqlite）；云端多模态（Qwen-VL 系，可选）

## 七、与竞品的本质差异

| 维度 | 通义听悟/讯飞听见 | Notion/Obsidian | 熵减 |
|------|------------------|----------------|------|
| 核心场景 | 会议/访谈转写 | 知识管理/写作 | 技能自学 |
| 数据路径 | 上传→云端处理→下载 | 本地/云端写作 | 捕获→提取→沉淀→记忆 |
| 离线能力 | ❌ | ✅（Obsidian） | ✅ 全功能 |
| AI 依赖 | 核心依赖 | 可选 | 可选增强层 |
| 科学内核 | ❌ | ❌ | ✅ 26 机制 |
| 数据主权 | ❌ 数据上云 | ⚠️ 取决于方案 | ✅ 数据不出本机 |
| 锁定风险 | 高（格式/平台） | 中（Obsidian 文件/Notion 块） | 低（Markdown+SQLite 可导出） |

**熵减不做「更好的转写工具」或「更好的笔记软件」——它做的是从视频知识到个人能力的完整链路。**
