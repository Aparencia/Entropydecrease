## 附录：立项与规划流程精要（源自 phase-1-planning 萃取）

> 原 4 份规划方法论文档（立项/MVP 验证/需求头脑风暴/估算）按「保留决策结论」原则萃取为目的+检查清单；架构决策记录（04-ADR）因具独立规范价值已完整保留为 standards/adr.md。

### 项目启动与立项流程

在正式投入开发前，系统性地评估项目可行性、明确范围和目标，避免"做到一半发现方向错了"。

**核心检查项：**
- [ ] Problem Statement 已用一句话明确表述
- [ ] 目标用户和核心场景已定义
- [ ] 可行性评估 5 个维度均已完成
- [ ] 主要风险已识别并有缓解方案
- [ ] 技术选型已确定并记录决策理由
- [ ] MVP 范围已用 MoSCoW 划定
- [ ] 里程碑和交付日期已设定
- [ ] 代码仓库已创建并初始化
- [ ] 基础工具链已配置（lint/format/git hooks）
- [ ] README 和 .env.example 已编写
- [ ] 首次提交已完成


### MVP 验证与原型流程

在投入大量开发资源前，用最小成本验证核心假设是否成立，避免"做了半年发现没人要"。

**核心检查项：**
- [ ] 核心假设已明确列出（不超过 5 个）
- [ ] 风险最高的假设已识别
- [ ] 每个假设有可衡量的验证标准
- [ ] 选择了成本最低的验证方法
- [ ] 原型/实验已完成
- [ ] 至少 5 个目标用户参与了测试
- [ ] 用户反馈已记录和分析
- [ ] Go/No-Go 决策已做出
- [ ] 决策理由已记录
- [ ] 下一步行动已明确


### 需求理解与头脑风暴

系统性地收集、分析和验证需求，确保开发的是用户真正需要的东西；通过结构化头脑风暴激发创意并收敛为可执行方案。

**核心检查项：**
- [ ] 所有需求已通过 5W1H 澄清
- [ ] 每个需求有明确的用户故事
- [ ] 每个用户故事有验收标准（Given-When-Then）
- [ ] 需求已用 MoSCoW 或 RICE 排优先级
- [ ] 模糊需求已与利益相关者确认
- [ ] 头脑风暴产出了多个备选方案
- [ ] 方案已收敛为 1-2 个可执行选项
- [ ] 选中的方案已转化为 backlog item
- [ ] 需求文档已归档


### 估算与迭代规划

将需求转化为可执行的工作计划，合理估算工作量和时间，设定可持续的开发节奏，避免"永远做不完"或"赶工出烂代码"。

**核心检查项：**
- [ ] 所有 Epic 已拆解为 Story 和 Task
- [ ] 每个 Task 在 2-8 小时范围内
- [ ] 估算已完成（故事点或小时）
- [ ] 迭代节奏已确定
- [ ] 迭代容量已计算（含缓冲）
- [ ] 本迭代目标已明确（一句话）
- [ ] 依赖关系已识别
- [ ] 风险项已标注缓冲
- [ ] 进度跟踪方式已确定
- [ ] 验收标准每个 Story 都有
