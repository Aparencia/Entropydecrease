# 学习全链路认知地图与产品蓝图 v3
## ——融合裁决卷：从双轨分叉到统一产物层
> **文档性质**：熵减产品规划工作参考文档（v3 融合裁决卷）
> **演进来源**：v1.0（47痛点/26机制）→ v2.0（容器地形上卷 + feed 地形下卷）→ 本版：对 v2 上下卷分叉关系的正式裁决
> **本文档地位**：与 v2.0 并行生效——v2 定义两个地形各自的理论，本版裁决它们如何共存于同一个产品；v2 不归档，v3 是其融合层
> **适用场景**：视频/网课学习（容器地形）＋短视频消费学习（feed 地形），目标用户为技能自学者与网课学生

## 第一部分：文档总览
### 1.1 v2 留下的三个悬而未决
v2.0 上下卷各自完备，但留下了三个必须由 v3 裁决的问题：
| # | 问题 | v2 的状态 |
|---|------|-----------|
| 1 | "短视频"是什么？边界锚定平台还是内容形态？ | 未定义（下卷只描述了 feed 地形，未划界） |
| 2 | 上下卷是同一个产品还是两个产品？ | 悬置（两卷理论各自成立，关系未裁决） |
| 3 | 如果共存，融合点在哪一层？ | 悬置 |
### 1.2 三个裁决结论（本版核心）
1. **地形定义裁决**：边界不在平台、不在时长、不在用户声明，而在**学习结构住在哪里**——结构在内容里是容器地形，结构在行为里是 feed 地形；声明/采集只是路由开关。
2. **产品形态裁决**：一个产品、一个产物模型、两条地形管线。不拆版本线，不隔离进程。
3. **融合点裁决**：融合发生在**产物层**（笔记组），不在管线层——统一的笔记组模型 + 组级学习循环，让两种来源的内容进入同一个学习闭环。
### 1.3 一句话定位（v3 修正版）
v2 的定位"维护'我正在学会X'的叙事连续性"不变，v3 补充其实现形态：
**结构在内容里的，成为课程；结构在行为里的，成为组；两者被同一个学习循环接住。**

## 第二部分：地形定义裁决——学习结构住在哪里
### 2.1 候选判据的排除
| 候选判据 | 排除理由 |
|----------|----------|
| 平台（抖音/B站/YouTube） | 同一平台内并存 15 秒口播、长视频合集、付费专栏——形态差异大于平台差异；且桌面端主要捕获面是网页播放器与本地文件，平台 API 不可达，多端协调下平台属性每端变形 |
| 时长（长/短） | 边缘案例切错：90 秒的完整公式推导有结构，30 分钟的闲聊切片无结构。时长只能作启发式信号 |
| 学习声明（用户是否选择采集） | 任何内容都可通过采集获得声明，判据失去判别力——声明改变流向，不改变地形 |
| **结构承载性（采用）** | 学习结构住在内容里（作者预制的章节/进阶/论证）→ 容器地形；学习结构住在行为里（单条无结构，消费模式有结构）→ feed 地形 |
### 2.2 声明的正确定位：路由开关
用户对短视频按下"采集"之后发生什么，正好暴露判据的本质：
| | 采集一段网课 | 采集一条短视频 |
|---|---|---|
| 产物 | 有章节、前置依赖、论证链的**课程笔记** | 三五句话 + 几张示范画面的**碎片** |
| 能否支撑"我在学X" | 能——构成知识实体 | 不能——300 条碎片相加不等于一门课 |
**采集/声明改变内容的归属，不改变内容的性质。**碎片可以资产化（可搜索、可复习），但不能冒充课程——这正是 v2 上卷"动机App化/假燃料"死法的微观形态，产品必须如实呈现碎片的身份。
### 2.3 边缘案例验证
| 案例 | 结构承载性判据的路由结果 | 自洽性 |
|------|--------------------------|--------|
| 抖音付费专栏（有章节） | 作者结构在内容里 → 容器地形 | ✓ 入口在抖音，地形属上卷——证明边界与平台无关 |
| 单条 20 分钟系统教程 | 单条承载完整论证 → 自成一组（容器化处理） | ✓ |
| 90 秒公式推导 | 结构密度高 → 自成一组 | ✓ 长短判据失效处的正确路由 |
| 半年刷的 300 条穿搭视频 | 单条无结构、模式有结构 → feed 地形，按主题归组 | ✓ |
| 用户收藏 50 条同主题短视频 | 归组（feed）；用户主动"收藏→大纲"时升级为容器 | ✓ 地形可迁移，迁移即下卷的"容器交接" |
### 2.4 多端协调的推论
锚定结构承载性后，跨端同步的资产是平台无关的：**学习声明 + 消费账本 + 能力测量 + 笔记组**。任何端产生的内容都按同一判据路由进同一产物模型——平台只是适配器（代码中 `PlatformAdapter` 已按此设计）。

## 第三部分：技术架构裁决——引擎共用，循环分叉
### 3.1 三层划分
```
公共底座（地形无关，已建成）
├── sherpa-onnx ASR / PaddleOCR / 视频解码 / 常驻引擎池
├── 四维解耦（ContentForm × VisualTier × DomainTag）——结构密度的可计算代理
└── PlatformAdapter（平台壳适配）
        ↓ 地形分叉（terrain 标记路由）
地形管线（地形强相关）
├── 容器：实时捕获 → 流式转写 → 会话级归档 → 笔记产物（天时钟）
└── feed：导入/账本 → 异步批处理 → 主题组聚合 → 组产物（季/阈值时钟）
        ↓
统一产物层（v3 融合点）
└── 笔记组：两种来源的归宿，同一学习循环的入口
```
### 3.2 为什么"都是视频分类"却曾需要两套理论
四维解耦回答"**这段内容是什么**"（内容本体）；飞轮/同步器回答"**这个人如何与内容共处**"（生命周期本体）。同一分类结果在两个地形语义不同：一段"教程"视频，在容器是一个会话（被提取、被复习），在 feed 是半年 300 条中的一条（测量材料）。**分类是管线的公共输入，生命周期是地形的分叉输出**——公共底座与分叉理论不矛盾。
### 3.3 成本裁决
| 方案 | 裁决 | 理由 |
|------|------|------|
| 共享引擎 + 独立管线 | **采用** | 增量约 20–30%：terrain 标记 + 管线分叉 + 组模型；引擎单例复用 |
| 完全隔离进程 | 否决 | 模型双份加载、IPC 复杂度翻倍，零收益 |
| 无实时竞争的事实 | 备注 | feed 管线是异步批处理，与容器实时捕获时序零竞争，双轨共存比预期便宜 |

## 第四部分：融合方案——统一产物模型（本版核心）
### 4.1 融合点裁决
不在管线层融合（代价高、语义混），不做物理隔离（客群重叠、漏斗相连）——**在产物层融合：一切采集产物归入"笔记组"，组是唯一容器，两种来源只是组的两种形成方式**。
```
结构密度高 → 自成一组（无论长短）
结构密度低 → 归入主题组（按 DomainTag 领域粒度）
```
### 4.2 组的三条设计契约
**契约一：分组粒度对齐领域，拒绝大类。**"人生成长"式的大类会把化妆/编程/乐理装进一个组，退化为杂物抽屉。判据：**一个组能否回答"关于X，我学到了什么"——答不上来的粒度就是太粗。**支持 DomainTag 自动归组 + 用户自建主题组。
**契约二：组是学习单元，不是档案盒。**这是融合成败的分叉点：
| | 档案盒（仅归档） | 学习单元（进循环） |
|---|---|---|
| 碎片组的命运 | 存起来、能搜到 | 组内碎片生成闪卡、主题自测、进度对账 |
| 上下卷差异 | 依然存在（学习 vs 存档） | **真正融合**（两种来源共享同一学习循环） |
采用后者：**闪卡/复习的绑定粒度从"会话"提升到"组"**——短视频碎片也能被间隔复习、被主题测试。这正是 v2 下卷"收藏→大纲（沼泽排涝）"的轻量实现。
**契约三：组有结算机制（防沼泽）。**短视频组天然膨胀。组内碎片达到阈值或周期时触发对账：提炼核心概念、合并重复碎片、归档低价值项。复用 v2 下卷"换季结算"设计资产，时钟从"季"缩短为"组阈值/周期"。
### 4.3 融合后的残留差异
仅剩一处，且对用户心智不可见：**容器管线是实时提取（流式 ASR/OCR），feed 管线是导入式批处理**。产物形态、学习循环、界面语义全部统一。

## 第五部分：两卷资产的重新定位
### 5.1 上卷资产：全保留
提取管线、笔记、精修、复习、九状态/骨折层设计——全部保留，是容器地形管线的既有实现。
### 5.2 下卷资产：三档重定位
| 档位 | 资产 | 处置 |
|------|------|------|
| 一期吸收 | 容器交接 | 落地为"收藏→大纲"的轻量版：主题组升级机制 |
| 一期吸收 | 换季结算 | 落地为组结算机制（阈值/周期触发） |
| 二期增强 | 显影报告 / 盲测仪器 / 常模库 | 降级为可选增强：先验证"碎片能升级为学习材料"（组级复习/测试的使用率），通过后再建测量层 |
| 理论保留 | 同步器模型（失同步双向性） | 作为元理论保留：容器防叙事透支、feed 把叙事拖上来追赶能力——仍是两地形设计的依据 |
### 5.3 元理论统一
v2 上下卷的元结构本就同构：稳态/瞬态区分、事件驱动干预、身份指标（第二门课启动率 ≈ 下一学期回归率）、指标异端护城河。差异只在失同步方向与主时钟。v3 的融合不消灭这个差异，只是让差异止步于管线与节奏，不再侵入产物与循环。

## 第六部分：指标体系融合
| 层级 | 指标 | 含义 |
|------|------|------|
| 反指标 | DAU、使用时长（v2 遗产）；显影报告人均重读次数（若二期建显影） | 引擎效率与停留时长负相关；重读＝把证据当安慰剂 |
| 过程指标 | 碎片升级率（碎片→闪卡的比例）、组结算执行率、主题组活跃数 | 融合是否真实发生：碎片是否真的进入了学习循环 |
| 北极星 | **笔记组的学习循环完成**（组有复习记录＋有自测记录＋经历过结算） | 上卷"有证据的毕业"与下卷"有证据的校准"在组粒度上的统一读数 |
| 身份指标 | **第二组启动率** | 用户自愿开始第二个主题组/第二门课——与 v2 两卷的身份指标严格平行 |

## 第七部分：实施路线图（v3 版）
- **Phase 1：笔记组基建**——组数据模型（terrain 标记 + 来源溯源）、结构密度路由（四维解耦信号接入）、碎片独立身份（原料层，不与课程笔记混装）
- **Phase 2：学习循环统一**——闪卡/复习绑定粒度提升到组、主题自测、组进度对账
- **Phase 3：组结算机制**——阈值/周期触发、核心提炼、重复合并、低价值归档
- **Phase 4：测量层增强（可选）**——显影报告 / 盲测仪器 / 常模库（v2 下卷重资产），以 Phase 2 的碎片升级率为启用前置条件

## 第八部分：Pre-mortem（v3 特有死法）
| 死法 | 描述 | 危险等级 |
|------|------|----------|
| 组沼泽化 | 结算机制形同虚设，主题组三个月后变成第二个收藏夹 | ★★★★★ |
| 路由误判 | 结构密度信号不准：高结构碎片被扔进主题组（埋没）、低结构长视频自成一组（空洞） | ★★★★ |
| 强行融合 | 碎片闪卡质量低劣，组级复习体验差——"碎片升级"假设不成立却继续加码 | ★★★★ |
| 测量层过度建设 | Phase 2 未验证通过就开建盲测/常模（v2 下卷重资产），资源错配 | ★★★ |
| 假燃料微观形态 | 碎片组伪装成课程进度，制造"我学了一门课"的虚假叙事 | ★★★ |

## 第九部分：版本线与功能开关裁决
| 层 | 机制 | 理由 |
|----|------|------|
| 版本线 | **不拆分**：同一 dev 主线、同一 SemVer、同一发布 | 同一产品、同一品牌（记忆主权/本地世界叙事对两地形同真）、同一数据主权 |
| 数据层 | terrain 标记 + 来源溯源 | 公共底座复用、管线分叉的前提 |
| 交付层 | feed 相关能力以功能开关引入，默认关闭 | 符合项目"增强能力默认关闭"传统；Phase 2 验证前不默认启用组级循环 |
| 导航层 | 界面按钟分域：容器管线出现在每日视图/会话面；feed 产物只出现在组与结算面 | 防止心智污染，v2 三层界面架构的直接推论 |

## 第十部分：一句话
v1 问：学习有哪些环节会失败。v2 问：学习在两种地形里各以什么方式失败。v3 的回答是：
**两种地形，一个容器——结构在内容里的成为课程，结构在行为里的成为组，都被同一个学习循环接住。**
产品不是同时做两件事，而是用两种进料方式，养同一个"我正在学会X"的叙事。

## 附录：判据速查
| 判据 | 定位 |
|------|------|
| 平台 | 适配器（PlatformAdapter），不是边界 |
| 时长（长/短） | 路由启发式，不是判据 |
| 学习声明/采集 | 路由开关：改变归属，不改变性质 |
| **结构承载性** | **地形边界**：结构在内容里→容器；结构在行为里→feed |
| 结构密度（四维解耦代理） | 组路由信号：高密度自成一组，低密度归主题组 |
| 组粒度 | 对齐 DomainTag 领域级，拒绝大类 |
| 组语义 | 学习单元（复习/测试/结算绑定到组），不是档案盒 |
