# 笔记设计理念：活沉淀（Living Sediment）

> 本文档阐述熵减笔记模块的设计哲学——不是文档编辑器，不是提取产物容器，
> 而是一个**活的沉淀系统**。
> 关联：v0.10.0 版本规划 · PRD · 痛点图谱 P7/P12/P22/P38/P47

---

## 一、定位：学习的枢纽

### 市场对照三角

```
                听悟/妙记               Obsidian/Notion            熵减笔记
定位             记事的终点              写作的起点                 学习的枢纽
用户动作         提取→查看               打开→写作                  沉淀→编辑→回顾→出发
上游依赖         无                      无                         会话产物（转写+OCR+AI）
下游出口         无                      导出/分享                  闪卡/问答/回顾流
数据属性         文档（终态）             文件（源头）               证据（活态）
回访机制         无                      用户自愿                   回链+注意力跟踪+回顾流
```

**核心差异**：市场产品的笔记要么是「产出即终态」（听悟），要么是「从零写」（Obsidian）。
我们的笔记是从会话中自然沉淀、以证据锚定、可持续演化、能反哺学习的**活体**。

### 「活沉淀」的三层含义

1. **沉淀于会话** — 笔记不是从头开始写，而是从课堂助手的产出中「沉降」出来。
   转写分段 → 过滤 → 结构化 → 落库，每一次转换都是去芜存菁。

2. **锚定于证据** — 笔记的每一段都与视频证据通过时间戳回链连接。
   这不是可选的附加功能，而是笔记完整性的核心承诺：
   「你看到的每一句话，都能追溯到原始来源」。

3. **演化为知识** — 笔记不是一次性产物。用户编辑、AI 精修、版本迭代、
   段落重组，使笔记从粗糙的转写沉淀，逐步结晶为精炼的个人知识。

## 二、克制哲学：范围纪律 × 质量深度

### 三层过滤（为什么不做某些事）

**第一层：产品定位过滤**
> 「我们是笔记模块，非通用工作区」

不抢 Notion 的写作盘（不做块编辑器、数据库视图、模板系统），
不做 Obsidian 的知识库盘（不做双链、图谱、文件级资产），
不做听悟的终点盘（不做纯转写展示）。

**第二层：技术架构过滤**
- 与 Markdown 存储冲突的 → 不做（块编辑器、WYSIWYG）
- 与本地优先冲突的 → 不做（协同编辑、实时协作）
- 与 SQLite 资产模型冲突的 → 替代方案（导出补偿文件级资产）

**第三层：范围纪律过滤**
- 属多笔记组织的 → V1.0（数据库视图、双链、文件夹）
- 属闪卡体系的 → 顺延（笔记即卡片）
- 与产品叙事不一致的 → 不做（网页剪藏）

### 克制不是妥协

在边界内，把该做的事情**做到极致**：

- **阅读视图**：不只是渲染，而是可交互的文档
  — 任务列表可勾选、时间戳可跳转、搜索可高亮定位
- **编辑视图**：不只是 textarea，而是可结构化的源码编辑器
  — 段落级操作、快捷键、标签管理
- **版本链**：不只是快照，而是可理解的历史
  — 来源徽标、结构化 diff、成本透明度
- **回链**：不只是链接，而是证据锚定
  — 段落级精度、悬浮预览、双向跳转

## 三、核心设计原则

### 原则 1：证据第一性

笔记的内容来自会话证据，而非用户凭空写作。这意味着：

- 每段内容的时间戳可追溯到视频时间点（`[[ts:ms]]`）
- 来源会话的上下文在一键可达范围内
- 编辑不会切断证据链（编辑只是叠加层，原始证据始终可回溯）

### 原则 2：Markdown 为本

选择 Markdown 而非块编辑器的原因：

- **机器生成友好**：课堂助手产出天然为 Markdown，块模型需要有损转换
- **版本 diff 可行**：Markdown 的纯文本特性使逐行 diff 成为可能，
  块模型的嵌套结构 diff 复杂度指数级上升
- **零摩擦编辑**：textarea 起手，零额外依赖；进阶用户可直接编辑源码
- **导出无门槛**：Markdown = 通用格式，不存在厂商锁定

### 原则 3：学习可见

笔记不只是「记下来」，而是要让学习过程可感知：

- 注意力跟踪（A6）记录用户在哪些笔记上花了时间
- 版本历史可视化（A4）展示知识的演化过程
- 段落级操作（A1）让笔记结构随理解深度演进而变化
- 未来：笔记健康度、回顾流、知识半衰期标记

### 原则 4：可迭代性

笔记不追求「一次完美」：

- 自动保存保底不丢稿
- 版本链支持任意回滚
- AI 精修/补充可在任何阶段触发
- 标签/属性系统为未来组织维度留扩展位

## 四、A 层增强的设计意图

v0.10.0 在基础能力之上增加 A 层特征，体现了「不越界做深」的核心理念：

| A 层特征 | 解决的痛点 | 科学机制 | 设计意图 |
|----------|-----------|---------|---------|
| A1 段落级操作 | P22 笔记质量低 | 认知负荷理论 | 让用户能结构化组织信息，而非被动接受机器产出 |
| A2 搜索高亮定位 | P12 知识检索困难 | — | 阅读时的快速定位能力，降低查找摩擦 |
| A4 版本可视化 | P46 进展不可见 | 进展原则 | 让笔记的演化过程可见可感，持续喂养内在动机 |
| A5 回链预览 | P38 记忆黑洞 | 序列位置效应 | 悬浮即见来源，降低验证成本，强化证据信任 |
| A6 注意力跟踪 | P14 元认知缺失 | 自我效能感 | 不入侵主交互，默默收集数据为元认知仪表盘铺路 |

这些特征都不需要新数据模型、新后端命令、新外部依赖，
是在现有架构内用纯前端增强 + 极轻量后端复用实现的「不克制」。

## 五、与全局产品理念的关系

笔记模块是熵减产品理念的**集中体现**：

- **本地优先**：所有笔记数据存本地 SQLite，导出 Markdown 保底
- **AI 为增强层**：AI 精修/补充是可选叠加，编辑/回链/搜索 100% 离线可用
- **科学内核**：痛点图谱的 P7/P12/P22/P38/P46/P47 在笔记层有对应解法
- **学习链完整性**：会话→笔记→编辑→版本→回链→搜索→新建，形成闭环
- **克制不妥协**：范围纪律下做深做透

## 六、未来演化方向

v0.10.0 完成的是单笔记基础。后续版本的自然演化路径：

1. **多笔记组织**：标签体系进阶、课程级分组、轻量互链（V1.0）
2. **笔记→闪卡联动**：段落级 QA 提取、间隔重复闭环
3. **回顾流**：笔记级待回顾标记、到期排序、睡前回顾提醒
4. **笔记健康度**：本地规则版（段落长度/结构化程度/置信残留）→ AI 增强版
5. **导出体系**：Markdown/HTML/PDF，弥补 SQLite 非文件级资产的局限

但核心设计理念不变：**笔记是学习的枢纽，不是终态，不是起点，
而是从证据到知识的过渡态——活沉淀。**
