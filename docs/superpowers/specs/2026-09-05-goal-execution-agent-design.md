## 2. "执行型"的定义与红线（先划界再设计）

- **"执行"在本系列的语义**：agent 回合式产出**每日可执行清单**（规则骨架，AI 可选增强）、归集"完成信号"、生成复盘草稿——**不自动操作系统动作、不自动标记完成、不自动建/改/删任何用户数据**（建议制确认后落库，红线同 ADR-028 人类裁决）。
- 完成信号的权威来源=既有循环本身（组复习结算/里程碑勾选/应用记录），agent 只聚合展示，不自造第二账本。
- 语音/图像不出本机；纯文本上云仅在有 AI 授权且对应独立开关（默认关）下进行；预算档位/审计复用。

## 3. 分期设计

### P0 · 执行数据层与规则骨架（v0.21.0 建议）

1. **每日清单现算（零新主表）**：`daily_focus_snapshot(goal_id, date)` 纯函数聚合：
   - 到期复习：该目标关联组内 `list_due_cards`（新增命令，FSRS 到期现算，无卡即空）；
   - 里程碑推进：未完成里程碑（含 dueWeeks 倒计时、判据类型）；
   - 体系缺口任务：目标服务体系的节点缺口（依赖 D2 产出结构，跨批后置接入）；
   - 弱项信号：最弱概念 Top（复用 concept_weakness 判据）；
   - 规则优先级（确定性、golden 可测）：复习到期（今日截止）> 里程碑临近（≤7 天）> 弱项 > 缺口。
2. **完成信号归集**：当日"已完成"=复习日志/里程碑 done/应用记录按日聚合（既有事件/记录，零双写）；实践类手动补记（可选）：`execution_logs(kind=practice, goal_id, ref_note_id?, date, note)` 小表（幂等去重）。
3. **UI：目标详情「今日学习包」折叠卡**：
   - 交互矩阵（完整审计）见 §5；
   - 每项=点击跳转原生动作（该组复习面/里程碑详情/体系节点），从"看清单"到"做"零中间层。
4. 无 AI 时全功能（本地优先降级链：规则骨架=产品本体，AI=增强）。

### P1 · AI 增强层（v0.21.1，全部默认关独立开关）

1. **AI 晨间包**（`goalDailyAIEnabled` 默认关 + 授权前置 + budget 复用）：输入=规则清单+近 3 日完成轨迹+弱项+kb 检索线索 → 输出=清单重排建议+新增建议项（逐项建议制确认，未确认不落库）。
2. **晚间复盘草稿**：当日完成/未完成 + 次日建议（建议制，可采纳入明日包或丢弃）；断网=规则模板复盘（完整可用）。
3. **"卡住求助"**：接通既有 dock 对话，预注入当日上下文（goal_chat_context）+ kb L3；前端 `/goal` 命令解析补齐（v0.18.2 欠批项一并清）。
4. prompts 资产 `prompts/goal_execute.json`；ai_tasks op_type 白名单扩展 `goal_daily`/`goal_review`；审计/成本沿用。

### P2 · 闭环增强（v0.21.2）

1. 判据升级（建议制）：里程碑判据"应用记录/节点证据"信号并入完成提示（绑定体系的节点应用计数），毕业判定给建议不给自动；
2. 体系反哺：执行记录回写 concept 激活信号（goal 维度引用），弱项信号随执行刷新；
3. 周契约联调：目标周完成度提示（targetDays/Cards 现算），断签不清零纪律不变。

### P3 · 不做（远期候选，需新 ADR 单独授权）

常驻自由执行/自动外部动作/自动完成学习循环/自动结算毕业——不在本系列承诺，避免"假进步感"反指标（体系哲学防线）。

## 5. 执行面板交互矩阵（完整审计）

维度同批次设计 §2.9。适用"今日学习包"卡（目标详情内）。

| 场景/动作 | 行为 | 边界 |
|---|---|---|
| 清单为空 | 空态文案+「为何今日无建议」解释（无到期/无未完成里程碑/无目标绑定组） | 不空转制造任务（反"进步感"红线） |
| 条目点击 | 跳转原生动作面（组复习/里程碑/体系节点） | 不内嵌执行（零中间层） |
| 条目 ✓ 勾选 | 仅对"可确证信号"开放（里程碑类=走既有勾选+埋点；复习类=引导开始该组复习面，由结算信号自动归集，不做假完成） | 勾选=真实动作入口，非状态伪造 |
| 手动补记"练习" | 弹层（做了什么/关联笔记可选）→ execution_logs | 幂等去重；可删（误记） |
| AI 建议项（P1） | 「✨ AI 建议 + 理由」卡，逐项 [采纳][忽略]，采纳=并入今日清单（临时不落库） | 建议制；未确认不落库 |
| 复盘入口 ✍ | 规则模板（本地）或 AI 草稿（P1，默认关）→ 草稿预览 [采纳入明日][丢弃][编辑] | toast 撤销 3s；采纳=写入明日包输入（明日现算含"延续项"） |
| 求助 | 卡住项旁 💬 → 既有 dock 对话预注入上下文 | 对话不落执行账本 |
| 状态机 | 今日卡状态：无目标/加载/有建议/进行中/全完成/逾期回滚（次日未完成项按规则重排进明日，不惩罚） | 弹性承诺纪律（断签不清零） |
| 键盘/可达 | 清单原生滚动；按钮原生可达；无拖拽 | 列表级键盘导航=观察项（同批次 §2.9 约定） |
| 数据一致性 | 完成信号跨页变更 → data:goals-changed/data:* 事件刷新（useDbRefresh 既有） | 现算无缓存竞态 |

## 6. 数据与命令清单（P0 范围）

- 新：`list_due_cards(goal_id, date)`（现算到期卡）、`daily_focus_snapshot`（纯函数+golden）、`log_practice_execution`/`delete_execution_log`、`execution_logs` 表（幂等迁移）；
- 无新表存"今日包"（现算视图）；里程碑/复习/应用信号全部复用既有表与事件。
- 埋点：execution 相关 metrics_events kind 扩展（practice_logged）。

## 7. 测试与验收（全代码自验证）

- golden：daily_focus 规则优先级矩阵（含空/全完成/逾期回滚）、due 现算边界；
- 组件：执行面板状态机（空/建议/完成/回滚）、手动补记幂等；
- 端到端 mock：晨间包/复盘建议制两路径（采纳/忽略）；
- 真机：连续 3 日真实使用（有目标+有到期复习），验收"每天 5 分钟闭环"是否成立；无 AI 开关全流程可用。

## 8. 风险表

| 风险 | 防线 |
|---|---|
| 清单变任务负担（新记账压力） | 零新账本（信号归集复用）；空态诚实不制造任务；断签不清零 |
