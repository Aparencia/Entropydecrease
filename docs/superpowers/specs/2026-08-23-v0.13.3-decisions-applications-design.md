## 一、总架构

自底向上四层（AGENTS.md §3）：

```
原子层：knowledge_pure.rs 增 validate_decision_input（used_refs JSON 结构校验，TDD golden 先行）
业务层：db_knowledge_decisions.rs（一表两面 CRUD）＋ db_knowledge_concepts.rs 增 set_concept_applied
        （last_applied_at 更新，列已存在——不迁移）＋ types.rs 增 KnowledgeDecision/NewKnowledgeDecision
系统层：commands_knowledge_decisions.rs（log_decision/log_application/list/get/delete，参数校验与编排）
UI 层：概念详情面板"记一次使用"按钮 + 决策日志区（概念页默认开；组/复习面本版不做）
```

硬约束：
- **一表两面**：`knowledge_decisions` 用 `kind` 区分 decision/application，**不双表双记**（决策=思辨面，应用=学习面最小环）。
- **只记"我的决策"**：`knowledge_decisions` 是**唯一写入路径**，且仅存用户显式输入；**禁止**从产物层 `ArtifactKind::Decision`（内容里的"决策"）自动升格/自动写——不建任何"决策→记录"回路（假证据，红线）。
- **引用必填防膨胀**：used_refs 非空才计入指标；无引用记录不入库（command 层拒绝）。
- **零破坏**：`db_migrations.rs` 只新增建表/索引；`concepts.last_applied_at` 列已存在（v0.13.1），不 `ensure_column`；`metrics_events.kind` 为 TEXT，**不迁移**，仅新增两个 kind 字符串（复用既有 `add_metric_event`）。
- **命名纪律**：decision/application/system/refs 术语贯穿全栈（Tauri command 与 TS 类型同名，snake→camel 对齐）。

## 二、数据层（db_migrations.rs 增量——建表幂等）

沿用整合分析 §4.2 SQL 逐字（仅补索引）：

```sql
-- v0.13.3（REQ-208）：决策与应用（一表两面；四行法字段）
CREATE TABLE IF NOT EXISTS knowledge_decisions (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  kind TEXT NOT NULL DEFAULT 'decision',       -- decision/application
  system_id INTEGER REFERENCES knowledge_systems(id) ON DELETE SET NULL,
  question_id INTEGER REFERENCES knowledge_nodes(id) ON DELETE SET NULL,
  used_refs TEXT NOT NULL DEFAULT '{}',        -- JSON（结构见下；引用必填，command 层拒绝空）
  content TEXT NOT NULL,                       -- 决策内容/应用动作
  expectation TEXT, actual TEXT, reflection TEXT,
  decided_at INTEGER NOT NULL, created_at INTEGER NOT NULL
);
CREATE INDEX IF NOT EXISTS idx_decisions_system ON knowledge_decisions(system_id);
CREATE INDEX IF NOT EXISTS idx_decisions_kind   ON knowledge_decisions(kind);
```

**used_refs JSON 结构**（设计裁决，扩展 §4.2 注释——覆盖体系实体/证据全引用）：
```json
{ "node_ids":[..], "concept_ids":[..], "model_ids":[..],   // 体系实体引用
  "group_id":n, "card_id":n, "note_id":n, "fragment_id":n } // 证据引用（四类 LinkTarget）
```

**不可变约束 / 零破坏**：
- `concepts.last_applied_at`（列已存在）更新**只在 db 层追加方法**：`Db::set_concept_applied(id, applied_at_ms) -> Result<bool>`（一次 UPDATE 置 last_applied_at＋updated_at）。**不迁移、不改既有查询**。
- `metrics_events` 本版仅新增 kind 字符串 `decision_logged / application_logged`（`concept_promoted` 属 v0.13.2、`system_audited` 属 v0.13.4，本版不做）。

## 三、原子层：纯函数（TDD golden 先行）

```rust
// knowledge_pure.rs —— 无副作用、无 DB（实体存在性由 command 层校验）
pub fn validate_decision_input(refs_json: &str, kind: &str) -> Result<String, String>;
// 只校验 used_refs 的 JSON 结构，不做存在性（结构契约，非证据契约）。
// 返回规范化紧凑 JSON（存储态）；同一 refs 的多种写法序列化为一致。
// 规则（kind 驱动）：
//  - 必须是 JSON 对象（非数组/字符串）：否则 Err「引用需为对象」。
//  - 只接受已定义键 node_ids/concept_ids/model_ids/group_id/card_id/note_id/fragment_id，
//    未知键 Err「不支持的引用键」；每个 id 必须 >0（≤0 Err「无效的 id」）。
//  - decision：至少引一个体系实体（node/concept/model）**或**一个证据（group/card/note/fragment），
//    全空 Err「决策需引用体系实体或证据」。
//  - application：至少一个引用（概念或证据）；命令层再按 §四 挂载规则强制
//    「挂概念或体系」与「概念模式需 concept_ids 含概念」——纯函数只保证结构非空。
//    空引用 Err「应用记录必须至少一个引用」。
// golden（≥6）：decision{concept_ids:[3],group_id:2}→Ok / decision{}→Err / decision{model_ids:[7]}→Ok /
//  decision{group_id:2}→Ok / decision[1,2]（数组）→Err / decision{node_ids:[-1]}→Err /
//  application{concept_ids:[]}→Err / application{concept_ids:[5],card_id:9}→Ok / application{group_id:2}→Ok（体系模式证据引用） / decision{unknown:1}→Err
```

**明确不做**：`application_updates_stale` 判断函数——`concept_stale`（v0.13.1 已备）已用 `last_applied_at`（90/180 天）判定失效；本版应用记录只是**写入**该数据源，不新增任何"是否过期/需更新"纯函数。

## 四、系统层：Tauri commands（commands_knowledge_decisions.rs）

入参校验统一（复用 `commands_knowledge.rs` 的 `require_id`/`normalize_text`/`parse_target_type`）：id>0；`content` 非空且 ≤2000（`normalize_text`）；used_refs 经 `validate_decision_input` 后**再做实体/证据存在性校验**（`get_knowledge_concept`/`get_knowledge_node`/`get_knowledge_model`/`get_group`/`get_note`/`get_card`/`get_fragment`——引用 id 不存在→报错）；四行可选字段经 `opt_trim`/`opt_field` 风格清洗。

| 命令 | 参数要点 | 返回值 |
|---|---|---|
| `log_decision` | system_id, question_id?, content, expectation?, actual?, reflection?, used_refs | 决策记录（kind=decision 硬置） |
| `log_application` | concept_id?, system_id?, content, expectation?, actual?, reflection?, used_refs | 应用记录（kind=application；见下挂载规则） |
| `list_decisions` | system_id?, kind?, limit? | 决策+应用列表（合并，前端分 tab） |
| `get_decision` | id | 单条记录 |
| `delete_decision` | id | 幂等删除（用户记账允许删；>0 返回 bool） |

**log_decision**：校验体系存在；used_refs 引用（实体或证据）存在→`decision_logged` metric（`add_metric_event`）。used_refs 空→拒绝。

**log_application 挂载规则（决策 R-A，写明错误语义）**：
- `concept_id` 与 `system_id` **至少提供其一**，否则 Err「应用记录必须挂概念或体系」。
- **概念模式（concept_id 提供）**：`system_id` 若同时传且与概念的体系不一致→Err「应用概念不属于该体系」；used_refs 至少含 `concept_ids=[concept_id]`（引用必填）；**事务**：插 application 行 → `set_concept_applied(concept_id, now)` → `application_logged` metric。
- **体系模式（仅 system_id 提供）**：used_refs 必须含 ≥1 证据引用（group/card/note/fragment），否则空→拒绝；插 application 行（system_id 落库）→ `application_logged` metric；**不更新任何概念 last_applied_at**（体系级应用，应用率按体系聚合）。
- **不做**：无 concept 也无证据的系统级空引用；禁止 `concept_id` 与 `system_id` 均缺省落"空应用"。

**校验用例清单**（command 层）：content 空/超长拒绝；used_refs 空拒绝；decision 引用不存在实体/证据→报错；application 概念不存在→报错；application 无 concept 也无 system→拒绝；list_decisions 非法 kind/limit≤0→报错；delete 幂等（不存在 id 返回 false 不报错）。

## 五、UI 层

- **入口裁决（决策 D1）**：**本版只实现概念页"记一次使用"＋决策日志（概念详情面板，默认开）**；**组/复习面入口本版不做**（不做需手动开启的 feature flag——开关本身是隐藏复杂度，且组/复习面做入口需额外"选概念"步骤，违背记账负担防线；§九.1 倾向"概念页默认＋复习面默认关"，本版收敛为只做概念页）。复习面专注记忆编码，插入应用表单即打断——零打扰优先。
- **概念详情面板扩展**（`KnowledgeDetailPanel.tsx`，选中的 `selection.type==="concept"`）：
  - 「📝 记一次使用」按钮 → 打开四行表单（默认带入当前概念 `concept_ids=[id]`，证据引用可选）。
  - 「决策日志」区：`list_decisions(concept 关联)` 渲染；**决策 / 应用分 tab**（徽标计数）。
- **四行表单**（`KnowledgeDecisionForm`，复用 `KnowledgePage` 场景，占位=指南附录C 语义，**不预填内容**——预填＝假燃料）：
  - content（决策内容/应用动作，*必填*）· expectation（预期结果）· actual（实际结果）· reflection（反思：如果重来改变什么）
  - used_refs 引用选择器（体系实体：节点/概念/模型；证据：组/笔记/闪卡/碎片，mock 型下拉）——必填，空提交拦截。
- 决策/应用徽标：决策=「🧭」＝思辨面；应用=「🛠」＝学习面；反思字段允许负面（失败真实记录，不设质量评分）。
- 前端文件：`types/knowledge.ts` 增 `KnowledgeDecision`/`UsedRefs`/`DecisionKind`；`components/KnowledgeDecisionForm.tsx`；`components/KnowledgeDecisionLog.tsx`。

## 八、验收（真机走查，REQ-146 批内）

1. 概念页选中概念 →「记一次使用」→ 填四行＋选概念/证据引用 → 保存 → 应用记录出现 + 该概念 `last_applied_at` 更新（详情刷新可见）。
2. `list_decisions` 决策/应用分 tab 呈现；kind 徽标正确（🧭/🛠）。
3. 决策记录：`log_decision` 引用不存在实体→明确报错；空引用→拒绝（无膨胀记录）。
4. 空 used_refs / 无概念仅体系的应用 → 按 §四 规则拒绝或落体系级；不崩。
5. 回归：notes/组/闪卡/复习面全链路不变（零破坏）；概念三问编辑与引用（v0.13.1）不回归。
