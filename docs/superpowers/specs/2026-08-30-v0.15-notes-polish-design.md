## 1. 背景与目标（痛点 → 根因）

v0.14（编辑器 CM6 / 视觉系统 / 知识体系 / 采集质量）交付后，用户实测反馈 6 项：

| # | 反馈 | 现状根因（代码定位） |
|---|------|---------------------|
| 1 | 加 H1 后再点按钮"无取消" | `headingCommand.ts:50` 与 `markdownEdit.ts:82` 对已是标题的行**跳过**（纯 no-op）；按钮有光标行级别高亮态（`RichEditorView.tsx:167`）暗示可切换但点了没反应 |
| 2 | 组件大小不能自适应 | 全站固定宽列硬编码：笔记页 240/320/180（`GroupSidebar.tsx:270`、`NoteListView.tsx:100`、`NoteReadingView.tsx:93`）、会话页 320（`SessionListPanel.tsx:299`）、知识页 260/320（`KnowledgePage.tsx:220`、`KnowledgeDetailPanel.tsx:132`）、课堂页 320（`ClassroomPage.tsx:376`）；默认窗口仅 960×720（`tauri.conf.json`）——正文区被挤压；`NoteImage.tsx:86` 固定 240×160 CSS 缩略（原 TODO(v0.12.0)） |
| 3 | 笔记组、笔记不可收起 | 组侧栏已按 kind 分区折叠（`GroupSidebar.tsx:375`，记忆 localStorage）；但中部列表平铺（v0.12.2 决策 1：组行只过滤不展开），组/列表整列无折叠 |
| 4 | 用户插入的图片需复制一份 | 🖼 文件选择已复制（`import_note_image`，`commands_note_images.rs:79` ✅）；但 🌐 链接图只存外链 URL（源站删除即失效）、剪贴板粘贴（待 #5）未落盘、手写/粘贴的绝对路径引用既不显示（`resolve_note_image_path` 只认 4 种前缀）也无副本 |

**目标**：编辑与阅读所见一致；图片资源零丢失；笔记页与全站布局随窗口自适应；笔记组/笔记可收起。

## 2. 方案选型记录（逐条裁决）

### 2.1 H1 切换语义（#1）

| 方案 | 结论 |
|---|---|
| **A. set-or-toggle 切换语义（采纳）** | 逐行：行已精确等于所点级别 → 剥掉 `#×level+空格` 还原普通段；其他情况 → 置为该级别。多行选区逐行独立判定。CM 与 textarea 双路径同步修改，配套单测改造 |
| B. 保留跳过 + 独立"清除格式"按钮 | 按钮更多，发现成本高，否决 |
| C. 仅保留升/降级（Ctrl+Shift+↑↓） | 与用户"点 H1 取消 H1"预期不符，否决 |

边界：纯空白行保持现有行为（加标记——不具有"取消"语义）；光标落位逻辑不变（末行标记后）。

### 2.2 全站自适应（#2）——用户裁决：**全部页面**

统一策略：**所有固定宽列改为"可拖拽 + 宽度记忆 + 最小/最大约束 + 窄窗自动折叠"**；组件内部自适应（工具栏换行、表格横向滚动已有；图片改为自适应尺寸）。

### 2.3 收起（#3）——用户裁决：**分组树 + 整列折叠**

中部列表改分组树（组头可收起，记忆）；左栏/中栏/右栏大纲全部支持整列折叠（窄条形态）；组头"点击名字=过滤"的 v0.12.2 决策 1 **保持不变**（chevron 才有折叠动作）。

### 2.4 图片落盘（#4）——用户裁决：**每个入口保证复制；不做巡检**

- 🖼 本地文件：已有（`import_note_image`），保持
- 剪贴板粘贴（与 #5 同条线）：落盘
- 🌐 链接图：**自动下载复制**（推荐，用户确认）；失败降级插原 URL + 提示
- 手写/粘贴绝对路径引用：**不做巡检/不改写**——登记为已知边界（用户裁决：入口全落盘后巡检不再必要；将来若观察到高频粘贴本地路径 Markdown，再在 paste 钩子转换）
- 删除笔记：顺带清理 `notes-images/{nid}/` 目录（防孤立残留，用户确认；失败不阻断删除）

### 2.5 剪贴板导入（#5）

CM 侧 `EditorView.domEventHandlers.paste` 读 `event.clipboardData`（同步、无权限弹窗）；textarea 降级路径 `onPaste` 同款（共享 util）。后端新增 `import_note_image_b64`（base64 IPC，同 `capture_fragment` 先例）。

### 2.6 换行一致（#6）——用户裁决：**单换行=硬换行渲染 `<br>`**

阅读渲染启用 remark-breaks；零源数据变更（存量内容自动修复）；两空格/`\` 强断行语义保留；不加设置项（YAGNI，将来需要再提）。

## 4. 详细设计

### 4.1 标题切换（#1）

**纯逻辑**（`computeHeadingChanges` / `headingLines` 同步改，规则一致）：

```
对每行：
  m = 行首 /^#{1,6}\s/ 匹配
  行已等于目标级别（m[0].len === level）→ 变更：删 [行首, 行首+level+1)（剥 `#×level+空格`）
  其他（其他级别标题或普通段）→ 变更：行首插 `#×level+空格`
     —— 其他级别标题先剥后置（先删原标记再插新标记），净效果=替换
```

- 多行选区逐行独立判定；光标落末行标记后（不变）
- `headingCommand` 的 `changes.length === 0` 卫兵保留（全行均无变化时无空 transaction）
- **测试改造**：`headingCommand.test.ts` 原"已是标题的行跳过不叠加"用例改为"同级别行剥除标记/不同级别行置为该级别"；`headingLines` 对应用例同步；补 H1→普通段、H2 行点 H1、普通行点 H1 三类 golden
- 高亮闭环：toggle 后光标行级别变化 → `onHeadingLevelChange` 更新 → 按钮高亮同步消失

### 4.2 全站自适应（#2）

**布局装备**（三件套，全站复用）：

1. `useColumnWidth(key, { default, min, max })`：state（像素）+ `useEffect` 持久化 `layout:col-width:{key}`；暴露 `width/setWidth/reset`
2. `ColumnResizer`：4px 宽手柄，`onPointerDown` → `setPointerCapture` + 移动回调（方向感知：左列拖右边界 → width 增；右列拖左边界 → 负向）；拖拽中 `user-select: none`；最小/最大夹取；双击 = 恢复默认
3. 窄窗自动折叠：页面根容器 `ResizeObserver` + 阈值阶梯（<1100 大纲折叠；<860 组侧栏折叠；<700 中列折叠）；**用户手动态优先**——窗口回宽后恢复用户手动折叠/展开选择；折叠/展开态持久化 `layout:col-fold:{key}`

**列迁移清单**（默认宽度=现状值，逐列登记）：

| 列 | 当前 | min | max |
|---|---|---|---|
| GroupSidebar | 240 | 180 | 320 |
| NoteListView / FeedFragmentList | 320 | 240 | 420 |
| 大纲 | 180 | 140 | 260 |
| SessionListPanel | 320 | 240 | 420 |
| Knowledge 左 | 260 | 200 | 360 |
| KnowledgeDetailPanel | 320 | 260 | 420 |
| Classroom 右 | 320 | 240 | 420 |

**折叠形态**：窄条 26px（图标容器，title 提示），点击展开；展开态恢复记忆宽度。折叠/窄条组件 `ColumnBar`（≤80 行，随 ColumnResizer 同文件 or 同包）。

**组件内自适应**：
- `NoteImage`：`width: "auto", maxWidth: "100%", maxHeight: "60vh"`（原始比例，窄窗不溢出；点击放大保持不变）
- 工具栏：现有 `flexWrap` 保留；窗口过窄时提示语（"Ctrl+Shift+↑↓层级…"）允许省略（`display: none` via 容器查询或保留——低优先）

**编排**：`NotesPage` 持有 3 列状态（侧栏/列表/大纲）+ 折叠态，传给受控子组件；`SessionsPage`/`KnowledgePage`/`ClassroomPage` 各自接入同款（每页 1-2 列，工作量机械）。

### 4.3 分组树 + 整列折叠（#3）

**分组树（NoteListView 版）**：

- props 增 `groups: NoteGroup[]`（NotesPage 已有 `groups` state，直接复用）
- 渲染结构：`[📁 未分组]`（`group_id == null`，可折叠）→ 各组按 `GroupSidebar` 同款 kind 排序？**否**——保持 `list_notes`/`search_notes` 返回顺序，仅分组挂载，组顺序=组 id 升序（稳定）；组头渲染：chevron（`▸/▾`）+ 组色条（`resolveNoteColor` 已贯通）+ 组名 + `N` 计数
- **交互契约**（v0.12.2 决策 1 保持）：组头**名字区点击 = 过滤切换**（`groupFilter` toggle）；chevron `stopPropagation` 仅折叠/展开；折叠态持久化 `notes:group-fold:{gid}`（未分组区 `notes:group-fold:none`）
- **退化规则**：`keyword`/`tagFilter` 激活或 `sortMode != "updated-desc"` 时 → 平铺（树上下文搜索无意义）；恢复条件清除后还原树
- **批量勾选**：树态下"全选"作用于当前可见集合（与现有"只删可见子集"安全边界一致，`NoteListView.tsx:85` 逻辑保持）
- 空组：**不渲染组头**（无笔记的组不进树；组信息在 GroupSidebar 管理）——避免空头占位噪音
- 组件拆分：`NoteTreeSection`（组头 + 子树容器），NoteListView 保持 ≤300 行

**整列折叠**：

- GroupSidebar / NoteListView / 大纲：`NotesPage` 列状态统一驱动；折叠 = 窄条 26px + 图标（📁/📝/📑）+ 展开
- 大纲列：**移除** `NoteReadingView` 内的独立 `outlineCollapsed` 悬浮按钮体系（`NoteReadingView.tsx:48,92-147`），并入统一列折叠（行为等价：✕ 收起 → 窄条；窄条点击展开）
- 与 4.2 窄窗自动折叠共用同一套 `layout:col-fold:{key}` 状态与 `ColumnBar` 组件

### 4.4 图片落盘三入口 + 清理（#4）

**4.4.1 后端核心提取**（`commands_note_images.rs`）：

```
save_image_bytes(data_dir, note_id, bytes, ext_hint) -> Result<String, String>
  ① 字节数 ≤ IMAGE_MAX_BYTES（10MB）
  ② image::guess_format + ImageReader 解码验证（坏图拒绝；不信任 MIME/扩展名）
  ③ 落盘 notes-images/{nid}/{ts}.{ext}（唯一名冲突 _1/_2 复用现有逻辑）
  ④ 返回 "notes-images/{nid}/{name}"
import_image_file 改为委托（fs 复制→读字节→save_image_bytes）
```

**4.4.2 新命令 `import_note_image_b64(note_id, image_b64)`**：
- base64 解码 → `save_image_bytes`（ext 以解码格式为准）
- 校验：note 存在、`image_b64` 非空、解码后 ≤10MB
- 传输：base64 字符串（10MB 图 ≈ 13MB JSON——与 `capture_fragment` 同款先例）

**4.4.3 新命令 `import_note_image_url(note_id, url)`**：
- 校验 URL → http/https；`ureq` GET（timeout 10s、跟随重定向 ≤3、限流 10MB）
- Content-Type 白名单（image/*）或按 `image::guess_format` 兜底
- `save_image_bytes` 落盘 → 返回相对引用
- 失败 → `Err`（前端降级：插原 URL + status 提示"外链图下载失败，原链接已插入"）

**4.4.4 前端接线**：
- 🌐 链接图：`prompt` 后先 invoke `import_note_image_url`，成功插相对引用；失败降级插原 URL（status 提示）
- 剪贴板（4.4.5/4.5）：粘贴 → `import_note_image_b64`
- 工具栏文案：`🖼 图片`（本地）"/ 🌐 链接图（下载为本地）"

**4.4.5 删除清理**：`delete_note` 命令/Rust 层在 DB 删除成功后 `remove_dir_all(data_dir/notes-images/{id}/)`，失败 eprintln 不阻断（残留无害、无用户可见错误）

**已知边界（登记）**：正文中手写/粘贴的绝对路径/`data:` 引用不改写、不吸收（用户裁决：入口全落盘后巡检不需要；观察将来频度再议）。

### 4.5 剪贴板导入图片（#5）

- `useClipboardImagePaste`（纯提取，两个编辑器共用）：
  ```
  extractClipboardImage(e: ClipboardEvent | React.ClipboardEvent) -> { blob, mime } | null
  规则：items 中首个 image/* → blob；多图取第一张；超 10MB 前置拦截（status 提示）
  ```
- **CM 侧**：extensions 增 `EditorView.domEventHandlers`：
  ```
  "paste" (e)：
    图 = extractClipboardImage(e)
    无图 → return false（默认文本粘贴）
    有图 → e.preventDefault() → blobToBase64（提取自 GroupSidebar，移入 utils）→
           invoke import_note_image_b64 → 成功：dispatch insert `![图片](rel)\n`（userEvent input.paste）
           失败：status 提示（文本粘贴不补救——下一帧用户可 Ctrl+V；诚实降级）
  ```
- **textarea 侧**：`onPaste` 同款（复用同一 extract + import 函数；插入用 `applyEdit(insertAtCursor(...))`）
- 落盘后 CM decoration 插件自动重算 → 图片即时内联显示
- 权限：`event.clipboardData` 同步读取，WebView2 paste 手势下无需 `navigator.clipboard` 权限弹窗

### 4.6 换行一致（#6）

- `app/package.json` + `remark-breaks@^4`
- `NoteMarkdown.tsx`：`remarkPlugins` 增 `remarkBreaks`（置于 remarkGfm/remarkMath/remarkMarkHighlight 之后）
- 语义：单 `\n` 段落内 → `<br>`；`\` 断行与两空格断行保持；列表/引用内续行同样断行（符合直觉）
- **存量影响**：既有笔记中的软换行从"空格"变"换行"——正是本次修复目标；**全量 vitest 走查**：`NoteReadingView.test.tsx`/`NotesPage.test.tsx`/`NoteMarkdown` 相关断言若有文本拼接断言需同步
- 不加设置项（用户确认直接生效）

## 5. 验收标准

1. **H1**：光标在 `# 标题` 行点 H1 → 变普通段，按钮高亮消失；H2 行点 H1 → `#` 级；多行选区混合级别逐行正确；textarea 降级路径行为一致
2. **自适应**：各页列可拖拽、记忆重启后保持；窗口缩到阈值链 → 大纲/侧栏/列表自动折叠，回宽恢复；图片窄窗不溢出
3. **收起**：分组树组头收起/展开 + 记忆；组头点击=过滤不变；三列均可靠窄条折叠/展开
4. **图片**：剪贴板粘贴图、链接图、文件选择图全部落盘 `notes-images/{nid}/`；删源文件图不丢；删笔记清空其图片目录；坏图/超限/下载失败有提示不脏内容
5. **换行**：编辑态单换行 → 阅读态 `<br>`；强断行（`\`、两空格）不回归
6. 非功能：`cargo test`、vitest、`tsc --noEmit`、`vite build` 全绿；新增文件带 `@ai-context`；单文件 ≤300 行（超限登记豁免）

- 图片垃圾回收（孤儿图清理仅限删除笔记时；历史孤儿后续单独任务）
- 设置项：硬换行开关、列宽主题化
- 服务端/移动端；无障碍深度打磨
