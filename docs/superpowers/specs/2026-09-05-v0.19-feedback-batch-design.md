## 1. 总则：AI 增强一律可选（本批所有 AI 能力的公共条款）

本地优先铁律在 AI 增强上的可操作化，每条 AI 能力必须同时满足：

1. **独立开关且默认关**：不得捆绑在"AI 功能开关"或授权里隐形开启；每条新能力新增独立设置位（AiSettings JSON 增量字段 + read-modify-write 最小面 setter，仿 `ai_set_goal_plan`/`ai_set_vision_refine`）。
2. **建议制**：AI 产出永远是可丢弃建议（落地提示、采纳/忽略），不自动写库、不自动改用户数据。
3. **离线/降级完整**：关闭或失败时本地规则路径完整可用（如标题=来源名/首句；缺口清单=纯规则现算）。
4. **审计与成本**：新增 AI 调用走 ai_tasks 任务化（op_type 扩展白名单）+ 审计 + 预算硬顶复用。
5. **语音/图像不出本机**红线延续；纯文本上云仅在有 AI 授权前提下。

## 2. 修复规格

### 2.1 焦点问题 → 画面停更检测与捕获会话自愈（#1）

**背景证据**：Rust 捕获链无按焦点暂停逻辑（已全仓核查）；三级后端 WGC→DXGI→GDI（ADR-022）；`WindowLost` 仅 `GetWindowRect` 失败触发；ScreenStats 已有 `no_change/capture_err` 计数但未外露。用户复现=Win11/抖音桌面客户端/双屏；冻结时视频肉眼在动 → **我方捕获会话静默失效**（WGC 会话失活但未被重建的高嫌疑）。

**修复 = 三件套（可独立交付，先 ① 后 ②③）**：

1. **帧心跳观测**（先落地，真机复现确认后进 ②）：
   - 采集期间 Rust 每 2s emit `live:frame-heartbeat`：`{backend, gotNewFrame, noChangeCount, captureErrCount, targetVisible, targetIconic, wgcSessionMs, lastError}`；
   - 前端课堂页在开发/诊断态显示（或仅日志）；一次复现即可区分"无新帧 vs 帧全错/错误累积"。
2. **WGC 静默自愈 watchdog**（纯状态机可单测）：
   - 条件：backend=Wgc 且目标窗口 visible 且非 iconic 且**无新帧持续 > WGC_STALL_MS(5s)** → 重建 WGC 会话（`WgcState::create(hwnd)` 重试）；
   - 节流：重建失败后按 30s 周期重试（沿用 DXGI_RECREATE_INTERVAL 既有节奏）；连续失败升级为 ② 的停更提示；
   - 边界：DXGI/GDI 路径"桌面无变化=Ok(None)"属正常分支**不触发**重建（与 WGC 语义区分开）。
3. **停更提示与末帧保留**：
   - 末帧保留现状已有（latest_frame 共享缓存）——冻结期不黑屏；
   - 新增 `live:frame-stalled` 轻提示横幅（区别于真窗口丢失的 window-lost）：文案"画面源已 Ns 无新帧（可能播放器暂停渲染）——检测到恢复自动消失"；帧恢复自动清除。

**文件**：`live_frame_process.rs`（心跳统计/上报）· `live_session_loop.rs`（watchdog 调度）· `dxgi_capture.rs`/`wgc_capture.rs`（backend_name/重建接口已有）· `types/live.ts` · `ClassroomPage.tsx`（横幅）· 新纯函数模块 `frame_watchdog.rs`（状态机+单测）。
**验收**：单测=watchdog 判定矩阵（静默超时/可见性变化/错误累积/正常无变化不重建）；真机=双屏复现前后对比，恢复时间 ≤ 5s+重建耗时。

### 2.2 会话标题内容化（#2）

**A 层（零 AI，先交付，直接修"两条都叫抖音"）**

1. 来源名净化 + 同源去重：创建会话时若归一化标题（去平台尾缀白名单，如 " - 抖音"/"- Douyin"）与近 90 天既有会话相同 → 追加序号「抖音 #2」；纯函数 `dedupe_session_title`（查询入参=现同名集合）+ 单测。
2. 首句自动升级：会话结束融合完成时，若 `title_kind=source`（未被人工改）且首个稳定转写段可用（长度 8–40 字、过 UI 垃圾过滤、非开场杂句）→ 截断升级标题；纯函数 `first_line_title(segments, ui_junk)` + golden 单测（含纯音乐无文本=不升级）。
3. 改名入口补齐：会话详情头部标题行内改名（Enter 保存/Esc 取消，复用 GroupSidebarRow 重命名模式）+ `update_session_title` 命令 + `data:sessions-changed` 广播；改名即 `title_kind=manual`（此后 A/B 自动升级均不覆写）。
4. DB：`sessions.title_kind TEXT NOT NULL DEFAULT 'source'`（幂等加列迁移，零表重建）。

**B 层（AI 建议标题，默认关）**

- 开关：`AiSettings.titleSuggestEnabled`（默认 false）+ `ai_set_title_suggest`；前置=AI 已开启且已授权（content_gate 双闸门沿用）。
- 时机（默认案）：会话结束融合完成即触发轻任务（op_type `title_suggest`，输入=前 3000 字清洗转写，预算 ≤1K token，输出 JSON `{"title": "≤20字"}`，解析失败=无建议静默）；**精修采纳后刷新**：若该会话随后有笔记被 AI 精修采纳（data:notes-changed 钩子 + 会话→笔记关联反查）且建议未曾被采纳 → 基于精修稿首段再生成一次替换旧建议（质量更高，不重复整篇上云）。本刷新为第 2 步实现（同批或紧随）。
- UI：会话列表/详情卡显示「💡 AI 标题建议：xxx [采纳] [忽略]」；采纳→改名(title_kind=ai)；忽略→该会话不再提示。
- 失败/离线：无建议、无调用、零阻断（A 层照常）。

**文件**：Rust `commands_session.rs`（改名/去重/升级钩子）· `db_sessions.rs`/迁移 · `title_rules.rs` 新纯函数 · `ai_refine_task`/`ai_tasks` op 白名单扩展 · prompts/`title_suggest.json` · FE `SessionListPanel`/`SessionDetailPanel` 徽标与改名 · `types/ai.ts`。
**验收**：A 层 golden 单测（抖音双会话/文件名导入/人工改名不被覆写）；B 层任务化协议单测 + mock 模式端到端（采纳/忽略两路径）。

### 2.4 列拖拽"加速"修复（#4）

- 根因：`ColumnResizer.onPointerMove` 传**距起点累计位移**（`clientX - startXRef`），`useColumnLayout.resizeBy` 为**增量语义**（`cur + delta`）→ 每次 move 重复累加全程 → "加速"。影响全站（笔记/会话/课堂/知识四页共用）。
- 修复：`ColumnResizer` 增加 `lastXRef`，move 传相邻增量 `dx = clientX - lastX`（side 符号逻辑不变）；结构不动。
- **测试**：新 ColumnResizer 单测——pointer 序列（50→70→80）断言 onResize 回调增量为 [20,10]（非累计）；双击 reset 不变；useColumnLayout 既有测试保留。
- 验收：四页各拖一次，宽度严格跟手、无回弹。

### 2.6 笔记列表交互重构（#6，最大项）

**交互矩阵（已裁决基线 + 本批补全）**

| 起点/动作 | 行为 | 备注 |
|---|---|---|
| 行身单击 | 选中 + 右栏读（现状保留，Outlook 式） | 三栏架构下"单击选中"天然兼"预览读" |
| Ctrl+单击 / Shift+单击 | 加选/区间选，**不换右栏** | 桌面标准主通道 |
| 行身按住拖动（位移 >6px 激活，即时无延迟） | 拖拽：单行或整组多选行 | 替代用户所述"长按拖拽"（澄清=按住即拖） |
| 行首 4px 色条区 | 同为拖拽手柄语义 | 防未来图文混排时与划词冲突的保留锚点 |
| 组标题空白/行间空隙/空列表区按住拖动 | **划过加选**（marquee：半透明选区框反馈） | 行内不做划选；命中率不足则回退 Shift 为主（诚实边界，代码保留） |
| 拖到左侧组行 / 中部组标题 | 跨组移动（drop target 双处） | 中部组标题落点=新入口（现仅左侧组行） |
| 拖到同组行上/下沿 | 组内位置移动 | 该组须为手动排序；自动排序组首次拖=提示后自动切换并快照当前序 |
| 拖到自动排序组内行 | 禁入反馈（not-allowed） | Notion 排序锁定同款 |
| 右键在选集内行 | 菜单作用于整个选集（移动到组/删除 N 项/固定） | Outlook 同款 |
| 右键在选集外行 | 先单选该行再出单项菜单 | 现状保留 |
| Esc / 点击空白 | 清空选择 | — |
| 搜索/标签/排序(非手动)平铺态 | 禁拖拽排序（锁定），跨组拖仍可用 | — |
| 列表头「批量选择」按钮 | 勾选模式：单击行=勾选，批量栏浮现，Esc/完成退出 | 触屏/精确兜底，Gmail/Notion 同款 |

**实现要点**：

1. 行内 checkbox 移除（NoteListRow）；选中视觉=行背景 + 左色条实心；多选集状态从 NoteListView 上提为列表级受控 state（仍留在 NoteListView 内，NotesPage 不感知，批量动作经回调上抛——沿用现有 onBatchDelete 模式）。
2. 批量操作栏扩为**删除 + 移动到组**（新 BatchActionBar；移动组复用组选择小弹层，归组命令循环调 `move_note_to_group` 幂等语义；只删可见子集守卫沿用 v0.12.8 审查口径）。
3. **手动排序模型（DB）**：`note_groups.order_mode TEXT NOT NULL DEFAULT 'auto'`（'auto'|'manual'）+ `notes.order_index INTEGER NULL`（同组内排序键，未分组区用伪组键处理）；命令：`enable_group_manual_order(group_id)`（快照当前排序为初始 order_index，事务内）、`disable_group_manual_order`（置 auto + 清 order_index）、`move_note_position(group_id, note_id, before_note_id)`（纯函数步进+单测）；`list_notes` 排序扩展：manual 组按 order_index 排（SQL 联合或 Rust 分组后归并，选实现成本低者）。收件箱碎片列表不涉及。
4. 拖拽实现：**保留既有 HTML5 DnD 行→左侧组行**（已上线可用），新增目标=组标题 drop + 同组行间落点指示线 + dragOver 高亮；组内行间落点解析为 move_note_position。WebView2 HTML5 DnD 已知不稳的迁移（pointer events 自实现）登记为**观察项**（真机若拖拽异常再立项迁移，不本批扩面）。
5. 划过加选：容器空白指针起点（组标题/空隙/空区）→ 自实现轻量 marquee（~100 行，矩形与行 rect 相交判定 + 视觉框），无新依赖；与拖拽起点互斥由"起点是否在行 DOM 内"决定。

**文件**：`NoteListView.tsx`（选择模型重构）· `NoteListRow.tsx`（去 checkbox/视觉/拖拽源）· `NoteTreeSection.tsx`（组头 drop target）· 新 `BatchActionBar.tsx` / `selectionMarquee.ts` / `dropPosition.ts`(纯函数) · `GroupSidebar.tsx`（drop 保持）· Rust `commands.rs`/`note_filter.rs` 排序扩展 + 迁移 · 测试（选择模型矩阵/落点解析/划选相交/move_note_position 步进 golden）。
**验收**：真机手势矩阵逐行过（两屏拖拽/Shift 区间/划选/批量栏）；重点回归=引用跳转 focusNoteId 滚动（行 id 不变）、右键菜单既有用例。

### 2.7 体系生长：D1 证据反推 + D2 节点缺口（#7）

**D1 证据反推生长（建议制）**：

- 命令 `kb_evidence_clusters(systemScope)`：候选=未挂接体系的问题树证据源（笔记/碎片，排除已链接知识_links 命中者，session 转写内容作为 note 已入链不算）→ 本地 embedding 聚类（复用 kb 引擎；引擎未就绪=诚实提示需先启用语义引擎/降级关键词共现簇并标注"近似"）→ 输出建议簇：代表标题列表 + 共同关键词 + **拟新问题表述（规则拼装，非生成）** + 现有体系内最相似节点（查重提示，防重复建）；
- UI：体系页全局区「🌱 生长建议」卡片列表：每条=「这 6 条证据似乎都在说同一件事」+ 候选问题文案可改 + [基于此新建问题] [忽略]；确认后走既有节点创建命令（证据随后由用户按现有挂接通道手动挂，**不自动挂**——AI 只建议不生成红线）；
- 依据证据=体系生长的唯一真实来源（哲学原则 1），解决冷启动与"树不生长"。

**D2 节点缺口仪表**：

- 命令 `system_node_gaps(system_id)`：每节点现算——证据数（note/card/fragment 引用计数分型）、最近引用时间、90/180 天 stale 状态（复用 concept_stale 判据理念）、概念"三问未填"标记、模型"无应用记录"；纯只读聚合零双写；
- UI：节点详情新增「缺口」卡：缺口清单（如"有概念无证据：0 条引用 / 90 天未用"）+ 每缺口旁 [加入目标]：目标选择小弹层（复用目标列表）→ 调既有里程碑新增命令落草稿（目标侧人工审批流程不变，不直写里程碑状态）；
- 产出同时是执行型 agent（另文档 P0）的每日输入源。

**文件**：Rust `kb_evidence.rs`/`system_gaps.rs`（纯函数+聚合）· `commands_kb.rs` 扩展 · FE `KnowledgePage.tsx`/`KnowledgeDetailPanel.tsx` 卡片 · prompts 不需要（零生成，规则拼装）。
**验收**：聚类/查重/缺口聚合 golden 单测（fixtures 用本地样例）；真机=真实笔记库跑通一次"建议→建节点→手动挂证据"。

### 2.8 AI 精修加速：①片内流式 + ②输出预算化（#9）

**现状证据**：精修=切片并发（≤8000 字/片、CONCURRENCY=3、每片独立**非流式**请求、SLICE_RETRY=1）；单请求 max_tokens 上限 20000；DeepSeek 长输出实测 ~110s@20k token（ai_client 注释实证）；前端已有 `ai:refine-stream` 帧协议与 useRefineStream。直连无中转。

**① 片内流式**：

- 后端：refine adapter 请求改 `stream:true`（SSE 解析复用 `ai_chat.rs::parse_sse_line`）；帧协议扩展 `RefineStreamFrame::Delta { sliceIndex, text }`（增量随到随推）；
- **顺序呈现规则**（并发执行、顺序展示）：每片文本按其 sliceIndex 归槽；展示层只渲染"连续前缀 + 当前正在流式的片"——片 1 从 ~2s 起打字机式增长（体感核心），片 2/3 后台并行；某片完成后接续展示下一片（若其已流完则直接整片落位）；最终 diff/采纳仍走整片 validate 后的规范结果（流式仅为呈现，validate/审计语义不变，原料不可变红线不破）；
- 前端：`useRefineStream` 扩展 Delta 槽模型；RefineWorkbench 预览区增量渲染（文本追加，节流帧渲染参照 REQ-275 既有帧级批量渲染）；
- mock 路径同步支持流式帧（mock 可配分片吐字延迟）。

**② 输出预算化**：

- prompts/note_refine.json v3（或新 strategy meta 段）为每档位声明 `output_budget_chars`（L1 轻改写档最小……L4 极简最小；自定义档=默认档值）；系统提示词尾附"输出控制在 X 字内，删冗余不改事实"；
- 单请求 `max_tokens` 由 20000 收敛为 `clamp(档位预算换算, 8k, 20k)`——防止模型空转长尾，直接省生成时长；
- 既有 L3"表达改写但事实红线不动"等约束不受影响。

**埋点（REQ-275 基线收尾）**：每片记录 t0/首 delta 时刻/结束时刻 → 任务轨迹（trajectory_json 增字段或新 eprintln 汇总行）；`ai_tasks.elapsed_ms` 既有；设置/开发日志可读。**先埋点后调参**——①上线前后各取 3 条真实会话做 A/B 记录（真机验收待办）。

**文件**：`ai_refine_task.rs`（adapter 流式调用/帧）· `ai_chat.rs`/`ai_chat_stream.rs`（SSE 复用）· `commands_ai_refine.rs`/prompt 资产 · `types/live.ts`/`useRefineStream.ts`/RefineWorkbench · 测试（SSE 行解析复用既有、帧序模型纯函数、预算 clamp）。
**验收**：单测=流式帧归槽模型（乱序到达/前缀规则）；真机=3 条会话 A/B（首 token 时间、总耗时、字数、成本）。

## 2.9 交互矩阵完整性补齐（2026-09-05 用户追加：逐交互面审计）

审计维度：输入设备（鼠标/键盘）/ 状态覆盖（空·加载·错误·忙碌·部分成功）/ 冲突对 / 退出与撤销 / 键盘可达性 / 可发现性。第 6 项矩阵见 §2.6；本节补齐其余各面。

**通用约定**：Esc=先退最内层（输入/浮层）再退多选；toast 撤销窗口 3s；AI 建议类徽标一律带"依据来源"悬停说明（转写片段/精修稿）；按钮/控件保持原生键盘可达。

|---|---|
| 会话标题改名（2.2A） | 详情头 ✎ → 行内输入（Enter 保存/Esc 取消，失焦保存同 GroupSidebarRow 先例）；**行单击=打开详情，不做行内改名**（零冲突）；改名→kind=manual 永久停止自动覆写；空标题拒绝保存（提示沿用原标题） |

## 5. 红线与公共约束

- 原料层（session_segments 原文）永不可变；精修流式仅呈现增强，validate/审计/采纳语义零变化；
- AI 建议永不自动落库（§1 总则）；标题/体系建议/任务建议三处同守；
- 语音/图像不出本机；纯文本上云需既有 AI 授权；
- 模型文件不入库；无新第三方运行时依赖（划选/搜索选择器均自实现零依赖）；
- SQLite 迁移全部幂等加列；不重建表。
