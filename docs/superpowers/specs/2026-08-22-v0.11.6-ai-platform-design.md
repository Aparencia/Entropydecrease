# v0.11.6 设计：AI 平台化——Provider 抽象 + 能力声明化 + 产出策略定制

> 状态：已批准（用户确认方案 B，2026-08-22）
> 依据：市场调研（Notion AI 官方博客 / Braintrust×Notion / Obsidian Copilot / Granola / ZenML LLMOps，调研缓存见 `.firecrawl/`）·
> 旧项目参照（`Entropydecrease-old/server/ai-gateway`：providers/fallback/circuit_breaker/key_pool + 40+ chains + license 充值闭环）·
> 痛点：设置页 AiServicePanel 六类功能混杂、品牌写死 SiliconFlow、第三方余额卡片、单 Provider 直连无降级
> 范围：v0.11.6（M1 Provider 层 → M2 策略层 → M3 能力层收尾）
> 前置决策：充值系统远期（本设计只留桩，不实现支付/配额）

## 一、总架构

三层模型 + 现有基础设施复用：

```
能力层 capabilities/（一能力一目录）
  src/capabilities/note_refine.json / note_enrich.json / text_filter.json
  声明：prompt 模板集 + 协议引用 + 策略维度 + 默认档位
策略层 ai_strategy.rs（+tests）
  维度/档位定义 + 策略指令注入 prompt（纯函数）
Provider 层 ai_provider.rs + ai_provider_client.rs（+tests）
  多 Provider 配置（BYOK）+ OpenAI 兼容抽象（ai_client.rs 泛化）
基础设施（复用不改）：ai_task / ai_guardrails / ai_credentials / ai_cost / db_ai_usage
```

硬约束（写入每层实现）：
- 授权红线不动：`enabled + authorized` 双条件 gate 保留，AI 调用默认关
- 密钥永不落 JSON/DB（DPAPI per-provider，明文红线）
- 错误契约不动：`AiClientError` 六类 + `AiTaskFailure` 四类映射，前端零改动
- 协议 schema 不随策略变化：策略只改 prompt，响应结构不变（校验器零改动）
- 身份诚实：AI 产出仍标记 ai-enhanced，策略不改来源标记
- 充值留桩：Provider 配置不带计费语义，命令空间 `ai_quota_*` 隔离预留

## 二、Provider 层（M1）

### 2.1 配置模型（ai_provider.rs）

```rust
pub struct AiProviderConfig {
    pub id: String,              // 唯一 id（uuid/slug）
    pub name: String,            // 显示名（"SiliconFlow"）
    pub kind: ProviderKind,      // OpenAiCompat | Ollama
    pub base_url: String,        // 默认来自预设模板
    pub models: Vec<String>,     // 可用模型列表
    pub default_model: String,
    pub enabled: bool,
    pub fallback_order: Vec<String>, // 降级链（本 Provider 失败后依次尝试）
}
```

- 存储：`ai_providers.json`（数据目录）；沿用 ai_settings.json 的"缺失/损坏回退内置默认"加载模式
- 内置预设模板（编译期捆绑）：SiliconFlow / DeepSeek / OpenRouter / Ollama（base_url + 推荐模型）；Ollama 走 OpenAI 兼容端点 `/v1/chat/completions`——本地推理复用同一抽象，构成无网降级路径
- 密钥 per-provider：ai_credentials.rs 扩展，DPAPI 条目名带 `provider:<id>` 前缀；密钥永不落 JSON/DB
- 兼容迁移：首启检测旧 ai_settings.json 的 base_url/model/密钥 → 自动生成 "SiliconFlow" Provider 并设为默认（用户无感）

### 2.2 OpenAI 兼容抽象（ai_provider_client.rs）

- `chat_text`/`chat_json` 接收 `&AiProviderConfig`（替代全局 AiClientConfig）
- AiClientError 六类（Auth/Network/Balance/Quota/Server/Parse）契约不变
- 踩坑经验原样保留：R1 系 no_think 特判、max_tokens 显式传值（DeepSeek 8192 硬切教训）、300s 超时（20k token 长输出）、指数退避重试

### 2.3 降级链（第一期简单版）

- 任务命令接受 `provider_ids: Vec<String>`（默认 = 全局降级顺序）
- Network/Server/Quota 失败 → 自动切下一个，最多 fallback 一次；Auth/Balance 不自动降级（保留错误归一，引导用户）
- 不引入熔断器/Key 池（网关侧概念，客户端单用户场景收益低——YAGNI）

## 三、策略层（M2）

### 3.1 维度与档位（ai_strategy.rs）

```rust
pub struct StrategyDim {
    pub key: String,              // "examples"
    pub label: String,            // "例子处理"
    pub options: Vec<DimOption>,  // {value, label}：保留完整/简化/删除
    pub default: String,
}

pub struct StrategyPreset {       // 档位 = 维度值预设组合
    pub id: String,               // "detail" | "standard" | "minimal"
    pub name: String,             // "保留细节" | "标准" | "极简"
    pub dim_values: HashMap<String, String>,
}
```

- 维度由**能力声明**（JSON）定义——每个能力声明自己的旋钮（例子/术语/细节/引用/过渡…）
- 指令注入纯函数：维度值 → 自然语言指令段落，追加 system prompt 末尾（"本次产出策略：例子只保留一个典型示例并压缩说明；…"）
- 存储：`ai_settings.json` 增加 `strategy` 字段（默认档位 id + 逐项覆盖 map）
- 生效：全局默认 + 任务级覆盖（任务命令参数 `strategy: Option<StrategyOverride>`）
- UI 分期：M2 内部分两小步——先全局档位下拉 + 任务发起时档位选择，再逐项微调 UI

### 3.2 策略与协议解耦

- 策略只影响 prompt 组装，`AiRefineResponse` 等协议 schema 与校验器零改动
- 档位/维度值非法 → 回退默认值（防御性编程铁律）

## 四、能力层（M3）

### 4.1 能力声明 JSON（capabilities/note_refine.json 示意）

```json
{
  "id": "note_refine",
  "version": 3,
  "prompt": {
    "core_instruction": "精修=整理不创作：…",
    "styles": { "lecture": "…", "hands-on": "…" },
    "profile_style": { "lecture": "lecture", "coding": "hands-on" },
    "fallback_style": "lecture",
    "few_shot": [],
    "output_format": "…"
  },
  "protocol": "AiRefineResponse",
  "strategy_dims": [
    { "key": "examples", "label": "例子处理", "options": [{"value":"keep_full","label":"保留完整"},{"value":"simplify","label":"简化"},{"value":"drop","label":"删除"}], "default": "keep_full" }
  ],
  "presets": [
    { "id": "detail", "name": "保留细节", "dim_values": {"examples":"keep_full"} },
    { "id": "minimal", "name": "极简", "dim_values": {"examples":"simplify"} }
  ]
}
```

### 4.2 prompt 组装管线（ai_capability.rs 纯函数）

```
core_instruction + style_system(profile 档案映射) + strategy_instructions(策略值) + few_shot + output_format
```

### 4.3 迁移路径

- 现有 `prompts/note_refine.json` 内容几乎不动，仅加 `strategy_dims` + `presets`
- 三个适配器（ai_note_refine / ai_note_enrich / ai_text_filter）保留壳，prompt 来源从"内置 struct 解析"改为"能力声明解析"（bundled() 逻辑平移）
- 未来新能力 = 新增声明 JSON + 薄适配器（≤100 行）

## 五、设置页重构（M1 拆面板，M2 加偏好）

```
AI 服务 组（AiServicePanel 408 行 → 拆 4 面板）
├── AiProviderSettings     Provider 列表（名称/状态/默认模型 + 编辑/测试/启用）
│                           "添加 Provider" → 预设模板 → 填密钥 → 选模型 → 测试连接
├── AiPreferenceSettings   产出偏好：默认档位 + 展开微调（按能力维度，M2）
├── AiUsagePanel           用量：本地统计（近 7 天任务数/token/成本估算）——远期换熵减配额
└── AiAuditPanel           审计列表（折叠"高级"区，默认收起）
```

- **余额卡片移除**：SiliconFlow 第三方余额不再展示（用户不该看到别家钱包）；"测试连接"保留（验证密钥有效性，不再显示余额分项）；低余额提醒保留在命令层（调用失败时提示）
- 全局开关 + 授权确认卡保留（隐私红线 UI 不动）

## 六、数据流

```
用户发起精修（可选 provider_id + strategy）
  → 命令层：content_gate（授权红线）→ 解析 Provider 配置（默认/降级链）
  → 能力适配器：解析能力声明 → 组装 prompt（base + 档案风格 + 策略段落 + 输出约束）
  → ai_provider_client：按 Provider 配置请求（超时/重试/错误归一）
  → 响应强校验（协议 validate 不变）→ 失败回退纯规则（不丢不假）
  → 结果落库 + 审计 + 用量统计
  → 前端：任务轮询/事件双通道（useAiTaskPolling 不动）
```

## 七、错误处理

- AiClientError 六类契约不变；新增：Provider 未配置/已禁用 → Auth 同文案（引导设置页）
- 降级切换失败 → 归因原 Provider 错误 + 附加"已尝试降级 Provider: xxx"
- 降级不静默：任务失败原因可见（AiTaskFailure 展示层沿用）

- **M1 · Provider 层**：ai_provider.rs + ai_provider_client.rs + 旧配置自动迁移 + 设置页拆出 Provider 管理（余额卡片移除）→ 交付：多 Provider 可用
