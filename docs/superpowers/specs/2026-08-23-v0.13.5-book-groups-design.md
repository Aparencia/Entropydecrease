# v0.13.5 设计规格：书籍笔记组与知识树附加（方案 C）

> 状态：**已批准**（2026-08-23 上层审斡通过；依据 [v0.13.md §v0.13.5 规划](../../versions/v0.13.md#v0135-规划书籍笔记组与知识树附加方案-c2026-08-23-立项) + [电子图书馆调研](../../Foresight/competitive-analysis-personal-library.md) + [知识体系设计理念 §七](../../product/knowledge-system-design-philosophy.md)）
> 系列：[v0.13 系列](../../versions/v0.13.md) · 需求登记 REQ-213~218
> 范围：书籍笔记组 + 知识树附加（方案 C）——**不存书内容**、一书本一组、复用优先（升卡/复习/组归档/application 全复用，零新机制）

## 一、总架构

自底向上四层（AGENTS.md §3）：

```
原子层：book_pure.rs（book_stale / parse_application_field / require_book_status / require_rating
        纯函数，TDD golden 先行；与 knowledge_pure 同范式）
业务层：db_books.rs（books 表 CRUD + JOIN note_groups；:memory: 单测）
系统层：commands_books.rs（create/update/list/book_stale_check；无 delete、无真实元数据拉取）
UI 层：书籍组卡片/徽标 + 写体会模板（应用字段表单）+ 知识树「附加书籍」区（组卡渲染 + 挂接）
```

硬约束（写入每层）：
- **不存书内容**（红线）：books 是元数据壳；无导入/无阅读器/无内容复制；只存用户体会（自己产出＝生成效应）。
- **一书本一组**：`books.group_id UNIQUE`；书组名＝书名；体会＝组内手动笔记（零新命令）。
- **复用优先**：升卡/复习复用 `generate_group_cards`；挂树复用 `link_knowledge_target`；删除走既有组归档；应用字段复用 v0.13.3 `knowledge_decisions(kind=application)`。全部复用，零新机制。
- **零破坏**：仅新增 books 表 + `commands_groups::GROUP_KINDS` 白名单 +1（'book'）；`note_groups.kind` 无 CHECK 约束 → **无需迁移**（结论见 §二）。
- **本地优先**：纯本地 SQLite；无网络（元数据拉取＝可选增强桩，默认关）。
- **「书→判断」贯通**：体会「应用字段」→ application 记录；一本书挂多问题 → v0.13.4 交叉点提示**自动适用**（零新代码）。

## 二、数据层

### 1. books 表（建表幂等，v0.13.md 规划 §一.1 逐字）

```sql
-- note_groups.kind 扩展 'book'（现有 kind 无 CHECK，command 层白名单+1 即可）
CREATE TABLE IF NOT EXISTS books (            -- 元数据壳，不存内容
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  group_id INTEGER NOT NULL UNIQUE REFERENCES note_groups(id) ON DELETE CASCADE,
  title TEXT NOT NULL,
  author TEXT, isbn TEXT,
  status TEXT NOT NULL DEFAULT 'reading',     -- toread/reading/finished/abandoned
  rating INTEGER,                             -- 1-5，可选
  lesson TEXT,                                -- 一句话"这本书对我的意义"
  created_at INTEGER NOT NULL, updated_at INTEGER NOT NULL
);
```

### 2. 零破坏结论

- 仅新增 `books` 表（`ensure_table` 幂等）；既有表结构与查询不动。
- `note_groups.kind` **无 CHECK 约束**（现状）：`commands_groups::GROUP_KINDS` 为 `[&str;3]=["course","topic","standalone"]`，白名单+1 为 `[&str;4]` 加 `"book"` 即可，**无任何迁移**。
- `note_groups` 现无独立 `status` 列（不是 `fragments.status`）——组级归档由组结算/组件生命周期语义承载（软删除，不销毁数据）；**本版不新增 `note_groups.status` 列、不新增 delete 命令**。
- `flashcards.kind` / `metrics_events.kind` 不受影响。

## 三、原子层：纯函数（book_pure.rs，TDD golden 先行）

```rust
// 全部无副作用、无 DB、无时间调用——输入信号由调用方聚合注入（now 以参数传入）。
pub struct BookStaleSignal { pub last_accessed_at_ms: Option<u64>, pub status: String,
                             pub created_at_ms: u64, pub now_ms: u64 }
pub fn book_stale(s: &BookStaleSignal) -> bool;
// 范式同 concept_stale：基线 = last_accessed_at_ms.unwrap_or(created_at_ms)。
// 仅 status == "finished" 且 (now_ms - baseline) ≥ 90 天 → true（"这本书还在影响你吗？"）。
// toread/reading/abandoned 永不 true（未读完不触发老化；放弃＝用户已裁决）。
// golden：toread 永不 / reading 永不 / finished 89 天 false / finished 90 天 true /
//        finished 从未访问（基线=created_at）90 天 true / abandoned 永不

pub fn parse_application_field(text: &str) -> Option<String>;
// 体会模板「应用字段」解析——从模板正文提取「我打算怎么用」段（标记为 `## 应用`）。
// 可空：标记缺失/内容为纯空白 → None；多行：非空行合并（空行折叠）；
// 引号转义：块引用 `> ` 前缀剥除、`\> ` 反转义；首尾 trim。
// golden：无标记→None / 有空内容→Some(单行折叠) / 多行含空行→折叠为单逻辑串 /
//        块引用剥除 / 仅空白与引号→None

pub fn require_book_status(status: &str) -> Result<(), String>;
// 白名单 toread/reading/finished/abandoned（非白名单/空串 → 中文业务错误）。
// golden：合法通过 / 非法拒 / 空串拒

pub fn require_rating(rating: Option<i64>) -> Result<(), String>;
// rating ∈ 1..=5 或 None（None=未评分合法）；0/负/≥6 拒。
// golden：1 / 5 通过；0 / 6 / -1 拒；None 通过
```

> 线宽豁免登记：book_pure.rs 预估 240–300 行（四函数 + golden 内联），超 300 则拆 `book_pure_stale.rs`（book_stale）与 `book_pure_field.rs`（parse_application_field）。

## 四、系统层：Tauri commands（commands_books.rs）

入参校验统一：id/group_id>0；title 非空且 ≤2000（复用 `normalize_text`）；status 用 `require_book_status`；rating 用 `require_rating`；author/isbn/lesson 可选（空串→None）。

| 命令 | 参数要点 | 返回值 |
|---|---|---|
| `create_book_group` | `title`(非空/≤2000), `author?`, `isbn?`, `status?`(默认 reading) | `BookGroup`（事务：建 `kind=book` 组（组名=书名，terrain=container，source=manual，route_reason JSON 注记"书籍组"）＋ books 行；`GROUP_KINDS` 含 book；`books.group_id UNIQUE` 兜底＋command 预查给友好错误——一书本一组） |
| `update_book_group` | `group_id`, `title?`/`author?`/`isbn?`/`status?`/`rating?`/`lesson?` | `BookGroup`（组必须 `kind=book`——防误改他组；status 白名单；rating 1-5；title 若有则非空） |
| `list_book_groups` | `status?` | `Vec<BookGroup>`（JOIN books+note_groups；status 过滤可选；按 updated_at 倒序） |
| `book_stale_check` | `group_id` | `{stale, signal}`（组必须 `kind=book`；聚合信号→`book_stale` 纯函数；同 `audit_due_for_system` 模式——审计**探测**，展示接线 v0.13.4，本版仅提供函数+命令） |

**返回类型**：`BookGroup`（camelCase）＝ `{ group: NoteGroup, book: Book }` 包装——`group.id` 即书组 id；`book` 含 title/author/isbn/status/rating/lesson。

**校验清单（全列）**：title 非空/≤2000 · status 白名单 · rating 1-5 或 None · group_id>0 · update 目标组 kind=book · 一书本一组（group_id UNIQUE） · `list_book_groups` status 过滤白名单 · `book_stale_check` 目标组 kind=book · `link_knowledge_target` 挂书组由 `link_target_exists(LinkTarget::NoteGroup)` 覆盖（kind=book 仍是 note_group，零新代码）。

**无 delete_book_group 命令（裁决）**：不删数据（书组、books 行、体会笔记、挂树引用全保留）；组删除走既有组归档路径（§二.2 软删除语义），无独立状态翻转与删除命令——避免为"删除"引入新机制。

**元数据拉取桩**：`FeatureFlags` 增 `book_metadata_pull: bool`（`serde(rename_all="camelCase")` + `default`，**默认 false**——增强能力默认关纪律）；留桩命令 `book_metadata_preview(title?: String, isbn?: String)` 返回 `{available:false, message:"元数据拉取未启用"}`（**本版不做真实拉取**，无网络调用，纯元数据无版权问题但仍不实装）。

## 五、UI 层

- **书籍组卡片/徽标**：`GroupSidebar.tsx` `kindBadge` 增 `kind==="book" → {label:"📕 书籍", color}`；组行（书名=组名/作者/状态徽标/体会计数）在组筛选侧栏与组详情面板呈现。`NotesPage` 不新增独立视图——书组复用组列表/组详情落点。
- **写体会模板**（`NoteEditView` 相关落点）：书组详情面板「✍ 写体会」**按钮**（非强制）——新建组内笔记并**预填正文模板**（标题=书目体会；正文骨架＝`> 这本书改变了我哪个判断？`＋`> 我打算怎么用？（应用字段）`＋常规体会正文占位）。模板可编辑/删除（预填≠强制，防"假燃料"）。
- **应用字段表单**：随"写体会"渲染——应用字段输入 + **挂概念/挂问题**目标选择器。提交规则（裁决）：**应用字段若为空→仅落组内笔记**（不建应用记录，防记录膨胀）；**非空→必调 v0.13.3 application**，且 `used_refs` 引用必填——**必须挂概念（selected concept_id）或书组引用（used_refs.group_id=book group id，兜底）**，可选挂问题（question_id）；`content=应用字段`。"书→判断"贯通。
- **知识树「附加书籍」区**（`KnowledgeDetailPanel` → 扩展 `KnowledgeLinkSection.tsx`，**树侧零 schema**）：新增副区——`list_knowledge_links(system, node/concept)` 过滤 `target_type="note_group"` → 对每个 `group_id` 经 `list_book_groups` JOIN 出书卡（书名/作者/状态徽标/体会计数）渲染；**添加＝复用 `link_knowledge_target`**（下拉选已有书组 / 现场新建书组）；撤销＝`delete_knowledge_link`。一本书挂多个问题/概念 → v0.13.4 交叉点提示**自动适用**（零新代码）。
- **书组升卡/复习**：复用 `generate_group_cards`（书组天然生效——组→卡）＋复习面/周契约/到期徽标（`count_due_cards` 对任意 group_id 已支持）；**无新 UI**（组行既有"复习 N"徽标即可）。
- 前端类型：`types/books.ts`（`Book`/`BookGroup`/`BookStatus`/`NewBookGroup`/`UpdateBookGroup` 接口，与 command 参数同名 camelCase）。

## 六、测试策略

- 纯函数 golden（AAA）：`book_stale` 6 组（§三 全列）、`parse_application_field` 5 组、`require_book_status` 3 组、`require_rating` 6 组（1/5 通过、0/6/-1 拒、None 通过）。
- 数据层 `:memory:`：事务建组+`group_id` 唯一约束（二次建同书组拒）；状态白名单；rating 边界（0 拒/6 拒/1 与 5 通过）；lesson 更新；JOIN 返回 `BookGroup`。
- command 层：title 非空/超长拒；status 非法拒；rating 越界拒；`update_book_group` 非 book 组拒；`link_knowledge_target` 挂书组校验通过（kind=book 仍 note_group）；`book_stale_check` 非 book 组拒。
- 前端 vitest：书卡渲染（书名/作者/状态徽标）；附加书籍区挂接（选组→`link_knowledge_target`）；写体会应用字段表单（空→仅建笔记；非空→调 application，未挂概念/书组→拦截）。
- 全栈零依赖（无网络、无 AI）；`cargo test` + `tsc --noEmit` + vitest + vite build。

## 八、验收（真机走查，规划 §三 五步）

1. 建书组：书名非空→组名=书名、状态默认 reading；**二次建同书组被 `group_id` UNIQUE 拒**（一书本一组）。
2. 写体会（带应用字段）→ 组内手动笔记 + application 记录（content=应用字段，used_refs 挂概念/书组）。
3. 挂问题树：节点/概念「附加书籍」区选已有书组或现场新建；书卡显示书名/作者/状态徽标。
4. 升卡/复习：书组 `generate_group_cards` 幂等；复习面/到期徽标对书组生效。
5. 审计探测：`book_stale_check` 在 finished 90 天边界返回 stale（测试注入时间验证；真机验证命令存在与结构——审计**展示**接线 v0.13.4，本版仅探测）。
6. 回归：notes/组/闪卡/复习面/知识体系/组归档全链路不变（零破坏验证）。

## 九、不做清单（本版）

书籍内容导入/格式转换/阅读器 · 全文检索（没有内容可检）· 书评社交 · 周阅读目标（≈学习计划 REQ-030，另议）· 书库管理（Calibre 已占位）· AI 摘要书评（获取隐喻；AI 只建议不生成）· `note_groups.status` 列 · 元数据真实拉取 · `delete_book_group` · 跨体系自由引用 · 图可视化 · 移动端
> 红线重申：**不存书内容**——只存用户体会（生成效应，记忆深 2-5 倍）；与 Readwise 分界：它存高亮（书的内容片段），熵减存"**书对我的改变**"。
