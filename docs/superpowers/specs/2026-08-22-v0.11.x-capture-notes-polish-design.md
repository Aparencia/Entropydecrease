## A 组 · 采集体验（1 / 2 / 11）

### 1️⃣ 档案采集中可改 + 自动重评（含记忆机制修正）

**现状**：[LiveProfileStrip.tsx](../../../app/src/components/LiveProfileStrip.tsx) 采集中只读展示形态×画面档×领域（唯一交互=降档确认）；
档案在 start 时落库一次（live_session_lifecycle.rs）；形态/领域无采集中重评（只有画面档 tier 每 2-3 分钟重评，REQ-189）；
记忆机制现状 = 记忆偏好**前置短路**（commands_video.rs：记忆命中 → 候选直接覆盖为记忆 kind、needs_confirmation=false，检测信号被完全丢弃）。

**目标行为**：
1. **采集态三维可改**：LiveProfileStrip 摘要 → 可点下拉（复用 ProfileDetector 三下拉组件：形态/画面档/领域）
2. **热切换通道**：新增后端命令 `update_live_profile` → 当前会话管线参数热切（采样预算/信号权重/后处理规则按新形态/档位）；事件 `live:profile-updated` 回推；只影响后续采集
3. **采集中自动重评**：形态/领域每 2-3 分钟重评（与画面档同 tick），检测信号增量更新（帧切换率/字幕统计/新 OCR 分区标签）
4. **记忆机制改为"检测优先 + 记忆兜底 + 冲突以检测为准"**（四象限）：

| 场景 | 行为 |
|------|------|
| 记忆命中 + 检测高置信且同 kind | 记忆生效（快路径，无需确认）——现状保留 |
| 记忆命中 + 检测高置信但冲突 | **检测为准** + 标记"记忆与检测冲突，已按检测"（可改；不自动改记忆） |
| 记忆命中 + 检测低置信/冲突 | 记忆生效（用户先验 > 弱证据）——现状保留 |
| 无记忆 | 纯检测（现状保留） |

**改动点**：
- 后端：video_profile.rs（vote_detect 输出 top kind 供冲突比较——新增 `top_kind()` 或使 `DetectResult` 携带）；commands_video.rs（记忆查询从"前置短路"移为"后置兜底 + 冲突判定"）；live_session 新命令 `update_live_profile` + 重评 tick 扩展（复用 tier 重评节奏）
- 前端：LiveProfileStrip 加三下拉 + 调 update_live_profile；监听 live:profile-updated

**测试**：记忆四象限决策矩阵单测（注入 fake 记忆/信号）；热切换参数生效单测（注入 fake 管线状态断言预算表切换）；采集中重评事件时序

### 2️⃣ 视频信息识别率（C：通用信号增强 + B站适配试点）

**现状**：平台识别=窗口标题后缀表（仅 8 平台）+ URL 主机名（platform_adapter.rs）；时长=播放器 OCR 时间对解析（session_info.rs parse_player_text）；合集=标题五模式（series_detect.rs）；形态/领域=标题关键词投票 + 帧切换率 + 字幕 + 时长（video_profile.rs / video_profile_domain.rs）。

**根因**：平台后缀覆盖不足 + 浏览器播放无后缀；形态/领域依赖标题关键词（B站营销化标题无关键词可命中）；时长依赖播放器 OCR UI 形态各异。

**目标行为**：
1. **通用信号增强（全平台受益）**：
   - 会话开头 30s ASR 文本 → 领域关键词（开场白自我介绍是领域强信号）
   - OCR 分区标签通道完善（platform_adapter 已有 bilibili 内联分区/local 路径分段，补"画面 OCR 标签通用化"消费端）
2. **B站适配试点（专用解析验证）**：固定标题形态 `标题_哔哩哔哩_bilibili` + 选集按钮 OCR 解析（P分P/总集数 → 合集信息）；作为**证据增强**（命中才加权，不命中不惩罚），不替代通用信号
3. 平台识别失败（浏览器播放等）→ 诚实"未知平台"，领域仍从其他信号出（现状已诚实，保持）

**改动点**：video_profile_domain.rs（DomainSignals 增 asr_opening 字段/消费）；platform_adapter.rs（B站解析扩展：选集 OCR 文本 → 集号/总集数）；live_session 重评 tick 携带新信号

**测试**：ASR 开场白 → 领域命中 golden（"大家好我是美妆博主" → beauty）；B站标题/选集样本矩阵（含边界反例）；无平台信号零回归

## B 组 · 数据与过滤（3 / 4 / 10）

### 3️⃣ 会话编号显示序号化

**现状**：`sessions.id INTEGER PRIMARY KEY AUTOINCREMENT`（永不归位）；SessionListPanel 直接显示 `#{s.id}`。

**目标行为**：列表/详情展示的编号 = **按时间序 rank**（删除前面会话后新会话显示为归位后的序号）；内部 id 保持稳定（外键/日志/缓存零风险）。

**改动点**：后端 list_sessions（及分组查询）返回 `display_no`（按 started_at 升序 rank，同时间戳按 id 稳定排序）；SessionListPanel 显示 display_no；详情面板/笔记跳转仍用内部 id

**测试**：rank 计算单测（删除中间会话后重排；同时间戳稳定序）；排序模式（updated/pin/created）与 rank 解耦——rank 永远按 created 序

### 4️⃣ 新颖度比较域=变化区域（PPT 结构相同内容不同不再被过滤）

**现状**：novelty.rs 对**整帧文本**做 Jaccard 重叠率 ≥0.85 判冗余——PPT 模板页脚/侧栏/导航固定文字稀释新内容 → 结构相同内容不同的页被整帧跳过。

**目标行为**：
1. 新颖度比较域改为 **grid_diff 判变单元格覆盖区域的 OCR 文本**（像素级变化与文本级冗余两级对齐——固定版面文字不再参与重叠率）
2. 阈值按画面档自适应：rich 档更宽松（0.90），low 档更严格（0.80），默认 0.85

**改动点**：novelty.rs（输入改为"变化区域文本"；阈值参数化）；live_frame_process.rs / import_frame.rs（组装变化区域文本 + 传档位）

**测试**：黄金用例——PPT 同构页（页脚/侧栏相同、正文不同）→ 不判冗余；正文相同仅动画微变 → 仍判冗余；档位阈值矩阵

### 10️⃣ 水印过滤 A+B+C 全部落地

**现状**：watermark_filter.rs 按 (region_key, 文本) 分组 + 三阈值；但 screens.rs/analysis.rs 构造 WatermarkInput 时 `region_key` 恒为 **None**（bbox 列 v0.7.3 已落库未接入）→ 区域稳定性信号完全未用；半透明水印 OCR 抖动（文本每帧略有差异）→ 精确分组计数不足 → 漏检（会话 38 "万事如番茄LilLil" 实证）。

**目标行为**：
- A：**bbox 接入 region_key**（screens.rs/analysis.rs 从 DB bbox 列构造区域键）
- B：**文本相似聚类**——编辑距离 ≤2 的文本归并同一候选（解决 OCR 抖动）
- C：**区域级出现率检测**——区域位置稳定 + 该区域内文本近似不变 → 水印候选（与具体文本解耦，直接落地不排队）

**改动点**：watermark_filter.rs（聚类 + 出现率两阶段）；screens.rs（bbox 传入）；analysis.rs（同步）

**测试**：会话 38 样本回归（"万事如番茄LilLil" 命中）；OCR 抖动变体聚类用例（截断/噪声字符归并）；区域级误杀保护（内容区域文字稳定时防误判——沿用"内容变化证据"信号）

### 6️⃣ 精修工作台（前后对比能力）

**现状**：AiRefineCard 内嵌于笔记预览视图小窗口 diff（行级 diff_markdown/diff_stats 引擎已有，note_diff.rs）；规则版/精修版无法大窗口对比；删除内容展示弱。

**市场依据**：Notion 块级 before/after + 逐条 accept/reject；GitHub PR 语义分组 diff；Smart Diff 反模式——无视觉 diff 直接应用 / 原始行级 diff 忽略语义分组 / 无选择性接受 / 隐藏删除。

**目标行为**：独立大模态「精修工作台」（≈80% 窗口）：

```
┌─ 精修工作台 ────────────────────────────────────────────┐
│ 顶部：✎ 统计条  新增 N 行 · 删除 M 行 · 切片 K · 成本 ¥X    │
│ ┌───────────────┬─────────────────────────────────────┐ │
│ │ ① 规则版（左）  │ ② 精修版（右）                        │ │
│ │   同步滚动      │   语义分组 diff（章节/段落 hunk）       │ │
│ │   章节锚点可回跳  │   新增绿/删除红（删除折叠可展开复查）    │ │
│ └───────────────┴─────────────────────────────────────┘ │
│ 底部：⟳ 重新生成（参数可改）│ 放弃 │ 采纳落库（版本化）         │
└────────────────────────────────────────────────────────┘
```

- **语义分组 diff**：行级 diff 之上按章节/段落聚合为 hunk（一个逻辑改动=一个 hunk）；删除内容折叠为"已删除 X 段"可展开——不隐藏删除
- **章节级锚点**：两栏均保留 `[[ts:]]` 回跳（与 7️⃣ 裁决一致：AI 输入剥离、展示/落库章节级挂回）
- **hunk 级部分采纳：本版不做**（YAGNI——误采纳由版本化兜底，VersionPanel 已有 50 版历史）
- **入口**：笔记预览视图 AI 精修卡 → 打开工作台；精修任务后台跑（异步任务基建复用），完成后自动打开
- **版本对比**：VersionPanel 增加"与当前版本对比"（版本快照已有，复用同一 diff 引擎——前后笔记内容比较的第二入口）

**改动点**：新组件 RefineWorkbench.tsx；note_diff.rs（行级 → 章节级 hunk 分组输出，纯函数）；AiRefineCard.tsx（入口改造）；VersionPanel.tsx（对比按钮）；commands_ai_refine（工作台查询接口：规则草稿+精修结果+分组 diff 一次取全）

**测试**：diff 分组纯函数单测（章节重排/段落合并/删除段折叠）；工作台状态机（运行中/完成/采纳/放弃/重新生成）；采纳落库版本化回归

## 假设与边界

- 编号只改展示层，数据层 id 永不变
- 采集中档案热改只影响后续采集；停止后产物可按新档案重建
- 精修懒自动仅会话详情入口触发；hunk 级部分采纳不做（版本化兜底）
- 产物命令保留但无 UI 入口；旧产物数据不失效
- 记忆冲突不自动改记忆；画面要点/词汇表移出笔记无开关（数据在会话详情可查）
