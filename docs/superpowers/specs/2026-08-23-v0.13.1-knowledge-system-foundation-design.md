# v0.13.1 设计规格：知识体系基建（体系/问题树/概念/模型/引用）

> 状态：**已批准**（2026-08-23，依据 [ADR-024](../../adr/ADR-024-knowledge-system-layer.md) + [整合分析 §四](../../Foresight/personal-knowledge-system-layer-integration.md)；用户赋权执行）
> [v0.13 系列文档](../../versions/v0.13.md) · 需求登记 REQ-202~205
> 范围：v0.13.1 体系基建——**不含**概念双面体（v0.13.2）、决策/应用（v0.13.3）、审计/交叉点（v0.13.4）

## 一、总架构

自底向上四层（AGENTS.md §3 纪律）：

```
原子层：knowledge_pure.rs（audit_due / concept_stale / promote_rules 纯函数，TDD golden 先行）
业务层：db_knowledge_systems.rs / db_knowledge_nodes.rs / db_knowledge_concepts.rs /
        db_knowledge_models.rs / db_knowledge_links.rs / db_knowledge_audits.rs（:memory: 单测）
系统层：commands_knowledge.rs（参数校验与编排，无业务逻辑）
UI 层：KnowledgePage（体系树 + 领域列表 + 创建向导）——三时钟纪律：体系不进每日视图
```

硬约束（写入每层实现）：
- **体系只引用、不收纳**：`knowledge_links` 是唯一引用通道；无任何"内容进体系"命令。
- **零破坏**：`db_migrations.rs` 只新增建表/补列；既有表结构与查询不动。
- **命名纪律**：业务术语贯穿全栈——system/node/concept/model/link 命名统一（Tauri command 与 TS 类型同名）。
- **本地优先**：全部纯本地 SQLite；无网络依赖；无 AI 依赖（AI 属 v0.13.2 可选增强）。

## 二、数据层（db_migrations.rs 增量——建表幂等）

```sql
CREATE TABLE IF NOT EXISTS knowledge_systems (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  parent_system_id INTEGER REFERENCES knowledge_systems(id) ON DELETE SET NULL,
  name TEXT NOT NULL,
  kind TEXT NOT NULL DEFAULT 'domain',        -- global/domain（command 层白名单校验）
  core_question TEXT,                          -- global 必填（command 层校验非空）
  status TEXT NOT NULL DEFAULT 'active',       -- active/watching/archived
  created_at INTEGER NOT NULL, updated_at INTEGER NOT NULL
);
CREATE UNIQUE INDEX IF NOT EXISTS idx_knowledge_systems_global
  ON knowledge_systems(kind) WHERE kind = 'global';   -- 全局体系唯一（防多核心稀释）

CREATE TABLE IF NOT EXISTS knowledge_nodes (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  system_id INTEGER NOT NULL REFERENCES knowledge_systems(id) ON DELETE CASCADE,
  parent_id INTEGER REFERENCES knowledge_nodes(id) ON DELETE CASCADE,
  type TEXT NOT NULL DEFAULT 'question',       -- question/scenario/domain_entry
  text TEXT NOT NULL,
  order_idx INTEGER NOT NULL DEFAULT 0,
  status TEXT NOT NULL DEFAULT 'active',       -- active/watching/archived
  created_at INTEGER NOT NULL
);
CREATE INDEX IF NOT EXISTS idx_knowledge_nodes_tree ON knowledge_nodes(system_id, parent_id);

CREATE TABLE IF NOT EXISTS knowledge_concepts (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  system_id INTEGER NOT NULL REFERENCES knowledge_systems(id) ON DELETE CASCADE,
  name TEXT NOT NULL UNIQUE,                   -- 全局唯一：交叉点判定的前提
  essence TEXT, boundary TEXT, relation TEXT,  -- 三问：本质/边界/联系
  status TEXT NOT NULL DEFAULT 'core',         -- core/watching/archived
  last_applied_at INTEGER,
  created_at INTEGER NOT NULL, updated_at INTEGER NOT NULL
);

CREATE TABLE IF NOT EXISTS knowledge_models (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  system_id INTEGER NOT NULL REFERENCES knowledge_systems(id) ON DELETE CASCADE,
  name TEXT NOT NULL,
  disciplines TEXT NOT NULL,                   -- JSON 数组（≥1 学科，command 层校验）
  claim TEXT, valid_when TEXT, invalid_when TEXT,
  cross_checks TEXT,                           -- JSON（v0.13.1 预埋字段，可空）
  status TEXT NOT NULL DEFAULT 'active',
  created_at INTEGER NOT NULL, updated_at INTEGER NOT NULL
);
CREATE INDEX IF NOT EXISTS idx_knowledge_models_system ON knowledge_models(system_id);

CREATE TABLE IF NOT EXISTS knowledge_links (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  system_id INTEGER NOT NULL REFERENCES knowledge_systems(id) ON DELETE CASCADE,
  node_id INTEGER REFERENCES knowledge_nodes(id) ON DELETE SET NULL,
  concept_id INTEGER REFERENCES knowledge_concepts(id) ON DELETE SET NULL,
  model_id INTEGER REFERENCES knowledge_models(id) ON DELETE SET NULL,
  target_type TEXT NOT NULL,                   -- note_group/note/flashcard/fragment
  target_id INTEGER NOT NULL,
  created_at INTEGER NOT NULL
);
CREATE INDEX IF NOT EXISTS idx_knowledge_links_system ON knowledge_links(system_id);
CREATE INDEX IF NOT EXISTS idx_knowledge_links_target ON knowledge_links(target_type, target_id);

CREATE TABLE IF NOT EXISTS knowledge_audits (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  system_id INTEGER NOT NULL REFERENCES knowledge_systems(id) ON DELETE CASCADE,
  items_json TEXT NOT NULL,                    -- v0.13.4 起使用；v0.13.1 仅留表
  stats_json TEXT NOT NULL DEFAULT '{}',
  created_at INTEGER NOT NULL
);
```

**不可变约束**：`knowledge_concepts.name` UNIQUE 全局——升格/交叉点判定依赖；名称归一化规则（trim＋连续空格合并）在 command 层执行后落库。

## 三、原子层：纯函数（TDD golden 先行）

```rust
// knowledge_pure.rs —— 全部无副作用、无 DB 依赖（输入信号由调用方聚合）

pub struct AuditSignal { pub item_count: usize, pub last_audit_at_ms: Option<u64>, pub now_ms: u64 }
pub fn audit_due(s: &AuditSignal) -> bool;
// 触发：last_audit 为空且创建/启用 ≥90 天；或距上次审计 ≥90 天且 item_count ≥ 20
// golden：首次 89 天不触发 / 90 天触发 / 二次审计 89 天不触发 / 90 天且不足 20 条不触发 / 90 天且 ≥20 条触发

pub struct StaleSignal { pub last_referenced_at_ms: Option<u64>, pub last_applied_at_ms: Option<u64>, pub now_ms: u64 }
pub enum StaleLevel { None, Watching/*≥90天无引用*/, Archive/*≥180天且 never applied*/ }
pub fn concept_stale(s: &StaleSignal) -> StaleLevel;
// 引用来源：knowledge_links 中 concept 出现 或 decisions.used_refs 含概念（used_refs JSON 文本扫描由调用方聚合）
// golden：有引用→None / 90~179 天无引用→Watching / ≥180 天无引用且从未应用→Archive / ≥180 天但有应用记录→Watching

pub struct PromoteInput { pub card_name: String, pub existing: Vec<(i64, String)>, /* (concept_id, name) */ pub target_system_id: i64 }
pub enum PromoteDecision { Create, Merge{concept_id: i64}, CrossSystemHint{concept_id: i64, other_system_id: i64}, AlreadyLinked{concept_id: i64} }
pub fn promote_rules(input: &PromoteInput) -> PromoteDecision;
// 规则：null 归一化名称精确匹配→AlreadyLinked（卡已带 concept_id）语义由调用方区分；
//      name 命中 existing→Merge；命中且 concept.system_id != target_system_id→CrossSystemHint（v0.13.4 交叉点数据源）；
//      均未命中→Create
// golden：新名→Create / 同名→Merge / 跨体系同名→CrossSystemHint / 空名→panic 前置（command 校验空名拒绝）
```

**线宽豁免登记**：`knowledge_pure.rs` 预估 260–300 行（三函数＋golden 测试内联），若超 300 行拆 `knowledge_audit.rs`（audit_due/concept_stale）与 `knowledge_promote.rs`（promote_rules）。

## 四、系统层：Tauri commands（commands_knowledge.rs）

入参校验规则统一：id>0；kind ∈ {global, domain}；type ∈ {question, scenario, domain_entry}；status ∈ {active, watching, archived}；target_type ∈ {note_group, note, flashcard, fragment}；name/text 非空且 ≤2000 字符；global 体系创建时 core_question 必填；`create_knowledge_system` 检查 global 唯一（DB 唯一索引兜底 + command 层预查给友好错误）。

| 命令 | 参数要点 | 返回值 |
|---|---|---|
| `list_knowledge_systems` | — | 体系列表（含节点/概念/模型计数） |
| `create_knowledge_system` | name, kind, parent_system_id?, core_question? | 新体系（global 唯一校验） |
| `update_knowledge_system` | id, name?, core_question?, status? | 更新后体系 |
| `archive_knowledge_system` | id | 幂等归档（status=archived） |
| `add_knowledge_node` | system_id, parent_id?, type, text | 节点（parent_id 校验同体系） |
| `update_knowledge_node` | id, text?, order_idx?, status? | 节点 |
| `delete_knowledge_node` | id | 级联删除子树（防误删：前端二次确认） |
| `list_knowledge_nodes` | system_id | 全树扁平列表（前端组树） |
| `add_knowledge_concept` | system_id, name, essence?, boundary?, relation? | 概念（name 唯一冲突→明确报错） |
| `update_knowledge_concept` | id, name?, essence?, boundary?, relation?, status? | 概念 |
| `list_knowledge_concepts` | system_id?, status? | 概念列表 |
| `add_knowledge_model` | system_id, name, disciplines(JSON), claim?, valid_when?, invalid_when? | 模型 |
| `update_knowledge_model` | id, …同上可改字段 | 模型 |
| `list_knowledge_models` | system_id | 模型列表 |
| `link_knowledge_target` | system_id, node_id?/concept_id?/model_id?（三者至少一）, target_type, target_id | link（target 存在性校验：note_group/note/flashcard/fragment 查对应表） |
| `list_knowledge_links` | system_id, node_id?/concept_id?/model_id? | link 列表 |
| `delete_knowledge_link` | id | 撤销引用（幂等） |
| `audit_due_for_system` | system_id | {due: bool, signal: AuditSignal}（v0.13.4 的前置读） |

**注册**：lib.rs `invoke_handler` 追加 + `mod commands_knowledge;`；单文件超 300 行拆 `commands_knowledge_systems.rs`（systems/nodes）与 `commands_knowledge_core.rs`（concepts/models/links/audit）。

## 五、UI 层（KnowledgePage + 创建向导）

- **入口**：NotesPage 同级导航新增「体系」；`App.tsx` 路由追加（三时钟纪律：体系页每周/季度视图，不与每日复习面混排）。
- **KnowledgePage 布局**（最小可用）：
  - 左：领域体系列表（名称/核心问题/计数/状态徽标；全局体系置顶固定）
  - 中：问题树（节点树 + 展开折叠 + 每节点挂载引用数；节点类型中文标签：问题/场景/领域入口）
  - 右（可折叠）：选中节点/概念/模型的详情面板 + 引用列表（`link_knowledge_target` 入口：组选择器 + 类型切换）
- **创建向导**（`KnowledgeSystemWizard`，三步）：
  1. 核心问题域：一句话（指引文案引用指南 §4.1，"不预填内容——预填＝假燃料"）
  2. 领域入口：3–5 个（自动生成 3 个空行，允许全部跳过）
  3. 本周第一个输出：文本（可选；落为 `knowledge_nodes(type=scenario)` + 一条提醒）
- **空态**：无体系时整页引导向导；已有体系且零节点时树区显示"从子问题开始"（引用指南附录A 提示，不预填）。
- **知识体系层级 UI 原则**（竞品调研 §五）：树＋列表，**不做图可视化**；标签/卡片质感=决策仪表盘，非 Notion 文档树。
- 前端文件：`types/knowledge.ts`（System/Node/Concept/Model/Link 接口，与 command 参数类型同名）＋ `pages/KnowledgePage.tsx` ＋ `components/KnowledgeSystemWizard.tsx` ＋ `components/KnowledgeTreeView.tsx` ＋ `components/KnowledgeDetailPanel.tsx`；`api` 封装沿用（若现有 invoke 封装模式）。

## 六、测试策略

- 纯函数全 TDD（AAA + golden）：§三 列出全部 golden 边界（audit_due 5、concept_stale 4、promote_rules 4 组）。
- 数据层 `:memory:` 库：六表 CRUD；约束用例——global 唯一（第二 global 创建报错）、概念 name 唯一冲突、节点 parent 跨体系拒绝（command 层）、级联删除（删体系→子表清空；删节点→子树清空且 links.node_id=NULL）。
- command 层：参数校验（id≤0/白名单/空名/超长/global core_question 缺失/链接 target 不存在）；错误信息含业务语义（沿用现有 AppError 模式）。
- 前端 vitest：向导三步表单校验（core_question 必填、领域行去重）；树组件展开/折叠与节点渲染。
- 模型零依赖（无 AI、无网络）；`cargo test --test app_lib_tests` + `tsc --noEmit` + vitest + vite build。

## 八、验收（真机走查，REQ-146 批内）

1. 创建全局体系（必填核心问题）→ 二次创建全局被拒；创建领域体系挂全局。
2. 问题树：添加三层子问题/场景节点；移动顺序；删除子树确认。
3. 概念/模型 CRUD：概念重名冲突提示；模型 disciplines 多学科 JSON。
4. 引用：组/笔记/卡/碎片 四类 target 引用到节点与概念；目标删除后引用键保留（ON DELETE SET NULL 语义验证）。
5. 审计探测：`audit_due_for_system` 在 90 天边界返回 due（测试内以注入时间验证；真机验证命令存在与返回值结构）。
6. 回归：notes/组/闪卡/复习面全链路不变（零破坏验证）。
