```

        audit_due / concept_stale 已交付（本版接线不重写）

       交叉点提示条 + FeatureFlagSetting 开关 + RouteInfoPopover 结算第三步
```

硬约束（写入每层实现）：
- **审计＝体系级结算**：与 `settlement_due`/`settlement_plan`/`execute_settlement` 同范式（plan→确认→execute）。审计产出**建议**，用户确认后生效；**无确认不生效**。无 streak、无惩罚继承（弹性承诺纪律 §七防线）。
- **零破坏**：`knowledge_audits` 表已存在（id/system_id/items_json/stats_json/created_at），本版**零新表**——建议/清单结果持久化**存 `items_json`（JSON 列表）**；`metrics_events.kind` 为 TEXT（无 CHECK），新增 `system_audited` 值**无需 schema 变更**。裁决：不需要新表。
- **确认动作白名单**：`execute_system_audit` 自动生效的确认动作**只允许**——降级/归档概念、更新体系状态、记 `system_audited` 指标。其余建议（模型边界修订/问题移除/问题新增/交叉点更新/核心问题调整）**本版不自动生效**，仅记录供用户手动走 CRUD。
- **命名纪律**：system/concept/model/link/audit/hint 术语贯穿全栈，Tauri command 与 TS 类型同名。

## 二、数据层（零新表）

- `knowledge_audits`：`items_json` 存 `AuditChecklistInput[]`+`AuditSuggestion[]`（JSON 列表）；`stats_json` 存 `AuditReportStats`+`结构统计`。**裁决：不需新表**（建议项是审计快照，随审计行留存；可追溯即够，不做独立建议表）。
- `metrics_events`：`add_metric_event("system_audited", payload)` 已有；payload=`{systemId, confirmedCount, thinking, learning}`。零 schema 变更。
- 读数聚合（复用既有接口）：`list_knowledge_concepts`/`list_knowledge_links`/`count_metric_events`/`list_knowledge_audits`。

## 三、原子层纯函数（TDD golden 先行，全部 added to `knowledge_pure.rs`）

线宽豁免登记：`knowledge_pure.rs` 现 174 行，新增三函数＋golden 预估超 300 行 → 拆 `knowledge_audit_pure.rs`（audit_checklist/cross_point_hint/merge_audit_report）与 `knowledge_pure.rs`（audit_due/concept_stale/promote_rules），登记线宽豁免清单。

```rust
// ===== audit_checklist: 六项清单评估 → 建议 =====
#[derive(Clone,Copy,PartialEq,Eq)] pub enum AuditCheckItem {
  ConceptsUnused,          // 哪些概念最近一次都没用过？→ 降级或删除
  ModelsFailed,            // 哪些模型在决策中反复失效？→ 修改边界或替换
  ProblemsOutdated,        // 哪些问题已不再重要？→ 从问题树移除
  NewProblems,             // 哪些新问题出现？→ 补充进问题树
  CrosspointStale,         // 两个领域之间的交叉点是否更新？→ 更新交叉概念
  CoreQuestionStill,       // 当前核心问题域是否仍然适用？→ 调整优先级
}
#[derive(Clone,Copy,PartialEq,Eq)] pub enum AuditEntityType { Concept, Model, Node, System, FreeText }
#[derive(Clone,PartialEq,Eq)] pub struct AuditResolution {
  pub entity_type: AuditEntityType, pub entity_id: Option<i64>,
  pub detail: String,               // 依据（如"已 200 天未应用"）
  pub suggested_status: Option<ConceptStatus>, // 由调用方 concept_stale 派生（降级/归档目标）
}
#[derive(Clone,PartialEq,Eq)] pub struct AuditChecklistInput { pub item: AuditCheckItem, pub resolution: Option<AuditResolution> }
#[derive(Clone,PartialEq,Eq)] pub enum AuditSuggestionKind {
  DowngradeConcept{ concept_id: i64, to: ConceptStatus },  // → watching/archived
  ArchiveConcept{ concept_id: i64 }, ReviseModelBoundary{ model_id: i64 },
  RemoveProblem{ node_id: i64 }, AddProblem{ text: String },
  UpdateCrosspoint{ concept_id: i64 }, AdjustCoreQuestion{ question: String },
  ReviewSystemStatus{ to: SystemStatus },
}
#[derive(Clone,PartialEq,Eq)] pub struct AuditSuggestion { pub kind: AuditSuggestionKind, pub from_item: AuditCheckItem, pub reason: String }
pub fn audit_checklist(items: &[AuditChecklistInput]) -> Vec<AuditSuggestion>;
// 规则：对有 resolution 的项产出对应建议；无 resolution 跳过；从建议只到需确认（不自动生效）。
// golden(≥8)：①ConceptsUnused+Archive→ArchiveConcept ②ConceptsUnused+Watching→DowngradeConcept
// ③ModelsFailed→ReviseModelBoundary ④ProblemsOutdated→RemoveProblem ⑤NewProblems→AddProblem
// ⑥CrosspointStale→UpdateCrosspoint ⑦CoreQuestionStill→AdjustCoreQuestion ⑧空输入→空 ⑨混合三项→三条按项序

// ===== cross_point_hint: ≥2 体系引用判定 =====
#[derive(Clone,PartialEq,Eq)] pub struct ConceptCrossSignal {
  pub concept_id: i64, pub concept_name: String,
  pub system_ids: Vec<i64>,         // 调用方聚合：{home_system_id} ∪ {links.concept_id=id → system_id} 去重
}
#[derive(Clone,PartialEq,Eq)] pub struct CrossHint { pub concept_id: i64, pub name: String, pub system_ids: Vec<i64> }
pub fn cross_point_hint(signals: &[ConceptCrossSignal]) -> Vec<CrossHint>;
// 规则：distinct(system_ids).len() >= 2 才产出提示；同体系多 link 去重后不误报（len==1 → 不提示）。
// golden(≥5)：①空/0 体系→无 ②[A]→无 ③[A,B]→[A,B] ④[A,B,C]→[A,B,C] ⑤[A,A,A]→无（同体系多 link 不误报） ⑥[A,A,B]→[A,B]（去重）

// ===== merge_audit_report: 思辨 vs 学习并列 =====
#[derive(Clone,Default,PartialEq,Eq)] pub struct AuditSystemStats {
  pub concept_count: u64, pub node_count: u64, pub model_count: u64, pub ref_count: u64, // 结构上下文（报告列头/诚实性交叉）
}
#[derive(Clone,Default,PartialEq,Eq)] pub struct AuditMetricCounts {
  pub concept_promoted: u64, pub decision_logged: u64,   // 思辨
  pub card_reviewed: u64, pub fragment_upgraded: u64, pub application_logged: u64, // 学习
}
#[derive(Clone,PartialEq,Eq)] pub struct AuditReportStats {
  pub thinking_actions: u64,   // = concept_promoted + decision_logged
  pub learning_actions: u64,   // = card_reviewed + fragment_upgraded + application_logged
  pub system_audited: u64,     // 审计执行次数（§八观察指标）
}
pub fn merge_audit_report(stats: &AuditSystemStats, metrics: &AuditMetricCounts) -> AuditReportStats;
// 规则：思辨/学习由 metrics 求和；stats 只作结构上下文透传（不在输出内做推断——诚实，避免"结构越多=学得越好"去关联）。
// golden(≥4)：①全 0→0/0 ②仅思辨(3+2)→5/0 ③仅学习(10+4+2)→0/16 ④混合→正确求和
```

**接线语义（audit_due/concept_stale 已交付，本版只接线不重写）**：
- 审计清单"概念失效"项 = 对该体系每个概念跑 `concept_stale(StaleSignal)`（信号由调用方聚合：last_referenced_at 来自 knowledge_links.concept_id 命中或 decisions.used_refs 引用、last_applied_at 来自 concepts.last_applied_at、created_at 按 concepts.created_at、now 注入）；`Watching`→DowngradeConcept(to=watching)，`Archive`→ArchiveConcept。
- 交叉点项 = 对该体系概念跑 `cross_point_hint`（≥2 体系）→ UpdateCrosspoint。
- 清单其余四项（模型失效/问题过期/新问题/核心问题）由用户审计时人工勾选结论。

## 四、系统层命令表（commands_knowledge_core.rs）

| 命令 | 入参校验 | 返回 | 说明 |
|---|---|---|---|
| `system_audit_plan` | system_id>0；体系存在 | `AuditPlan{due, signal, checklist[6], suggestions, nextAuditAtMs}` | 预填探测（概念失效/交叉点）+ 六项清单 + 建议（待确认）。`next_audit_at_ms=基线+90天`（基线=last_audit.unwrap_or(created_at)） |
| `execute_system_audit` | system_id>0；items 为 JSON（六项勾选）；confirmed 为建议 kind 列表 | `AuditResult{audited, applied, stats}` | **事务**：①落 `knowledge_audits` 行（items_json=清单+建议，stats_json=合并统计）②应用 confirmed 白名单动作（降级/归档概念→`update_knowledge_concept`；体系状态→`update_knowledge_system`）③`add_metric_event("system_audited")` ④下次基线=本行 created_at（latest_audit_at_ms 自动前移）。**confirmed 为空=仅记录不生效** |
| `cross_point_hints` | system_id?（None=全库）；**读 `feature_flags.cross_point_hint`，为 false→`{enabled:false,hints:[]}`** | `CrossPointHintsResult{enabled:bool, hints:Vec<CrossHint>}` | 后端不信前端隐藏（开关二次校验）。数据：全量概念 → 聚合 system_ids（home_system ∪ links.concept_id=id→system_id 去重）→ `cross_point_hint` |
| `audit_report` | system_id>0；体系存在 | `AuditReport{systemId, stats, structure, history[audits], lastAuditAtMs}` | `merge_audit_report(count_metric_events 各 kind)` + 结构计数 + `list_knowledge_audits` |

**注册**：`lib.rs` invoke_handler 追加四命令。`commands_knowledge_core.rs` 现 474 行（已豁免 300-600 带），新增超 600 → 拆 `commands_knowledge_audit.rs`（四审计命令）并更新豁免清单。

**组结算第三步增强（commands_settlement.rs）**：`settlement_plan` → 在 `settlement_plan_inner` 聚合"引用本组的体系"的失效概念（`knowledge_links.target_type=note_group AND target_id=group_id → system_id` 去重 → 该体系概念 `concept_stale`），作为 `concept_failure_candidates: Vec<ConceptFailureView>` 加入 `SettlementPlan`；`SettlementResult` 补 `conceptDowngraded: usize`。`execute_settlement` 在应用碎片归档后，应用确认的概念降级/归档（复用 `update_knowledge_concept`）。**第三步=低价值归档（v0.11 spec §5.2 第 3 步）的增强——概念失效检查与其并行呈现，仍走"建议+确认"。**

## 五、UI 层

- **KnowledgePage 审计入口**：`SystemCard` 增 `audit_due` 徽标（📋 该审计）；选中体系时详情区/右上"审计"按钮打开 `KnowledgeAuditPanel`。

- **GroupSidebar/RouteInfoPopover 结算第三步**：`settlement_plan` 呈现区增"概念失效检查"节（失效概念+待观察/归档建议），确认按钮并入既有"执行结算"确认流。
- 前端类型：`types/knowledge.ts` 增 `AuditPlan/AuditCheckItem/AuditSuggestion/CrossHint/AuditReport` 接口（与 command 参数同名）。

## 八、验收（真机走查，REQ-146 批内）

1. 体系到 90 天 → `audit_due` 给 due；打开审计清单（六项逐字预填探测）。
2. 概念失效：曾应用/长期未应用的概念 → 降级/归档建议；确认后状态变更+`system_audited` 指标+审计行落库。
3. 无确认执行（confirmed 空）→ 仅落库不生效（验证"确认制"）。
4. 交叉点：同名概念被 ≥2 体系引用 → 概念详情提示条（默认关，设置页打开后可见）；同体系多 link 不误报。
5. 审计报告：思辨 vs 学习两栏并列；历史审计列表。
6. 组结算：第三步出现"概念失效检查"区；确认后概念降级/归档并入结算。
7. 回归：体系/组/笔记/闪卡/复习面链路不变（零破坏）。
