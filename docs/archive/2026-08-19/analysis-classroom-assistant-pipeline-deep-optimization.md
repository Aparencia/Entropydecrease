## 1. 三阶段现状快照（代码级）

### 1.1 预处理阶段（信号 → 引擎输入）

```
音频: WASAPI环回(格式防御/声道选优/线性重采样16k/200ms切块)
      → 音频预处理链(AGC/削波/动态阈值, 默认关, env ENTROPY_AUDIO_PREPROC)
      → VAD阈值自适应(P10噪声底×3, 上限0.05) → 静音判定(原始样本RMS)
屏幕: DXGI(→GDI降级/周期重建) → 网格差异(32×18格, ADR-011)
      → 双速率采样调度(档案查表) → 动态ROI(RoiTracker: 播放区域+bbox聚簇锁定)
      → 字幕区裁剪/960px缩小 → (面板/前台切换/UI垃圾门控)
导入: 字幕探测(L1外挂/L2内嵌, ADR-008) → 字幕直出 或 分窗ASR(30s窗)
      → 关键帧OCR(中部full+底部subtitle两路)
```

**关键实现文件**：`capture/audio_loopback.rs`、`capture/resample.rs`、`audio_preprocess.rs`、`vad_adaptive.rs`、`capture/dxgi_capture.rs`、`capture/grid_diff.rs`、`region_tracker.rs`、`import.rs`、`import_frame.rs`。

### 1.2 核心处理阶段（引擎 → 文本事件）

```
流式ASR: partial节流(≥150ms) → 端点断句(rule1/2/3) → SenseVoice重打分(3s超时,
         前缀扩展/短句放宽/40%门限) → 标点恢复(可选) → asr_clean净化
          → 跨final去重 → 语义合并(merge-then-split, 链式上限4)
字幕OCR: ROI裁剪 → 内存OCR → is_ui_junk源头过滤 → 滚动检测(LCS≥0.6)
          → 多帧加权投票(REQ-065) → 切换/停止时定稿落库
全帧OCR: 版面分析(layout_analyzer+缓存) → 分区域OCR(≤4区, 表格2x放大)
          → 整帧兜底(has_useful_blocks判定) → 新颖度过滤(REQ-066)
          → 关键帧样本+归档(aHash+dHash双指纹)
融合: 字幕权威 → ASR补缝(gap≥1s) → 重叠概率加权(REQ-062) → 时间窗文本切分
      → replace_segments单事务原子替换
```

**关键实现文件**：`streaming_asr.rs`、`asr_rescore.rs`、`asr_clean.rs`、`asr_dedupe.rs`、`asr_merge.rs`、`subtitle_ocr.rs`、`live_frame_process.rs`、`region_ocr.rs`、`fusion.rs`、`live_keyframes.rs`、`engine.rs`。

### 1.3 后处理阶段（会话停止 → 笔记/产物）

```
停止: drain 8s宽限 → flush尾句(补重打分) → 音频finalize+磁盘清理 → 后台融合
      → 关键帧投票top5(session:keyframes)
笔记: note_filter过滤链(UI垃圾/碎片≤2字/低置信<0.6/相邻重复合并)
      → AI复核(边界段六类分类 → 云端三态keep/delete/merge, 授权默认关)
分析: 章节(30s窗近似信号+状态机) / 重点(重复短语+音量骤变[未接线]+OCR停留)
      / 术语(TF-IDF+缩略词+水印排除) / 讲者(空转——恒传空数组) / 练习段 / 书面化
产物: 水印过滤(区域稳定性×文本不变性) → 大纲(短文本启发式) → 质量报告
      → 五档案模板(artifact_templates) → 课后精修(表格/公式模型版)
```

**关键实现文件**：`live_session.rs`、`live_keyframes.rs`、`note_filter.rs`、`ai_text_filter.rs`、`watermark_filter.rs`、`analysis.rs`、`quality_report.rs`、`outline.rs`、`chapter_detect.rs`、`refine.rs`。

## 2. 预处理阶段：缺陷定位与深度优化空间

### 2.1 已定位缺陷（实现层）

| # | 缺陷 | 证据 | 影响 |
|---|------|------|------|
| PRE-D1 | **音频预处理链（AGC/削波/动态阈值）生产未启用**：`AudioPreprocessor` 默认关，仅 env `ENTROPY_AUDIO_PREPROC=1` 开启；REQ-041 承诺"微基准定默认"从未执行，v0.4 承诺的配置 UI 未落地 | `audio_preprocess.rs` L9-14、`live_session.rs` L331-338 | 功能悬空；低音量课程（12.wav 取证）VAD 截断无兜底 |
| PRE-D2 | **线性重采样无抗混叠滤波**：48k→16k 线性插值未先低通，高频混叠污染 VAD 静音判定与 ASR 前端 | `resample.rs` `resample_linear` | 高频辅音/噪声边界质量损失 |
| PRE-D3 | **声道选优按整块 RMS**：音乐/噪声声道能量可能高于语音声道 → 选错声道丢语音；无语音活性（频谱/持续性）辅助 | `resample.rs` `mixdown_prefer_cleanest` | 立体声课程误选声道 |
| PRE-D4 | **健康监测与 VAD 判定口径分裂**：`asr_health` 用固定阈值 0.005 判"有语音"，VAD 用自适应阈值——降级提示触发条件与实际切段条件不一致（注释自认有意为之，但产生"VAD 已切段但健康监测认为无语音"的错位） | `live_session.rs` L511-518 | 降级提示时序失真 |
| PRE-D5 | **24bit 音频格式不支持**：`pcm_bytes_to_f32` 对 24bit 返回 None 且仅首次打日志——整段音频静默丢弃 | `resample.rs` L149-172 | 罕见设备整段丢失 |
| PRE-D6 | **采样节拍固定 1s**：字幕区最高 2fps，快速切换字幕（<500ms 停留）可能一帧采不到；drain 后无补采 | `live_session_frame.rs` `SAMPLE_TICK_MS` | 快速字幕漏帧 |
| PRE-D7 | **导入链路 OCR 无净化**：`import_frame::ocr_keyframe` 直接落库，播放器时间码/水印/UI 垃圾会进 OCR 块（与实时链路 REQ-083 不对齐） | `import_frame.rs`（无 is_ui_junk 调用） | 导入会话画面要点污染 |

### 2.2 深度优化空间（按杠杆排序）

| # | 优化 | 原理 | 成本/风险 | 备注 |
|---|------|------|----------|------|
| PRE-O1 | **音频预处理链闭环启用**：用已落盘 S4 音频做**离线 CER 微基准**（数据已就绪！）→ 定 AGC/动态阈值默认值 → 出设置 UI 开关 | "先测后优"原则落地；REQ-041 从悬空变闭环 | 低（基准脚本+UI）；风险：环回成品音频降噪可能伤音质——基准数据说话 | 与 v0.6.0 M4（S4 落盘）直接衔接 |
| PRE-O2 | **抗混叠重采样升级**：线性插值 → 带限低通+抽取（sinc/分段多项式）；或复用 sherpa 前端已有 resampler | 消除混叠对 VAD/ASR 的隐性污染 | 低-中；需基准对比（与 PRE-O1 共用基准） | 独立纯函数，可单测 |
| PRE-O3 | **声道选优加语音活性维度**：RMS × 语音带能量（300-3kHz 占比）联合判定，替代纯 RMS | 防音乐/噪声声道压过语音声道 | 低（纯 DSP）；需实测校准 | 与 A2 声道策略延续 |
| PRE-O4 | **VAD/健康监测口径统一**：健康监测改用与 VAD 相同的自适应阈值 + 暴露"当前阈值"到诊断 | 消除降级提示与切段判定错位 | 低 | 涉及 asr_health 改造 |
| PRE-O5 | **24bit/8bit 格式支持**：补 PCM24 左对齐解包（罕见但低成本防御） | 消除"不支持却静默" | 极低 | 防御性编程 |
| PRE-O6 | **导入链路净化对齐**：import_frame 落库前过 is_ui_junk + 水印候选标记（与实时链路同口径） | 导入/实时双入口口径统一 | 低 | REQ-083 同表 |
| PRE-O7 | **采样预算事件化**：网格差异变化率 → 下一 tick 采样档位动态调整（变化密集提频、静止降频），替代纯档案静态预算 | 预算花在变化上；快速字幕漏帧缓解 | 中（调度器改造） | 与 M4 预算制衔接，避免与深化方向 M17 重复（那是倍速感知） |

## 3. 核心处理阶段：缺陷定位与深度优化空间

### 3.1 已定位缺陷（实现层）

| # | 缺陷 | 证据 | 影响 |
|---|------|------|------|
| CORE-D1 | **ASR 置信度是硬编码假数据**：`persist_final` 全部写死 `0.9`（正常段）/`0.8`（flush/兜底）；import 路径 `Some(0.9)`——**不是模型输出**。REQ-062 概率加权融合的 P(ASR)、note_filter 低置信过滤、quality_report 低置信列表全部消费这个假值 → 置信度体系在 ASR 侧是空的 | `live_session.rs` L140/L596/L655、`import.rs` L181 | **严重**——融合决策、过滤、质量报告三处失真 |

| CORE-D4 | **字幕段投票置信度不落库**：`persist_voted_subtitle` 落库 `confidence: None`——字幕投票算出的真实置信度在 session_segments 表中丢失，质量报告/低置信过滤覆盖不到字幕段 | `live_frame_process.rs` L478-485 | 中——字幕域无置信度可审计 |
| CORE-D5 | **DTW 时序对齐未接入生产**：机制先行但无收益验证路径（spike 状态），字幕 end_ms 滞后问题仍靠"下一字幕补齐"近似 | `dtw_align.rs` L7-15 | 中——已知未决 |
| CORE-D6 | **滚动字幕检测误杀风险**：LCS ≥0.6 判滚动——快速切换的正常字幕（相邻帧共享词多）可能被当滚动丢弃 | `subtitle_ocr.rs` `is_scrolling` | 低-中 |
