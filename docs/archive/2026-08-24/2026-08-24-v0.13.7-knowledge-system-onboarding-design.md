# v0.13.7 设计规格：知识体系上手路径（入口补全 + 具象化）

> 状态：**已批准**（2026-08-24，依据用户头脑风暴裁决：入口缺失 + 体系难上手双问题；v0.13 系列内小版本）
> 关联：[v0.13 系列文档](../../versions/v0.13.md) · [v0.13.1 基建规格](./2026-08-23-v0.13.1-knowledge-system-foundation-design.md) · [ADR-024](../../adr/ADR-024-knowledge-system-layer.md)
> 范围：v0.13.7——体系上手路径优化。**不含** v0.13.4 审计 UI、v0.13.5 书籍、图谱可视化。

## 一、问题定义

用户反馈 v0.13 知识体系层"不知道怎么上手、抽象难懂"。经代码核实，根因有二：

1. **入口缺失**：体系能力（页面/命令/升格/决策）已建好，但孤立在体系页内——组、笔记、结算三条日常动线无任何触达体系的方式；用户使用体系只能主动打开体系页。
2. **体系本身难上手**：① 创建后是空壳（向导产出无参照物，问题树/概念库/模型库全空且引导语抽象）；② 术语学术化（问题树/三问/模型 claim 非用户语言）；③ 引用能力 UI 面向开发者（挂笔记需手工输入笔记 id）。

**设计目标**：让用户感觉"我不是在搭一个新东西，我是在把已经学的东西理出结构"。

## 三、设计总览

两部分、五改动，全部前端 + 零新命令、零新表（复用 `link_knowledge_target` / `delete_knowledge_link` / `list_knowledge_links` / `list_knowledge_systems` / `create_knowledge_system` / `add_knowledge_node` / `add_knowledge_concept` / `add_knowledge_model` / 既有决策命令）：

```
Part A 入口补全（三触点）
  ① GroupSidebar 组行体系徽标
  ② NotesPage 笔记详情「挂到体系」
  ③ RouteInfoPopover 结算体系简报
Part B 具象化
  ④ 摄影示例体系（浏览 + 一键复制）
  ⑤ 向导内嵌示例（每步「例如」参照）
```

## 四、Part A：入口补全

### 触点 ① 组行体系徽标（GroupSidebar）

- 组行小字区（类别徽标旁）新增体系徽标：`🧭 体系名`（teal 配色，同体系页），**仅有关联时显示**——无关联不显示，零噪音、无负向提示。
- 数据源：`list_knowledge_links({ targetType: "note_group", targetId: g.id })` 返回该组的引用；体系名由前端从已加载的 systems 列表按 link.systemId 映射（GroupSidebar 需新增一次 `list_knowledge_systems` 拉取）。
- 交互：点击徽标 → 跳转体系页并选中对应体系（**App.tsx 既有跨页传参模式**——GroupSidebar 新增 `onOpenSystem(id)` 回调，App 层 `setFocusSystemId(id)` + `setPage("knowledge")`，与 `focusNoteId`/`focusSessionId` 同模式；KnowledgePage 接收 `focusSystemId` prop，useEffect 初始化 selectedSystemId）。
- 反馈（F）：tooltip 显示"该组为体系「X」提供 N 处引用"。
- 文件：`GroupSidebar.tsx`（+ 可能新增小组件 `SystemBadge.tsx`）。

### 触点 ② 笔记详情「挂到体系」（NotesPage 右栏）

- 笔记阅读视图右栏新增「挂到体系」按钮（次要样式，与删除/编辑同排）。
- 点击弹出轻量选择器（新建 `NoteLinkToSystem.tsx`）：
  1. 选体系（list_knowledge_systems；全局置顶）
  2. 选该体系下节点（list_knowledge_nodes 树形展示；可跳过=挂体系根）
  3. 确认 → `link_knowledge_target({ systemId, nodeId?, targetType: "note", targetId: 当前笔记.id })`——**用户零 id 知识**（修复手工输 id 断点）
- 成功后：按钮变"已挂 · 体系名"，可点击取消（`delete_knowledge_link`）。
- 反查已挂状态：`list_knowledge_links({ targetType: "note", targetId })`。
- 独立组件不改造 KnowledgeLinkSection（其绑定体系页实体上下文）；后端零新命令。

### 触点 ③ 结算体系简报（RouteInfoPopover 结算区）

- 结算计划呈现区下方新增体系简报卡，两行只读提示（纯提示，不自动升格/归档——AI 测量人类见证）：
  - 行 1（升格候选）：`🧬 本组有 N 张 model 卡可纳入体系`——组内 `flashcards.kind='model'` 且未升格计数（前端计算或复用既有查询）。
  - 行 2（失效预警）：`⏳ 体系「X」有 N 个概念 90 天未引用`——`concept_stale` 信号由前端聚合（concept.last_applied_at + 引用时间）；仅在有体系引用该组时显示。
- 交互：行 1 点击跳转体系页概念列表；行 2 点击跳转体系页。
- 纪律：结算只做提醒，动作留用户；无 streak、无惩罚。

## 五、Part B：具象化

### 5.1 摄影示例体系

**预置完整「摄影」领域体系**，作为用户理解体系的具象参照物。内容（前端常量 `knowledgeSample.ts`）：

```
领域体系「摄影」
├─ 问题树：
│  ├─ [问题] 照片为什么发灰、不通透？
│  │   ├─ [问题] 怎么判断一张照片曝光是否准确？
│  │   └─ [问题] 高光溢出了怎么办？
│  ├─ [问题] 为什么拍人像背景虚化不了？
│  ├─ [问题] 构图总是很平淡怎么办？
│  └─ [场景] 本周修好 10 张发灰的旅行照
├─ 概念库（三问填好）：
│  ├─ 「曝光三角」本质=光圈/快门/ISO 平衡光量；边界=不影响景深的是 ISO；联系=后期降噪的基础
│  ├─ 「安全快门」本质=1/焦距 的倒数；边界=有防抖/三脚架时失效；联系=与曝光三角快门联动
│  └─ 「三分构图」本质=主体放 1/3 分割线；边界=对称/居中构图不用；联系=与引导线结合
├─ 模型库：
│  └─ 「黄金时刻法则」claim=日出日落前后 1 小时光质最佳；valid_when=户外自然光；invalid_when=室内闪光灯/阴天想拍蓝调
└─ 决策日志（1 条示例）：
   └─ [应用] 用「曝光三角」判断朋友照片发灰；实际=欠曝一档提亮通透；反思=先看直方图再调参数
```

**交互**：
- 入口：体系页空态时，示例体系卡片与「创建第一个体系」按钮并列（"先看看摄影示例"）；已有体系时入口收敛到向导旁或侧栏底部（不打扰）。
- 两种模式：
  - **浏览模式**（默认）：只读展示完整示例（树/概念/模型/决策全部填好）——用户理解"体系长什么样"。
  - **一键复制**：按钮「📋 复制为我的体系」——逐条调既有 commands 创建真实体系（create_knowledge_system(kind=domain) → add_knowledge_node ×7 → add_knowledge_concept ×3 → add_knowledge_model ×1）；**全局体系前置检查**：若全局体系不存在，先打开全局创建向导（复用 KnowledgeSystemWizard），用户完成全局创建后再继续复制（复制链路阻塞等待，避免出现无根的领域体系）。
  - 复制后体系处于**待改造**状态（用户改不改、怎么改完全自主）。
- 实现：`knowledgeSample.ts` 常量 + `KnowledgeSampleView.tsx`（浏览）+ 复制逻辑（复用既有 invoke 序列）。零新命令、零新表。

### 5.2 向导内嵌示例（KnowledgeSystemWizard）

三步向导每步指引文案下方新增「例如」参考行（**纯参照，不写入输入框**——用户仍需自己输入）：

| 步骤 | 例如文案 |
|---|---|
| ① 核心问题 | 例如："如何让化妆又快又自然？" |
| ② 领域入口 | 例如："底妆 / 眼妆 / 发型" |
| ③ 第一个输出 | 例如："本周完成一个 5 分钟通勤妆视频" |

**纪律裁决（本版批准）**：示例 ≠ 预填。预填=把内容写进用户输入框（假燃料，禁止）；示例=用户可见的完整参照物（真燃料，允许）。浏览示例是被动的（看别人怎么搭）；复制示例是主动的（一键获得骨架，改不改由用户决定）——复制后体系处于"待改造"状态，不是"已完成"状态。需同步修订：v0.13.md 系列文档 + v0.13.1 规格 §五 注释口径 + KnowledgeSystemWizard @ai-context 注释。

## 六、测试策略

- 前端 vitest：
  - GroupSidebar：无关联不显示徽标；有关联显示体系名与引用计数；点击触发跳转回调。
  - NoteLinkToSystem：选择器三态（无体系提示/选体系/选节点）；成功后按钮文案切换；取消后回退。
  - RouteInfoPopover：简报两行（model 卡计数、90 天未引用提示）条件渲染。
  - knowledgeSample：常量结构完整性（节点层级/概念三问非空/模型三字段/决策四行）——示例数据即 golden。
  - 复制流程：mock invoke 断言命令序列与顺序（global 前置→system→node×7→concept×3→model×1）。
- 回归：tsc --noEmit + vitest 全量 + vite build；v0.13.1 既有用例不破坏。
- 真机走查（REQ-146 批内）：建全局→看示例→复制摄影→挂组→挂笔记→复习升格→结算简报。
