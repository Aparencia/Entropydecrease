# v0.11.7 设计：图文会话——截屏导入 + 跨链路采集体验同步

> 状态：已批准（用户确认方案 A + kind 字段 + 改进采纳，2026-08-22）
> 依据：课堂助手现有采集动线（实时捕获 / 视频文件导入 / 学习素材）· ADR-004（会话数据模型）· ADR-008（文件导入）· ADR-015（屏卡体系）
> 痛点：图文类内容（网页/PDF/图文教程）无采集路径——视频导入要求视频文件、实时捕获面向视频窗口，图文场景只能靠"选图片"素材走无会话流水线，无法形成会话、无法事后复盘
> 范围：v0.11.7（排期于 v0.11.6 AI 平台化之后）
> 版本规划：本 spec 配套 [v0.11.7 版本文档](../../versions/v0.11.7.md) 与 [v0.11 系列总览](../../versions/v0.11.md) 更新

## 一、总览

课堂助手新增第三采集动线「图文采集」：用户连续框选截屏 → 组成一个 `kind=photo` 的图文会话（无音频）→ OCR 全图识别 → 会话列表可见、可转笔记。同步两项跨链路采集体验改进到视频导入（完成后直达会话页 + OCR 进度携带识别块数）。

```
图文采集面板（课堂助手左栏第三面板）
  ▶ 开始图文采集 → start_photo_session（创建 recording 会话）
  📷 截屏 → capture_screen_snapshot（全屏快照 base64）
        → ScreenSelectOverlay 全屏遮罩框选 → canvas 裁剪 → PNG base64
        → save_photo_capture（存图 + OCR + 落库，返回识别预览）
  ✅ 完成采集 → finish_photo_session（零截图删会话；否则 finish）
```

硬约束（写入每层实现）：

- **数据主权**：截屏内容全部本地处理（GDI 捕获 → 本地 OCR → 本地存储），不出本机
- **三链路 OCR 口径统一**：图文链路与实时/导入链路同口径——OCR 输入缩至 960px 宽、bbox 反算回原图坐标系、低分过滤（score<0.5）
- **截图不过 UI 垃圾黑名单**：用户显式框选的内容即意图（与自动采帧链路不同），`is_ui_junk` 源头过滤不应用于图文截图
- **互斥**：图文采集与实时捕获互斥（共享屏幕内容动线，避免状态混乱）
- **不留空壳**：完成采集时零截图 → 删除会话；崩溃残留（recording 超 24h）→ 列表加载时清扫为 failed

## 二、数据模型（kind 字段）

`sessions` 表新增 `kind` 列，标识会话类型：

| 值 | 含义 |
|----|------|
| `NULL` | 旧数据 / 实时捕获 / 视频导入（默认，零回归） |
| `'photo'` | 图文会话（截屏采集） |

- **迁移**：`ensure_column(conn, "sessions", "kind", "ALTER TABLE sessions ADD COLUMN kind TEXT")`（幂等，`profile` 列同模式）；建表 SQL 同步加列
- **类型穿透**：Rust `Session.kind: Option<String>` / `NewSession.kind`；前端 `Session.kind: string | null`
- `create_session` 签名扩展：`kind: Option<&str>`（既有调用方传 `None`，零回归）

## 三、后端命令（commands_photo.rs + photo_capture.rs）

| 命令 | 职责 | 关键逻辑 |
|------|------|----------|
| `start_photo_session(title?)` | 创建图文会话 → 返回 session_id | 互斥检查（`live_session.active` / 已有图文采集中 → Err）；默认标题「图文会话 MM-DD HH:mm」 |
| `capture_screen_snapshot()` | 全屏快照 → base64 | `capture::gdi_capture(None)`（虚拟屏合并区域，多显示器支持）→ BGRA → RGB → JPEG q0.85 编码 → `{ base64, width, height }` |
| `save_photo_capture(session_id, image_b64)` | 截图落库 + OCR | 解码校验 → `SessionImageStore.save_frame`（full+thumb，双指纹去重，命中返回"重复"）→ 全图 OCR（缩 960px 有界等待）→ OCR 块落库（region=full，screen_id=None 走视图层聚类）→ 返回 `{ duplicated, block_count, preview: [String; ≤3] }` |
| `finish_photo_session(session_id)` | 完成采集 | 零截图 → 删除会话（含图片库）；否则 `finish_session` |
| `discard_photo_session(session_id)` | 放弃采集 | 删除会话（级联子表 + 清理图片库目录） |

### 3.1 关键实现点

- **OCR 输入**：保存原图尺寸到 `full/<ts>.webp`（屏卡显示清晰）；OCR 用缩至 960px 的副本（复用 `import_frame::crop_and_scale` 同款缩放开销）；bbox 按缩放比反算回原图坐标系（TD-046 同思路）
- **OCR 失败降级**：不阻断截图保存——图已落盘，返回 `block_count=0` + 提示；预览取识别文本前 3 条（按置信度排序，去空）
- **重复截图**：`save_frame` 双指纹命中 → 不落新 OCR 块，返回 `duplicated=true` 提示用户（防误触）
- **残留清扫**：会话列表加载时 `UPDATE sessions SET status='failed' WHERE kind='photo' AND status='recording' AND started_at < now-24h`（24h 保证不误伤进行中的采集）；清扫函数注入 `&Db` 可单测
- **互斥注册**：`AppState` 增 `photo_session: Arc<Mutex<Option<i64>>>`；`start_photo_session` 检查并占用；`finish/discard` 释放；实时捕获 `start_live` 增加图文占用检查

## 四、前端交互

### 4.1 图文采集面板（新组件 `PhotoCapturePanel.tsx`，课堂助手左栏）

三态动线（仿实时捕获面板结构）：

```
空闲态：  [▶ 开始图文采集]
采集中：  会话 #12 采集中 · 已截 3 张
         [🖼 最近截图缩略图]（convertFileSrc 预览 full/<ts>.webp）
         [📷 截屏]  [✅ 完成采集]  [放弃]
完成态：  ✅ 已保存会话 #12（3 张截图）
         [去会话页查看]（复用 onOpenSessions prop）
```

- 状态机：`idle → collecting → done`；互斥时开始按钮禁用 + 原因提示
- 截屏后显示识别反馈：「已识别 8 块：预览文本…」；`duplicated=true` 显示「与上一张内容相同，未重复保存」
- 完成采集后 `onStatus` 上抛 + 「去会话页」直达

### 4.2 全屏框选遮罩（新组件 `ScreenSelectOverlay.tsx`）

复用 `BoxSelectOverlay` 交互范式（拖框 + 确认浮层 + CSS 放大镜预览）：

- 快照图 **letterbox 缩放适配**显示（窗口内 fixed 覆盖，第一版不做真实全屏窗口——YAGNI）
- **DPI 换算**：归一化坐标按**图像物理像素**换算（Windows 125%/150% 缩放下 GDI 捕获为物理像素、CSS 显示为逻辑像素——`selectedPixels = normalized × imagePhysicalSize`，不经 window.devicePixelRatio）
- 确认 → canvas 裁剪（物理像素矩形）→ **PNG 编码**（无损，OCR 友好；快照显示用 JPEG 仅省流量）→ base64 → `save_photo_capture`
- Esc / ✕ 取消关闭；保存中禁用交互防重复提交

## 六、跨链路采集体验同步（视频导入）

| # | 同步项 | 改动 |
|---|--------|------|
| 1 | 导入完成后「去会话页」直达 | `VideoImportPanel` 增加 `onOpenSessions` prop；完成态文案旁加直达按钮（与图文面板共用交互） |
| 2 | OCR 进度携带识别块数 | `import.rs` ocr 阶段进度消息「画面识别 x/y」→「画面识别 x/y · 已识别 N 块文字」（累计块数经 `&mut` 计数传入 `ocr_keyframes` 回调） |

明确**不同步**（核实结论）：

- PNG 无损：实时链路原始帧直喂 OCR、视频导入 ffmpeg 抽帧 PNG——天然无损，仅图文链路（canvas 裁剪环节）需要
- 960px 缩放：三链路已具备（`live_frame_process.rs MAX_OCR_WIDTH=960` / `import_frame.rs crop_and_scale 960`）——图文链路遵循既有口径即可
- 重复提示：自动链路静默去重（双指纹/帧间文本去重）与手动链路（提示用户）交互性质不同
- DPI 换算：实时链路窗口矩形已用物理像素、屏卡框选为图像坐标——各链路已正确

## 七、错误处理与降级

| 场景 | 行为 |
|------|------|
| 截屏失败（GDI 不可用/远程桌面） | 遮罩不打开，状态条显示原因，会话不受影响 |
| 保存失败（解码失败/超预算） | 提示重试；不破坏会话状态 |
| OCR 失败/超时 | 图已落盘，`block_count=0` + 提示（下张截图重试语义） |
| base64 解码失败 | 前置拒绝（可诊断错误，不落盘垃圾——`capture_fragment` 同模式） |
| 应用崩溃残留 recording | 24h 清扫 → failed（列表加载时） |
| 采集完成零截图 | 删除会话（不留空壳） |
