# 非线性结构图像捕获与持久化（结构图）+ v0.7.7 修复项——头脑风暴与设计规格

**状态**: 已裁决（2026-08-20 用户头脑风暴：方案 A+ 批量+屏内选优；混合触发；会话内图库；两个修复项并入）
**版本**: v0.7.7（0.7 下一个小版本，独立发布，不与 v0.8.0 AI 合并）
**关联**: 版面分析（REQ-047，layout_analyzer.rs 规则版）· 屏卡体系（REQ-155~161，[ADR-015](../../adr/ADR-015-screen-cards-ocr.md)）· 三层图存储（REQ-051/110，image_store）· [ADR-010](../../adr/ADR-010-gap-filling-ai.md)（图语义"必须理解才能还原"→ 本版用"图像即产物"兜底）· REQ-056/058（AI 语义重建 V1.0）

## 一、问题与动机

版面分析（v0.5.0）已能把帧区域分类为 text/table/formula/code/image/unknown，但**非线性文本结构**（含义依赖二维排布、线性 OCR 必然失真的内容）缺少"图像级持久化"闭环：

| 结构类型 | 现状 | 缺口 |
|---------|------|------|
| 表格/公式/代码 | 实时链路已存裁剪图，但仅作精修中间产物（`crop/` 命名空间，REQ-159） | 无持久化记录、无图库消费、无区域级配图基础 |
| 流程图/思维导图/架构图/图表（Image/Unknown） | 完全无裁剪无持久化；OCR 线性文本必然失真；AI 语义重建（REQ-056/058）V1.0 才实装 | **中间缺"图像即产物"兜底**——纯本地铁律下唯一诚实路径是先保存图 |
| 笔记配图 | 只有整帧 full 图（屏段落配图，REQ-160） | 无区域级图（本版不做笔记消费，表留 screen_id 锚点待下版） |

**核心洞察**: 语义重建（V1.0 AI 补缝）之前，"保存图像本身"是本地优先架构下对非线性结构的正确降级——图比线性文本诚实。

## 二、头脑风暴裁决（2026-08-20）

| 议题 | 裁决 |
|------|------|
| 范围 | **两者都要**：结构三类（表格/公式/代码）+ 视觉型图结构（Image 区域）统一获得图像持久化能力 |
| 触发方式 | **混合**：自动覆盖高频（结构三类 + Image 区域过过滤）；手动框选补充低频/漏检 |
| 消费场景 | **仅会话内图库**（浏览/删除）；笔记内联消费留待下版 |
| 手动框选表面 | **屏卡全帧图上框选**（复用屏卡流与 full 图；不碰实时链路） |
| 自动范围 | **结构三类 + Image 区域**（Image 需 `diagram_likeness` 过滤防照片/装饰误收） |
| 实现方案 | **方案 A+**：批量时机 + 屏内多帧选优（详见 §三） |

## 三、方案对比与性能结论

| 方案 | 内容 | 权衡 |
|------|------|------|
| A：纯批量 | 停止后对屏卡代表帧（first_seen）重跑版面分析 → 裁剪入库 | 架构最简；质量上限=屏卡帧 |
| **A+（裁决）** | A + 裁剪源换成**屏时间窗内多归档帧中清晰度最高帧**（pick_sharpest 纯函数） | A 的复杂度拿 B 的大部分质量 |
| B：在线采集状态机 | 实时链路挂 StructureTracker：区域跟踪 + 逐帧清晰度评估 → 最优帧裁剪 | 增量 CPU 小（区域匹配微秒级、清晰度评估复用边缘网格、编码每区域仅一次），但**状态机复杂度与实时链路回归风险大**（与 ScreenTracker/region_tracker 并存；v0.7.5 刚根治停止残留类问题）；且屏卡代表帧已有 novelty 门控（动效中间帧本就不会成为屏卡帧），B 的质量优势被削弱 |

**性能结论（用户提问）**: B 的增量 CPU 负载很小（对比 OCR 数百 ms/次且已被变化检测+冷却门控，B 每帧增量几十微秒），真正的成本是状态机复杂度与实时链路回归风险 → 不选 B。

## 四、设计规格

### 4.1 数据层

**新表 `session_structure_images`**（`ensure_table` 幂等迁移，ADR-014 先例）：

| 列 | 说明 |
|----|------|
| `id` | 主键 |
| `session_id` | 会话（查询主路径，建索引） |
| `screen_id` | 所属屏（NULL=旧数据无屏）——为将来笔记按屏消费留锚点 |
| `kind` | `table` / `formula` / `code` / `image` / `manual`（字符串枚举，**不动** `RegionKind`——版面分析模块零改动） |
| `bbox` | JSON `{x,y,w,h}` 帧坐标 |
| `source_ts_ms` | 裁剪源帧时间戳 |
| `crop_path` | `struct/{ts}.webp` 相对路径 |
| `source` | `auto` / `manual` |
| `created_at` | 入库时间 |

**存储**：`image_store` 新增 `struct/` 命名空间——与 `crop/`（精修中间产物）**语义分离**：`struct/` = 持久化结构图（图库消费），`crop/` = refine 候选。缩略图同步生成（复用现有缩略管线）。

**预算**：独立桶 `STRUCT_BUDGET_AUTO`（常量 80/会话，仅限自动捕获）；**手动框选不设限**（用户主动行为不被预算驱逐）。auto 耗尽即停止本会话后续自动捕获（手动不受影响）。

**去重**：复用 `same_image` 双指纹（aHash+dHash，REQ-067 先例）——同屏同区域多帧候选只存一张；批量重跑幂等。

### 4.2 自动捕获（批量任务）

**触发**：会话停止后自动跑（与 REQ-159 结构精修同节奏）；图库提供"重新捕获"按钮可重跑（去重保证幂等）。

**管线**（新模块 `structure_capture.rs`，纯函数核心 + 命令胶水，单文件 ≤300 行）：

```
capture_session_structures(session_id):
  屏列表（screens 派生查询，屏卡体系产出）
  每屏:
    ① 帧候选：full/ 目录中时间戳 ∈ [first_seen, last_seen] 的归档帧
       （每屏采样上限 8 帧，超出均匀抽样——bound 解码成本）
    ② pick_sharpest(candidates) → 最清晰帧（边缘能量评分，灰度网格复用 frame_features）
    ③ grid_from_bgra（复用）→ analyze_layout（复用）
    ④ 区域过滤：
       - table/formula/code → 直接候选（is_structural）
       - image → diagram_likeness(region_grid) ≥ 阈值 → 候选
       - text / unknown → 跳过（text 走 OCR 线性文本；unknown 归 V1.0 AI 补缝）
    ⑤ 白边裁剪（image_crop 复用）→ WebP → struct/ + thumb/
    ⑥ same_image 去重 → 预算检查 → 入库
```

**`diagram_likeness(region_grid) -> f32`**（新纯函数，阈值 0.5 起步真机调参）：
- 边缘密度：框线/箭头结构多（复用边缘网格概念，frame_features 产出）
- 面积占比：区域面积 / 屏面积 ≥ 阈值（照片贴图与结构图粗分）
- 灰度方差：非纯色（防纯色装饰块误收）
- 三特征加权综合；合成网格单测（流程图样/照片样/纯色样/阈值边界）

### 4.3 手动捕获（屏卡框选）

**交互**：原料屏卡 full 图 → 「框选截取」按钮进入选择模式（`BoxSelectOverlay` 拖框）→ 松开出**确认浮层**（裁剪预览 + 保存/取消，防误触产生垃圾图）→ 保存。

**命令**：`capture_structure_manual(session_id, screen_id, x, y, w, h)`（归一化 0-1 坐标）：
1. 解析屏卡 `image_ref` full 图；缺失 → 明确错误（前端禁用按钮并提示"该屏无图像"）
2. 归一化 → 像素坐标；越界自动钳制；<32×32px 拒绝
3. **按用户框选原样裁剪**（不做白边裁剪——用户意图优先）→ `struct/` + 缩略图
4. 入库：`kind=manual`，`source=manual`，`source_ts_ms=屏 first_seen`，bbox=裁剪框
5. 不设预算上限

### 4.4 会话内图库 UI

**`ImageGallery.tsx` 扩展**（现 105 行，新增独立组件保持单文件 ≤300 行）：
- 新组件 `StructureImageSection.tsx`：结构图网格——kind 徽标（表格/公式/代码/图结构/手动）+ source 徽标（自动/手动）+ 时间 `MM:SS` + 屏号 + 删除按钮 + 「重新捕获」按钮 + 空态提示
- 命令：`list_session_structure_images(session_id)` / `delete_structure_image(id)`（删记录+删文件——文件仅被本表引用，可安全删）/ `capture_session_structures(session_id)`（重跑）
- 大图预览与参考图共用（见 4.6）

### 4.5 修复①：会话列表没有全选框

**现状**：`SessionListPanel` 有逐项勾选 + 批量操作栏（已选 N/批量转/批量删除/取消），无全选。
**设计**：批量操作栏最左加「全选」复选框，**口径 = 当前筛选视图（filtered 集合）**：
- 三态：全部选中（checked）/ 部分选中（indeterminate）/ 未选中
- 点击选中 → `selected` = 当前 filtered 全部 id；再点 → 清空
- 列表视图与课程分组视图共用（filtered 口径一致）
- 段搜索命中视图批量栏隐藏（现状）→ 全选框自然不出现
- 纯前端本地状态（selected 已是本地 Set），**零后端改动**

### 4.6 修复②：参考图片无法查看详情

**现状**：`ImageGallery` 缩略图无任何点击处理，无法查看大图。
**设计**：新组件 `ImagePreviewOverlay.tsx`：
- 点击缩略图 → 遮罩 + 大图（`contain` 适配窗口）
- 信息栏：相对路径 + 时间戳 + 删除按钮
- ESC / 点击遮罩关闭
- 参考图集与结构图区段共用（一处实现两处消费）

### 4.7 降级链（本地优先铁律）

1. 新会话（screen_id + full 图 + 版面信息）→ 全能力自动捕获
2. 旧会话无 screen_id → 屏列表空 → 自动捕获跳过（图库空态）；手动框选需屏卡有图（无图禁用+提示）
3. 无 full 归档帧（图集未开）→ 该屏自动跳过（不阻断其他屏）
4. 版面分析空/失败 → 该屏跳过
5. 全部失败 → 图库空态 + 手动框选仍可用（手动不依赖版面分析）

### 4.8 测试（AAA，纯函数优先）

- `diagram_likeness`：流程图样/照片样/纯色样/阈值边界（合成网格，layout_analyzer_tests 先例）
- `pick_sharpest`：多帧选最大/空列表/全零
- 批量管线：mock 屏+帧 → 候选集/去重/预算耗尽停止/幂等重跑
- 手动命令：越界钳制/最小尺寸拒绝/无 image_ref 错误
- DB：ensure_table 幂等/CRUD/旧库兼容
- 前端：框选归一化坐标纯函数 + 真机手动清单（Vitest 基建维持 v0.8.0 裁决）
