## 1. 问题定义

### 核心问题
v0.8.0 的 AI 精修/知识补充代码建设完成，但**真机不可用**：AI 调用有记录（SiliconFlow 侧产生费用）而返回结果未被实际使用（前端永久"排队中"）；此外存在丢图、成本失真、零审计、配额失控、切片结构错乱等 P1 问题，非功能扩展（任务可恢复性/并发/评测）为零。

### 检测方法
- 全链路代码审查：前端（AiRefineCard/EnrichPanel/AiServicePanel/NotePreviewView/types.ts）→ 命令层（commands_ai_refine/commands_ai_enrich/commands_ai_settings）→ 任务状态机（ai_task）→ 云端适配器（ai_client/ai_note_refine/ai_note_enrich）→ 协议校验（ai_refine_protocol/ai_enrich_protocol）→ 落库（ai_refine_apply/versioned_save/db_ai_usage）
- 契约实证：临时单测实测 serde 序列化输出（已还原）
- 文档对照：v0.8.0 规划验收项逐条核对

### 关键现状（检测结论）
- **P0 契约断裂（已实证）**：`AiTaskState` 带 `#[serde(rename_all = "camelCase")]`，枚举变体名被小写化（`"succeeded"`/`{"running":..}`/`{"failed":..}`/`"pending"`）；前端按 PascalCase 比较（`st === "Succeeded"`、`"Running" in st`、`"Failed" in st`）→ **全部失配**。任务后台真实执行成功（有调用记录、产生费用），前端永不进成功分支 → 永久"排队中" → 结果永不取回/展示/采纳。30s 卡住检测同样失效（`st !== "Pending"` 恒 true）。
- **P0 附：失败原因契约错位**：`AiTaskFailure` camelCase 输出 `{"insufficientBalance":..}`/`{"invalidResponse":..}`，前端期待 `"balance"`/`"invalid"` → 引导文案错位。
- **P1 丢图**：规则草稿含 `- ![画面 N](session-images/...)` 配图行，精修协议仅 5 种文本块、无 image 类型 → 精修版配图全丢。
- **P1 成本失真**：估算只按输入字符；**无模型→单价映射**，切付费模型后确认弹窗仍显示 ¥0 → 实际扣费无感知。
- **P1 零审计**：精修/补充调用不上 `ai_audit_list`（仅余额/测试连接/复核有记录）→ REQ-140 轨迹可见化缺失。
- **P1 配额失控**：精修/补充不消费 DailyQuota；「记住此选择」后完全跳过确认 → 无限烧钱；无任务去重，双击/重进可重复扣费。
- **P1 切片上下文丢失**：多片独立请求，每片输出完整章节结构，合并仅 `\n\n` 拼接 → 章节标题重复、结构错乱。
- **P1 一片失败=全任务失败**：REQ-145「部分失败可单独重试」未实现。
- **P1 任务结果内存态**：任务注册表在 AppState 内存，重启即失。
- **已做对**：授权红线（enabled+authorized 双 gate）、DPAPI 密钥、余额查询+低余额提醒、schema 强校验、降级本地规则版保留、版本链+回滚+成本落库、事件+轮询双通道、闭包 ref 修复、trim_tasks 容量守卫。

### 约束条件
- 本地优先 + AI 为增强层；数据不出本机；AI 调用须用户授权且默认关闭（AGENTS.md 铁律）
- Windows 桌面（Tauri 2 + Rust + React）；单文件 ≤300 行；Rust 侧有 1271 测试基线
- 范围纪律：不铺开新 AI 能力（问答/VLM/闪卡仍排除），聚焦精修/补充一条线做深
- 网络环境：本机 TLS 拦截，新增 crate 依赖受限（DPAPI 先例）

### 成功标准
1. 真机精修全流程走通：预估→确认→任务→diff→采纳落库，无"排队中"卡死
2. 精修版不丢配图；成本显示真实（模型单价映射）；精修/补充调用上审计
3. 任务结果重启可恢复；完成通知可见；长笔记并发提速；单片失败可重跑
4. 协议 v2 向后兼容；结构回归评测全绿；现有 1271 测试不劣化

## 3. 收敛阶段（设计定稿）

### 总体架构：任务中心化（方案 C）

**核心洞察**：P0/P1 多数问题（契约断裂、零审计、无去重、结果易失、无重试）同根——任务注册表是无持久化的内存 HashMap。以「持久化任务中心」为支点，修复项与扩展项统一承接，一次架构动作解决全部问题。

### 3.1 修复层（F0 + F1）

**A1 契约断裂修复（P0，ai_task.rs）**
- `AiTaskState`：去掉 `rename_all = "camelCase"` → 变体名恢复 PascalCase（Pending/Running/Succeeded/Failed），字段保持 snake_case（finished_slices/total_slices）→ 与前端 types.ts 逐字匹配
- `AiTaskFailure`：保持 camelCase，显式 rename 两个变体：`InsufficientBalance → "balance"`、`InvalidResponse → "invalid"` → 与前端四类出口对齐
- **不动** `AiTaskHandle`（taskId camelCase 契约 2026-08-21 已修正确，勿改）
- **新增契约快照单测**：断言 serde 序列化输出等于前端期望 JSON 字面量（本次事故教训，防再断裂）

**A2 丢图修复（双层）**
- 协议 v2 增加 image 块（见 3.3 C2）
- 降级路径：本地合并——精修落库时把规则版 `- ![画面 N](...)` 配图行按章节锚点合并回精修版（协议未返回 image 块时启用，零模型成本）

**A3 成本失真修复（ai_cost.rs）**
- 新增模型→单价映射表（内置：免费档 ¥0、DeepSeek-V3/Qwen3-235B 实测价格；设置页可编辑；env 覆盖保留）
- 预估 = 输入token×单价 + 输出token×单价（输出按输入比例系数粗估）
- 确认弹窗/成本落库统一用映射表单价 → 消灭「切付费模型仍显示 ¥0」

**A4 审计补齐（commands_ai_refine / commands_ai_enrich）**
- 任务完成/失败时 push_audit（op 类型 + task_id + 结果 + 成本）→ 本地审计列表可见精修/补充调用轨迹

**A5 配额接入 + 任务去重**
- 精修/补充任务启动时消费 DailyQuota（按片计，耗尽 → 明确拦截引导）
- 同 session/note 存在进行中任务时拒绝重复启动（防双击/重进重复扣费）

### 3.2 任务中心（F2）

**B1 SQLite 任务表（新表 ai_tasks，迁移）**
- 字段：task_id, op_type(refine|enrich), ref_id(session/note), state, result_json, cost_yuan, elapsed_ms, model, error, created_at, finished_at
- 状态流转与内存注册表同步写（锁内 read-modify-write；写库失败不阻断 AI 调用——内存注册表继续 + 明确日志，见 H2）

**B2 结果恢复**
- 应用启动时从 ai_tasks 恢复未采纳的成功结果 → 前端任务面板可见历史结果，重启不丢
- 保留策略：每类型保留最近 50 条，超限清理旧终态任务（防表膨胀）

**B3 全局任务面板 + 完成通知**
- 前端新增「AI 任务」视图（设置页 Tab 或独立面板）：历史任务列表（时间/类型/状态/成本/模型）、查看结果（diff 预览复用）、重跑入口
- 完成通知：ai:task-update 事件全局监听 + 顶栏角标/提示（跨卡片生效，REQ-145「完成通知」真正落地）

**B4 并发与单片重试**
- 切片并发 2-3（配额计数并发安全改造——v0.8.0 开放问题「切片并发 vs 每日配额」一并解决）
- 单片失败自动重试 1 次（幂等片）→ 仍失败则保留已成功片 + 标记部分成功（partial_failed：x/y 片成功，可重跑失败片；REQ-145 兑现）

### 3.3 协议 v2（F3）

**C1 版本化与向后兼容**
- 响应增加 schema_version: u32（缺省=1，v2 显式=2）
- 反序列化宽容：v1 响应（无 version 字段）仍按 v1 解析 → 旧任务结果/缓存不崩

**C2 image 块类型**
- AiRefineBlockType 增加 Image：content 为本地配图引用（session-images/{sid}/{rel} 相对路径）
- 提示词 v2（note_refine.json）输出约束增加 image 块说明：配图行必须原样保留为 image 块，不得改写路径
- 校验：content 非空、路径须匹配 session-images/ 前缀（防注入）、每节 image 块数 ≤ 5
- to_markdown 渲染为 `- ![画面 N](session-images/...)` 原行 → diff 预览/落库保留配图

**C3 片间上下文字段**
- AiRefineRequest 增加：slice_index, slice_total, prev_summary（前片结尾 200 字摘要）, next_summary
- 提示词约束：本片只整理 content 对应内容，沿用 chapters 全局章节，禁止发明新章节标题
- 合并逻辑升级为「按全局章节归并」（同标题节合并块，不重复输出标题）

### 3.4 成本拦截完整化（F3）

**D1 启动前硬拦截**
- 流程：预估（映射表单价）→ 查余额 → 余额 < 预估×安全系数1.2 → 拒绝启动 + 三出口引导（充值/切免费档模型/放弃）
- 前端确认弹窗同步显示「余额不足将无法启动」提示

**D2 单价映射表**
- 内置表：免费档 ¥0、DeepSeek-V3-0324/Qwen3-235B-A22B 实测价（未知模型回退 ¥0 + 警告「该模型单价未登记，费用可能不准确」）
- 设置页「AI 服务」可编辑单价表（存 ai_settings.json）；env SILICONFLOW_PRICE_PER_1M_TOKENS 仍可整体覆盖（开发路径）

### 3.5 评测框架（F3）

**E1 内置样本集（src-tauri/fixtures/refine_golden/）**
- 3-5 个典型样本：网课讲义式（含术语/章节）、实操步骤式、口播摘要式、含表格+公式+配图场景（覆盖 image 块回归）
- 每样本 = 输入（切片 markdown + profile + glossary + chapters）+ 期望断言（章节集合、配图保留、块类型合法、schema_version=2）

**E2 回归测试（refine_golden_tests.rs）**
- 走 mock 适配器全链路（不联网）：mock v2 响应 → 协议校验 → to_markdown → 断言结构不漂移
- 提示词 golden 冒烟：固定样本断言输出结构（防提示词改动破坏契约）

### 3.6 可观测性（F3）

**G1** 任务表即用量数据源：聚合 SQL（按日/按类型：次数/费用/耗时/模型）→ 设置页「用量概览」小卡（不建完整报表页，YAGNI）
**G2** 审计补齐后 ai_audit_list 统一展示全部 AI 调用轨迹

### 3.7 错误处理与测试总纲

**H1** 每层错误归一 AiTaskFailure（四类 + server/invalid），任务表记录 error 原文
**H2** 新边界：任务表写入失败 → 内存注册表继续（不阻断 AI 调用）+ 明确日志；恢复时以任务表为准
**H3** 单片重试仍失败 → partial_failed（保留已成功片，前端显示「部分成功：x/y 片，可重跑失败片」）

**I1** 契约快照测试（A1，本次事故教训）：serde 输出 = 前端期望 JSON 字面量
**I2** 协议 v2：image 块校验/片间字段/版本兼容单测
**I3** 任务中心：CRUD/恢复/保留策略/并发计数单测（内存库）
**I4** 评测回归（E2）：mock 全链路 golden
**I5** 前端：无 Vitest 基建维持真机手动清单（契约测试已在 Rust 侧兜底）
**I6** 回归：cargo test + cargo clippy 全绿；现有 1271 测试不劣化

- 产出：全链路检测报告（P0 契约实证 + P1 八项 + 已做对清单）+ 方案三选（用户裁决 C）+ 六轴扩展全量收敛 + 里程碑四层设计

- 扩展方向全量裁决时明确「不做」清单（模型对比/人工评分/完整报表页已排除），保持窄而深
