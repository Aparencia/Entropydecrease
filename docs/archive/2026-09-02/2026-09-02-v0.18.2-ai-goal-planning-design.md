## 一、一句话

目标设定与详情页接入 **AI 目标规划师**：以访谈答案＋本地检索管道（库即记忆）为输入，AI 产出**结构化规划草案**（里程碑拆解＋建议绑定组＋**初步体系/概念建议**＋周契约建议）——**人类确认后落库**；AI 不可用时回退现有规则草案（M1 纯规则继续担当降级基线）。AI 默认关、授权确认后启用，预算档位化，全程成本/轨迹可查。

## 二、用户裁决记录（2026-09-02）

| 议题 | 裁决 |
|---|---|
| 入口 | **两处都要**：访谈第 5 步（宣言页）内嵌 + 详情页「💡 AI 规划」重规划 |
| 产物权限 | **建议制·确认后落库**（里程碑/组/体系/周契约全部草案，逐项确认/删改后写入；人类判断领地保留） |
| 体系联动 | 目标↔体系（含 **AI 提供初步体系**——无体系时建议并创建骨架）＋ 目标↔概念弱项（M3 真实化）＋ 目标↔AI 对话 `/goal`（L4.5 摘要注入）＋ 目标↔周契约（AI 建议预填） |
| 授权与成本 | **默认关 + 授权确认**（content_gate 双闸门）；预算档位化（默认标准 10K）；上报 token/成本/轨迹 |

## 三、规划师角色与交互

```
访谈第 5 步（宣言页）           目标详情页
┌─────────────────────┐        ┌─────────────────────┐
│ 四步答案（已收集）      │        │ intent_json 现取现拼   │
│ ＋ [✨ 用 AI 规划]    │        │ ＋ [💡 AI 规划]       │
│   ↓（开关默认关→授权弹窗）│        │   ↓（同闸门）          │
│  AI GoalPlanProposal │◄───────┤  AI GoalPlanProposal │
│  里程碑/组/体系/周契约草案│        │  现有目标重规划          │
│  [逐项勾选/删改] [确认落库]│        │  [预览/勾选/确认落库]   │
└─────────────────────┘        └─────────────────────┘
```

- **双入口同一协议同一组件**（`GoalPlanApprovalDialog` —— 一套草案确认流，优化评审 #4 同哲学：双轨制是入口不是两套组件）。
- **规则草案是默认基线**：宣言页先展示 `suggest_milestones` 规则草案；点「✨ AI 规划」→ 草案被 AI 建议**替换**（带"AI 建议"角标，可一键回到规则版）。
- **失败降级**：AI 不可用/JSON 校验失败/预算异常 → 诚实提示 + 规则草案继续可用（目标创建永不被 AI 阻断）。

## 四、规划协议（GoalPlanProposal，serde 强校验 + 失败整次降级）

```jsonc
{
  "milestones": [{ "title": "...", "dueWeeks": 4,
                   "criteriaType": "manual|group_settled", "refGroupId": 12|null, "note": "为什么" }],
  "groups": [{ "groupId": 12, "reason": "素材命中" }],
  "systems": [{
      "systemId": 5|null,                       // 现有体系→link；null→建议新建
      "name": "Python 基础", "coreQuestion": "...",  // 新建骨架必填（门槛校验）
      "domainEntries": ["语法基础", "..."],      // 初始问题树领域入口 ≥1
      "concepts": [{ "name": "闭包", "essence": "..." }],  // 初始概念 3-5 个（三问其余可空）
      "action": "link|create"
  }],
  "weeklyContract": { "targetDays": 3, "targetCards": 20 },
  "summary": "一句话规划说明（展示层）"
}
```

- **校验**：枚举白名单 / 字段长度上限（标题 80/说明 200）/ id 正整数 / dueWeeks ≤52 / 体系门槛（name+coreQuestion+≥1 domainEntry 缺一即整条丢弃并提示「体系建议不完整已跳过」）。
- **落库事务**：确认后按序写 goal_milestones（`goal_add_milestones` 批量命令）/ goal_groups / contracts（upsert）/ 体系骨架（复用 create_knowledge_system + add_knowledge_node + add_knowledge_concept + link，**一项一事务逐步创建**——骨架部分失败不污染目标层）。
- **响应性**：规划走 ai_tasks 任务化（复用 ai_task 状态机/轨迹/重试；完成事件推前端——规划 10K 量级输出约 10-30s，交互等待可接受；不流式，一次性 JSON）。

## 五、深度联动矩阵（本设计新增/真实化）

| 联动 | 机制 | 落点 |
|---|---|---|
| 目标↔体系 | `knowledge_links.target_type` 白名单 **+ 'goal'**（TEXT 无 CHECK，命令层白名单+1——group 先例零迁移）；目标详情「服务体系」区；体系页「服务于目标 X」反标（list_links_by_target） | 只加引用通道，体系层零侵入（只引用不收纳纪律延续） |
| 目标↔概念弱项 | 目标绑定组 → 组卡 → 概念（跨 knowledge_links）；弱信号=90 天无引用/未应用（concept_stale 判据理念）；目标详情「最弱概念」块（规则信号现算 + AI 解读可选用）；**作为 AI 规划/追问的输入** | M3 真实化（M1 版本 FSRS 弱项块保留同屏） |
| 目标↔AI 对话 | `/goal <目标名>` 命令（/refine 先例）→ L4.5 目标摘要**现算注入**（进度/里程碑/弱项/原始意图，<1K token）＋ L3 FTS 检索 top-K | ai_chat 命令解析 + 检索管道接线 |
| 目标↔周契约 | AI 建议 target_days/target_cards 预填 | 复用 upsert_week_contract（用户仍可改——弹性承诺纪律不变） |
| **初步体系** | AI 输出 systems[].action=create 骨架 → 确认后一键建体系+领域入口+初始概念＋目标↔体系引用 | 门槛校验（名+核心问题+≥1 入口）防低质骨架；用户可跳过 |

**一致性契约（延续）**：信号仍现算、零双写；AI 规划产物仅在确认后落库；目标层仍不侵入既有模块状态机（规划器是客户端编排，不是新状态机）。

## 六、治理（守项目铁律）

1. **默认关**：SettingsPage「目标 AI」段——开关（默认关）＋ 档位（轻量 4K/标准 10K/深度 30K，默认标准）＋ 授权入口；content_gate 双闸门（开关未开或未授权 → 按钮置灰「AI 规划未开启（设置→目标 AI）」）。
2. **预算硬顶**：复用 budget_allocator 纯函数（档位内：系统+摘要 ~2K｜信号 ~0.3K｜检索 ~2.4K｜滑窗 ~3K｜输出预留 ~2K）；超限按相关性截断 + 诚实提示，绝不静默；单次调用 ≤ 所选档位。
3. **成本/审计**：ai_usage 记录 token/成本；ai_tasks.trajectory 可见规划提示词/回答全文（AI 对话页任务视图）；首次发送云端提示（复用 v0.16 授权流）。
4. **降级**：除 AI 失败降级规则草案外，L4.5 摘要/弱项诊断等 AI 解读一律有纯本地信号兜底（统计数字永远可见）；信息全部本地，上传仅授权后的最小检索片段。
5. **红线**：不接 agent 框架/记忆模块/自主规划/每日推送；AI 不直接执行任何写入；体系骨架创建需用户逐项确认。

## 七、组件与命令

- **新增命令**：`ai_goal_plan_estimate`（预估+档位展示，ai_refine_estimate 范式）· `ai_goal_plan_start`（任务化，返回 taskId）· `goal_add_milestones`（批量落库事务）· `goal_link_system` / `link_goal_system_target`（目标↔体系引用，knowledge_links 白名单扩展）· `goal_concept_weakness`（概念低激活信号，规则信号现算）
- **前端组件**：`GoalPlanApprovalDialog`（双入口共用草案确认流：里程碑勾选/删改、组绑定勾选、体系 create/link 单选项、周契约预填、summary 展示、规则版回退按钮）· InterviewDialog 第 5 步「✨ AI 规划」按钮 + 草案替换态 · GoalDetail「💡 AI 规划」入口 + 「最弱概念」块 · SettingsPage「目标 AI」段
- **纯函数（TDD golden）**：`goal_plan_protocol.rs`（Proposal 解析/白名单/长度/门槛校验——table-driven）、`goal_plan_prompt.rs`（检索上下文→提示词组装，含档位截断）、`goal_summary.rs`（L4.5 摘要现算，<1K token 预算）、`budget_allocator.rs`（档位/排序截断/降级信号——v0.18 规格已设计，本批落地）、`concept_weakness.rs`（概念低激活信号）

## 八、测试与验收

- **纯函数 TDD**：Proposal 校验矩阵（合法/缺门槛/超长/非法枚举→整条丢弃/整次降级）；提示词组装；预算 O(1)（任意大输入→恒定输出）；摘要组装；概念弱激活边界（90 天/未应用）
- **命令层**：确认流落库（里程碑/组/契约/体系骨架分步事务——部分失败不污染目标层）；knowledge_links 白名单 +'goal' 回归；权限双闸门路径（未开/未授权 → 拒绝）
- **前端 Vitest**：GoalPlanApprovalDialog（勾选/删改/体系 create vs link/规则回退）；InterviewDialog AI 按钮态（未开启灰显/开启后替换草案）；GoalDetail 弱项块与重规划入口
- **验收（用户）**：① 默认关——未授权时规划按钮灰显且提示 ② 开启授权后：访谈第 5 步一键出规划、双入口一致、逐项确认落库 ③ AI 建议初步体系→确认→体系骨架+概念+目标引用即现，体系页见「服务于目标 X」 ④ 对话页 `/goal` 问「Python 我学到哪了」→ 摘要注入回答 ⑤ 周契约预填可改 ⑥ 断开 AI（关开关/断网）→ 全部功能回退规则草案正常建目标 ⑦ 每次规划成本/trajectory 在 AI 任务可见 ⑧ 回归：cargo test / clippy / vitest / tsc 全绿
