# v0.14 子项目 D：采集质量攻坚设计规格（结构 / 质量 / 算法 / 平台 四层）

> 状态：✅ 已批准（2026-08-28，逐节确认）
> 所属版本：v0.14
> 范围：子项目 D——章节级混合形态笔记 / 双维决策质量门控 / 版面重建+行合并+跨帧增量+行级重识别 / 平台模板适配

## 1. 背景与目标

### 1.1 痛点（用户反馈，2026-08-27~28）

| # | 痛点 | 现状根因 |
|---|------|----------|
| D1 | PPT 型视频知识内容可视但笔记仍口语化 | v0.11.5 决策：`assemble_markdown` 将 OCR 画面要点移出笔记正文（笔记只剩口语转写）；"转文字+手动梳理"优于"采集-转化" |
| D2 | OCR 产物质量偏低，喂 AI 只增 token 消耗 | 净化链是"字幕思维"（按时间戳线性拼接），对 PPT 版面结构性错误；bbox 已落库（v0.5.0）但从未使用；无质量评估，低质量 OCR 照样进正文/喂 AI |

### 1.2 用户关键纠正

> "问题在于不是所有的视频都有 ppt，而且一个视频内也可能存在两个部分。"

**不能做视频级二分法**——形态决策必须下沉到**章节级**。

### 1.3 目标

1. **章节级混合形态**：整篇笔记 = 图文章节 / 口语章节混编，每章独立决策
2. **质量门控**：低质量 OCR 不进正文、不喂 AI（省 token）；质量分诚实呈现
3. **算法提质**：屏内版面重建（bbox 空间排序）+ 行合并评分器 + 跨帧增量合并 + 行级重识别（官方 adapter 编排自研）
4. **平台适配**：B站/抖音/Edge 视频区 ROI + 字幕带先验 + 噪音区掩码（噪音从源头消失）
5. **全链路零新增 token 成本**：规则方案，可单测，有降级

## 3. 架构设计

### 3.1 四层数据流

```
采集（关键帧 + bbox + 时间戳）
  │
  ├─ D4 平台层：视频区 ROI 裁剪 / 字幕带先验 / 噪音区掩码（OCR 前）
  ▼
OCR 净化链（D3，重构 note_filter_ocr.rs）：
  排序 → ① 行合并评分器 → ② 行级重识别（疑碎行）→ ③ 跨帧增量合并 → 净化 → 去重
  │
  ├─ D1 结构层：章节边界检测 → 每章形态决策（图文/口语）
  ▼
D2 质量层：ocr_quality_score 门控 → 图文章节（达标）/ 口语章节（弃用/退回）
  │
  ├─ 笔记出口：图文章节 OCR 主体 + 口语引用块 / 口语章节现状形态
  └─ AI 出口：仅达标图文章节 OCR 进精修输入（提示词标注修正错字）
```

## 4. 详细设计

### 4.1 D1 章节级混合形态

**章节形态决策**（`chapter_morph.rs` 纯函数）：

```
输入：章节内屏卡集合（含 OCR 密度）+ ocr_quality_score
决策：密度 ≥ DENSITY_TH && 质量 ≥ QUALITY_TH → 图文
      密度 ≥ DENSITY_TH && 质量 <  QUALITY_TH → 口语（OCR 弃用，原料视图可查）
      密度 <  DENSITY_TH → 口语（现状形态）
边界：无章节边界 → 全篇退化现状；全高密度 → 整篇图文；空章节跳过
```

**图文章节组装**（concat.rs 扩展）：
- 主体：OCR 屏卡要点（版面重建后的段落）
- 口语降级为引用块（`> 讲者：...`，保留时间戳锚点）
- 章节标题复用 `detect_outline_smart` 屏标题资产

### 4.2 D2 质量分与门控

**`ocr_quality_score`**（章节窗口内，四信号加权）：

| 信号 | 计算 | 权重 |
|---|---|---|
| 置信度 | OcrBlock.score 加权均值 | 0.4 |
| 碎片率 | ≤4 字块占比（越低越好）| 0.2 |
| 连贯性 | 行合并后句长分布（可成句 → 高）| 0.2 |
| 噪音比 | UiJunkList 命中率（越低越好）| 0.2 |

- **阈值**：`QUALITY_TH = 0.6`（可配置，初值经 golden 用例校准）
- **AI 出口门控**：精修输入组装时过滤低质量章节 OCR（省 token）；达标章节提示词标注"以下为屏幕 OCR 内容，请优先修正错字后使用"
- **质量报告**：会话详情显示"本章节 OCR 质量 72 分，已采用/已弃用"（quality_report.rs 哲学延续："指标从恒 ≈0 变真实"）

### 4.3 D3 算法层

**屏内版面重建**（`layout_reorder.rs`，简化 XY-Cut）：
1. 行聚类：y 坐标容差（±8px）内归行
2. 行内排序：x 升序
3. 栏检测：相邻行稳定列间隙 → 多栏分组（栏内 y 序、栏间左→右）
4. 标题识别：最大字号/最短文本行 → 标题（复用屏标题资产）
5. 段落拼接：行间隙小的块合并为段落

**行合并评分器**（`line_merge.rs`）：

```
几何信号：垂直重叠 > 50%（同行）/ 水平间隙 < 半字宽 / 行高一致
文本信号：A 尾虚词（的/了/是/在/与…）→ 续接；A 尾句号/问号 → 断开；
          B 首项目符号（•/-/1.）→ 新要点
护栏：合并超长回退；字体差 > 30% 不合并（标题+正文）
反误合并原则：宁可少合并（损失完整性）不可错合并（制造幻觉句子）
```

**跨帧增量合并**（`incremental_merge.rs`）：
```
帧2 文本 ⊇ 帧1 文本 && bbox 位置稳定 → 同屏增量合并（动画逐行出现）
bbox 整体位移 → 翻页 → 新屏
```

**行级重识别**（`line_rec_engine.rs`）：
```
疑碎行判定：碎片率高（≤4 字块占比 > 阈值）或 置信度 < 阈值
流程：行聚类 → 行图裁剪（bbox 并集 + padding）→ TextRecognitionAdapter::execute（批量）
      → 行级文本替换碎片文本（行级得分取均值）
降级：adapter 构建失败 → 保留碎片结果（能力降级不失效）
挂载：engine.rs 常驻引擎池（OCR worker 线程）
```

### 4.4 D4 平台模板

**平台识别**：窗口标题/URL → `platform_layout.rs`（bilibili/douyin/youtube/edge-local/unknown）

**模板数据**（`platform_templates.json`，数据非代码）：

```json
{
  "bilibili": {
    "videoRoi": [0.15, 0.08, 0.62, 0.72],
    "subtitleBand": { "y": 0.82, "h": 0.10 },
    "noiseMasks": ["danmaku_band", "right_recommend"]
  },
  "douyin": {
    "videoRoi": [0.0, 0.12, 1.0, 0.8],
    "subtitleBand": { "y": 0.60, "h": 0.15 },
    "noiseMasks": ["right_comments", "left_likes"]
  }
}
```

**三层降级**：命中模板 → 用模板；未命中 → 几何兜底（黑边检测/动态区域/宽高比）；全失败 → 现状全窗口 OCR。

**收益**：OCR 只在视频区 ROI 内跑 → 弹幕/推荐流/评论区噪音从源头消失；字幕带先验让 `subtitle_detect` 从"盲找"变"带先验找"。

## 5. 错误处理

- **adapter 构建失败**：行级重识别跳过，保留碎片结果（净化链照常）
- **模板 JSON 解析失败**：跳过模板层，走几何兜底
- **章节边界缺失**：全篇退化现状（无回归风险）
- **质量分计算异常**（空章节）：按最低分处理（OCR 弃用，宁缺毋滥）

## 8. 决策记录

| 决策 | 结论 | 理由 |
|---|---|---|
| 形态粒度 | 章节级（非视频级）| 用户纠正：无 PPT 视频 + 一视频双部分 |
| 质量门控 | 密度 × 质量双维 | 低质量不沉淀、不喂 AI（省 token）|
| 行合并 | 几何+文本信号评分器 | 零 token、可单测；宁可少合并 |
| 行级重识别 | 官方 TextRecognitionAdapter 编排自研 | rec-only API 不存在；adapter 公共 API 已源码验证 |
| 跨帧增量 | 包含关系 + bbox 锚定 | 解决 PPT 动画逐行出现（现有去重失效场景）|
| 平台适配 | 模板 JSON + 几何兜底三层 | 改版只改数据；能力降级不失效 |
| 精修链路 | 结构引擎（A'）作增强 | 模型重（129MB+231MB），不进实时链路 |
