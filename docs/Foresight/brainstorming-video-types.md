## 轮次 1：哪些类型视频，用户会想提取内容

### 驱动因素（提取欲望的四变量）

| 变量 | 含义 | 推论 |
|---|---|---|
| 信息不可逆性 | 声音/画面流过即失，无法像文字一样回看 | 口播 > 有字幕 > 有讲义的课 |
| 知识密度 | 每分钟新信息量 | 网课 >> 纪录片 >> 综艺 |
| 复用/检索频率 | 以后还会回来查 | 工具教程 > 一次性资讯 |
| 记忆必要性 | 学了必须记住/用出来 | 备考课 > 兴趣科普 |

> 核心反直觉点：用户最想提取的不是"最好的课"，而是"**不得不学、但时间紧或难回看**"的视频。

### 九类视频 × 提取欲望

| # | 类型 | 例子 | 欲望 | 想提取什么 |
|---|---|---|---|---|
| 1 | 结构化教学（网课/录播） | MOOC、付费系统课 | ★★★★★ | 章节笔记、考点、可复习要点 |
| 2 | 步骤实操类 | 软件教程、化妆、编程跟练 | ★★★★★ | 分步指南 + 关键帧 + 参数/代码 |
| 3 | 口播知识类 | 知识区UP、TED | ★★★★☆ | 结构化摘要、观点、可检索文字 |
| 4 | 长访谈/播客 | 行业对谈、播客 | ★★★★☆ | 金句、观点提炼、时间轴索引 |
| 5 | 会议/汇报 | 周会、评审、培训 | ★★★★☆ | 结论、待办、决议 |
| 6 | 直播回放 | 技术直播、发布会 | ★★★☆☆ | 精华切片、QA 要点 |
| 7 | 纪录片/科普 | 人文历史纪录片 | ★★☆☆☆ | 轻量摘要 |
| 8 | 新闻/短视频碎片 | 时政热点 | ★☆☆☆☆ | 几乎不提取 |
| 9 | 影视/纯娱乐 | 剧、综艺 | ☆☆☆☆☆ | 无 |

### 按用户身份分层

- **技能自学者**（核心目标）：类型 1/2/3，学会→应用→检索
- 网课学生（应试）：类型 1，记住→考试，闪卡闭环价值最大
- 职场人：类型 4/5，复盘→产出（会议场景竞品强）
- 创作者：类型 3/4/6，素材→二次创作
- 通识爱好者：类型 7/8，兴趣→拓宽，欲望弱

### 按信号特征切（决定提取技术路径）

| 信号特征 | 代表类型 | 技术路径 |
|---|---|---|
| 有字幕 | 网课、B站教程 | 字幕优先（无损信道） |
| 纯口播无画面文字 | 播客、访谈、知识区 | 纯 ASR + hotwords 纠偏 |
| 板书/PPT/代码密集 | 网课、编程教程 | ASR + OCR 双通道（OCR 价值峰值） |
| 动作型（文字极少） | 化妆、健身、木工 | ASR + 关键帧截图，需"步骤卡"设计 |
| 多人对话 | 访谈、会议 | ASR + 说话人分离（远期） |

### 反例清单（用户不想提取的）

影视/综艺/音乐（情绪消费）、新闻/热点（即时消费）、纯氛围类（无信息）、社交内容（非知识）、高艺术性内容（体验 > 信息）。

### 优先级结论

- **P0（MVP 核心）**：结构化教学 + 步骤实操 + 口播知识
- **P1（早期扩展）**：访谈/播客 + 会议
- **P2（远期/不做）**：直播回放切片、纪录片

> **差异化空档**："步骤实操 + 代码板书"是通义听悟/讯飞覆盖最差的象限，也是"技能自学者"定位的主场。

## 轮次 2：如何根据特定视频类型进行优化

### 核心思路：VideoProfile 档案驱动

优化 = 为每种类型预设「采样预算 × 信号权重 × 后处理规则 × 产物模板」，运行时按档案驱动管线（对应机制清单 [E9]）。

### 检测层（三方案）

| 方案 | 做法 | 结论 |
|---|---|---|
| A 手动选择 | 会话开始前选类型 | 零误判、多一步 |
| B 自动检测 | 信号投票 | 零摩擦、误判高 |
| **C 混合（采纳）** | 自动出候选（窗口标题 A5 已入库/画面切换/字幕有无）+ 用户确认 + 记忆偏好 | 摩擦与准确率平衡 |

### 五类优化矩阵

| 类型 | 采样 | 信号权重 | 后处理 | 产物形态 | 预算 |
|---|---|---|---|---|---|
| 结构化教学 | 低帧率全帧 + PPT 翻页检测 | 字幕 > OCR(板书) > ASR | 章节检测 C1 + 大纲 + 术语表 C3 + 课件预热标题树 | 章节化笔记 + 大纲 + 术语表 | OCR 偏重 |
| 步骤实操 | 关键帧差异化采样 | ASR > OCR(UI/参数) | 帧聚类 B6 → 步骤卡 + 步骤语音摘要 | 步骤卡图集 | 帧处理偏重 |
| 口播知识 | 低帧率 | ASR 全权重 | 口语书面化 B5 + 重点标注 C2 + hotwords | 结构化摘要 + 时间轴索引 | ASR 全投 |
| 访谈/播客 | 极低帧率 | ASR 全权重 | 说话人变化检测 A3 + 金句提取 | 问答结构 + 讲者标注 + 金句 | ASR 全投 |
| 会议/汇报 | 极低帧率 | ASR 全权重 | A3 + 结论/待办识别（触发词规则） | 会议纪要（决议/待办） | ASR 全投 |

### VideoProfile 数据结构草案

```
VideoProfile {
  类型标识        // lecture / hands-on / talking-head / interview / meeting
  检测信号集      // 标题关键词、画面切换阈值、字幕有无、时长
  采样预算        // { 全帧fps上限, 关键帧触发条件, 差异化增益 }
  信号权重        // { 字幕优先?, OCR权重, ASR权重 }
  后处理规则集    // { 书面化强度, 章节检测, 帧聚类, 说话人检测, 术语表 }
  产物模板        // 产物块骨架 + 卡片生成规则
}
```

## 轮次 3：如何配套图片

### 图片必要性分级

- **画面即信息**（实操/编程/绘画）：无图无法理解 → 必需
- **文字难表述**（板书/公式/图表）：转写失真 → 高价值
- **记忆增强**：闪卡配图（远期）
- 口播/访谈/会议：画面几乎无信息 → **不配图**（资源留给实操类）

### 三层图结构

| 层 | 是什么 | 放哪 | 用途 |
|---|---|---|---|
| 关键图（每章节 1-3 张） | 多信号投票高置信帧 | **内嵌笔记正文** | 理解 + 记忆 |
| 参考图集（每会话 10-30 张） | 簇首帧全集 | 会话画廊 | 回溯 + 检索 |
| 缩略图走廊 | 极缩略图流 | 时间轴导航条 | "我记得有个图"跳转 |

### 筛选信号投票（纯本地规则）

| 信号 | 含义 | 成本 |
|---|---|---|
| 感知哈希帧聚类（B6） | 相似帧聚簇，簇首帧代表 | 低 |
| OCR 文本 diff | 新文字 = 新图 | 低 |
| 画面变化幅度 | 操作切换/演示动作 | 低 |
| 画面停留时长 | 10s+ = 讲师认为重要 | 低 |
| **用户显式截图 = 最高权重** | 用户自己觉得重要的时刻 | 零 |

> 关键洞察：用户按下的"截图键"是最强信号，且可反哺筛选阈值（D1 用户确认回路）。

### 图文对齐

- 图片携带时间戳 ↔ 段落时间戳 → 按时间轴交错渲染
- **以文搜图**：OCR 已提取图内文字 → 关键词搜索直接命中图

### 采图策略并入档案

`VideoProfile + { 聚类开关, 采图触发信号, 关键图阈值, 产物位置 }`；口播/访谈类省下的预算补给实操类高频采样。

## 轮次 4：非线性排布文字如何预处理

### 问题本质：行文本 OCR 在三个层面系统性崩坏

| 层面 | 崩坏方式 | 例子 |
|---|---|---|
| 检测层 | 图形误检为文字；列粘连成行 | 箭头"→"被识别；表格两列并一行 |
| 识别层 | 字符关系压平 | x² → x2；H₂O → H2O |
| 顺序层 | 读序错乱 | 表格行/列序、流程图箭头序、两栏 |

### 预处理管线四层

```
L1 图像增强（传统 CV）：CLAHE / 自适应二值化 / 小字放大2x / 背景纹理抑制
L2 版面分区：线条检测 + 连通域 + 文本密度 → text/table/formula/code/image/unknown
L3 结构重建（分类型专用）：表格网格重建 / 公式上下标规则 / 代码块缩进 / 区块拓扑排序
L4 融合增强：多帧投票 / OCR×ASR 交叉 / hotwords 符号短语表
```

### 视频时序红利（本项目特有）

静态图 OCR 需"从结果反推结构"（难）；实时链路只需"记录结构出现过程"（易）：

| 视频行为 | 免费信息 |
|---|---|
| PPT 动画逐行出现 | 出现顺序 = 阅读顺序 |
| 白板逐步书写 | 书写顺序 = 结构顺序 |
| 表格先画线再填数据 | 时间戳分组 = 行列归属 |
| 代码逐行敲出 | 天然代码块 + 行序 |

> 架构启示：**差异化采样 + 增量帧 diff 天然给出结构事件流**——比任何版面分析模型都廉价，应作为结构重建的第一输入。

### 能力边界（本地约束）

- ✅ 0.5.0 可做：图像增强、规则版面分区、线条表格重建、渲染公式上下标、代码块、时序红利、多帧投票
- ⚠️ 半做：无线表格、嵌套公式、化学式条件位、箭头引导读序
- ❌ 不做：手写公式、乐谱、图表数据提取、语义化、完整 LaTeX 还原（模型版/云端）

## 轮次 5：五类档案的产物形态总览

### 统一原则：一种原料，五种模板

```
原料层（已存在）      SessionDetail：segments[] + ocr_blocks[] + 帧/图
加工层（0.5.0 新增）  Artifact：按档案模板组装的块序列（有序 Blocks[]）
持久层（已存在）      Note（Markdown 渲染）+ 远期闪卡
```

产物**引用**而非复制原料（块携带 segment/ocr/frame id + 时间戳）——原料可回看、可重算（G1 派生视图地基）。

### 五类产物

| 档案 | 产物 | 核心块类型 | 图片角色 | 主要依赖 |
|---|---|---|---|---|
| 结构化教学 | 讲义式笔记（目录/章节/术语/小结） | Paragraph/KeyImage/Table/Formula/TermAnchor | 内嵌关键图 | C1/C3/C4 |
| 步骤实操 | 步骤卡图册（一卡一步 + 走廊索引） | StepCard{frame_ref, segment_ref, range, note} | **主角**（每卡一图） | B6/B8 |
| 口播知识 | 结构化摘要文（观点/论据/金句/索引） | Claim/Argument/Quote/KeywordIndex | 无 | C2/B5 |
| 访谈/播客 | 对话纪要（问答结构/讲者/亮点） | QAPair/Highlight/TopicNode | 无 | A3 |
| 会议/汇报 | 会议纪要（决议/待办置顶） | Decision/Todo/AgendaSection/ScreenShot | 附件归档 | A3+触发词 |

### 关键结论

`Artifact = Template(profile) × Blocks[]`——数据模型只需加"块"概念（`ArtifactBlock{kind, refs, payload, order}`），五类产物 = 五个模板函数。与 E9"档案 = 纯配置"一致。

## 轮次 6：补缝式 AI（Gap-filling AI）——只传本地识别不了的，返回可渲染结构

### 结论：可行，且是"本地优先"铁律下的最优形态

把"AI 增强"从"锦上添花"改为"**兜底补缝**"：本地管线全量跑，只有明确判定为"本地做不了/做不好"的块才触发云端理解，AI 返回结构化块，本地直接渲染。

| 铁律 | 满足方式 |
|---|---|
| 数据不出本机 | 上传单块裁剪图 + 最小上下文，暴露面缩小几个数量级 |
| AI 默认关闭、用户授权 | 触发点收敛（本地失败块）+ 全局开关 + 每次授权 |
| 离线降级 | AI 失败 → 本地低置信结果照常渲染 |

### 可行性三前提

1. **本地必须能"判定自己不行"**——B3 置信度 + 版面分区 + 重建失败标记构成判定器
2. **返回必须是"结构"不是"文本"**——与本地块同构，渲染器统一处理
3. **本地结果必须保留**——AI 是叠加层不是替代层（B3"可校对原料"定位）

### 返回协议草案（V1.0 与 Qwen-VL 契约）

```json
{
  "kind": "ai_enhanced",
  "source_ref": { "frame_id": 1024, "crop": [0.1, 0.2, 0.8, 0.6] },
  "context": { "prev_asr": "…", "next_asr": "…" },
  "content": {
    "type": "table | formula_latex | flowchart | diagram | handwriting | chart_data",
    "markdown": "| A | B |\n|---|---|\n| 1 | 2 |",
    "latex": "x = \\frac{-b \\pm \\sqrt{b^2-4ac}}{2a}",
    "nodes": [ { "id": "n1", "text": "…", "edges": ["n2"] } ]
  },
  "confidence": 0.92
}
```

### 协议关键设计点

块级粒度（单裁剪图+前后 ASR）/ schema 强校验（失败丢弃 AI 结果）/ 同图缓存（帧 hash）/ 成本护栏（配额+队列+超时）/ 来源标记（`ai-enhanced` 永远可辨认）/ 审计日志。

### 诚实边界

- 隐私红线：裁剪图可能含敏感信息 → 上传前预览 + "此块将上传"提示 + 可全关 + 默认关
- 判定器误判 → 阈值可配 + 用户逐块拒绝并"记住拒绝"（D1 回路）
- 体验分裂 → 来源标记 + 全局"仅本地"视图
- 网络依赖 → 降级为本地结果 + "AI 增强待网络"占位，永不阻断

## 追加讨论（同轮次后续）

### 1. 版面分析先行，再分区域 OCR（确认采纳）

工业界成熟范式（PP-StructureV3 / LayoutLM / 通义听悟同架构）：**版面分析（区域类型分类）→ 分区域专用管线 → 结构化输出**。

- 版面分析提高的是"内容正确还原率"（检测质量/结构保真/读序正确），不改变单字符识别率（CER）——对非线性内容，"有序+结构对"是 99% 的价值
- 本项目优势：输入是已知播放区域的视频帧（REQ-037 已锁定）——规则版版面分析在受限世界里可能比通用模型版更准更省
- **版面分析的三重收益**：采样预算按区域价值分配（REQ-039 升级）/ 区域类型→产物块类型直接映射 / unknown 区→补缝 AI 入口

### 2. 专项 OCR 模型调研

| 内容类型 | 专用模型 | 结论 |
|---|---|---|
| 公式 | ✅ pix2tex / **UniMERNet**（PP-StructureV3 同源，中文好） | 本地可行 |
| 表格 | ✅ **SLANet**（PP 同源，输出 HTML 结构，单元格文字仍靠普通 OCR） | 本地可行 |
| 版面分析 | ✅ DocLayout-YOLO / PP-StructureV3 layout | 本地可行（spike 项） |
| 流程图 | ❌ 无成熟轻量模型（图结构理解是语义任务） | 规则版 + AI 补缝 |
| 图表数据 | ⚠️ DePlot 等全是 LLM 系 | 直接走 AI 补缝 |
| 乐谱 | ❌ 无 | 超出范围 |
| 代码块 | 无专用模型（普通 OCR + 后处理） | 规则版即可 |

### 3. 从现有 OCR 更换到版面分析模型的工作量评估

- **前提澄清**：版面分析不是"更换 OCR 模型"而是"增补 layout 模型"——正确架构是 `layout 模型（新增）→ 区域分类 → 区域裁剪 → 现有 oar-ocr（不动）→ 分区域识别`
- **方案 A 整套更换**（paddleocr-rs 全家桶）：4-6 周+，不推荐——历史上已因上游 ndarray 冲突否决；版面能力与方案 B 完全一样，却承担全部回归风险
- **方案 B 增补 layout 模型（推荐）**：约 2-3 周——ORT 兼容 spike（2-3 天）+ 模型分发（复用 ModelScope）+ `layout.rs` 封装 + 编排改造（复用 `OcrEngine::recognize_image`，零改动）+ 回退链 + 区域→块映射 + 测试基准
- **关键洞察**：编排层先按"区域类型"设计，规则版→模型版只是换 `LayoutAnalyzer` 实现，编排代码零改动

### 4. 版面分析后的区域截图流程确认

```
原始帧 → ① 版面分析 → 区域列表
       → ② 逐区域裁剪（内存内 crop，不落盘）+ 区域级预处理（表格放大2x/公式高对比度）
       → ③ 分区域 OCR（现有引擎复用）→ 坐标还原（原帧坐标 = 区域坐标 + 裁剪偏移）
```
工程细节：裁剪带边距（10-20px）/ 坐标还原是纯函数必须单测 / 跳过 image 区总像素不增反减 / 多区域调用需"每帧最多 N 区"封顶 / **字幕区不进版面分析**（独立 ROI 高频管线）/ 低置信区域可局部放大重试一次。
