# 投喂指南：机制摘要文档结构说明

> **配套文档**: [brainstorming-classroom-assistant-mechanisms.md](./brainstorming-classroom-assistant-mechanisms.md)
> **用途**: 说明机制摘要文档的结构与使用方法，供人类读者理解，或作为"喂给其他 AI 模型时的使用说明"一并投喂。
> **一句话定位**: 机制摘要 = 一个自带"作业要求"的知识包——其他 AI 拿到它，无需访问仓库，即可基于系统现状做增量头脑风暴。

---

## 1. 这份文档是什么

| 项 | 内容 |
|----|------|
| 文档类型 | 头脑风暴输入包（机制摘要） |
| 服务对象 | 其他 AI 模型（无仓库访问权） |
| 核心目标 | 让新 AI 在**不重复已知答案**的前提下，产出**增量机制** |
| 关键设计 | "禁止清单"（§1.4/§1.5）+ "已知答案"（§1.3/§3）+ "作业要求"（§0）三者同文 |

## 2. 整体结构一览

| 章节 | 一句话内容 | 投喂时的作用 |
|------|-----------|-------------|
| §0 给其他 AI 的使用说明 | 头脑风暴任务书：任务/约束/评分/产出格式/禁止项 | **作业要求**，随文档一起给 AI |

| §2 核心研究结论 | 外部研究事实 + 来源（ASR/音频/捕获/OCR/ORT） | **事实依据**，防 AI 编造 |
| §3 机制候选清单 | 42 项新机制（7 域 A–G），各带原理/成本/风险/时机 | **已知答案**，AI 在此之上增量 |

| §5 开放问题 | 7 个待 spike/实测项 | **AI 的加分题**，优先回答 |
| §6 回顾与边界 | 组合关系 + 铁律重申 | 防跑偏 |

## 3. 逐节详解

### §0 给其他 AI 模型的使用说明（任务书）
- **作用**：把"你是来干嘛的、不能干嘛、怎么交作业"一次说清，AI 不需要猜。
- **关键内容**：三个任务方向（提新机制 / 改进既有机制 / 挑冲突矛盾）；硬约束（本地优先、无云依赖、Windows-only、防御性编程）；评分公式（可行性×影响力×创新性）；产出格式（表格模板）；禁止项（重复已否决清单、违反铁律）。
- **投喂注意**：这段就是 prompt 骨架。投喂时把它与 §1.4/§1.5/§3 一起给，AI 才能"带着约束做增量"。

### §1 系统快照（机制地图）
- **1.1 产品与定位**：技能自学者的视频知识提取应用；本地优先；对标通义听悟/讯飞听见。给 AI 建立"这东西是干嘛的"。
- **1.2 架构与数据流**：ASCII 架构图 + 关键机制说明（引擎池/双速率调度/字幕投票/融合规则/流式 ASR/会话数据）。给 AI 建立"数据怎么流动、瓶颈可能在哪"。
- **1.3 已实现机制清单**（25+ 项）：按域（采集/ASR/OCR/融合/存储/前端）列出。**作用是防 AI 把已做的东西当新想法再提一遍**。
- **1.4 已排期机制（v0.4.0 M0–M6）**：GPU 卸载/动态 ROI/实时字幕体验/预算制/热词闭环。**第二道防重复线**——但这部分允许 AI"借壳组合"（如 B3 依赖 M1 的 device status）。
- **1.5 已否决/搁置清单**：mpv IPC、剪贴板捕获、完整 diarization 等。**第三道防重复线**，除非有突破性依据。
- **投喂注意**：如果目标 AI 上下文预算有限，1.2 的架构图和 1.3 表格可以精简，但 1.4/1.5 必须全量保留。

### §2 核心研究结论
- 五个小节：流式 ASR 前沿（热词/两遍解码/SCD/forced alignment）、音频前端（RNNoise/AGC）、屏幕捕获（DXGI vs WGC）、OCR 与 ORT 性能（DirectML/量化/线程/arena）、可靠性方向。
- **作用**：给 AI 一个"外部事实基线"，防止编造或重复调研；每节都有方向性结论（哪些值得试、哪些已否决）。
- **投喂注意**：告诉 AI "这些是已核实的结论，引用它们作为论据，但标注需实测的项（文档已标）"。

### §3 机制候选清单（核心交付物）
- 42 项机制分 7 域：A 信号源与输入前端 / B 提取与识别质量 / C 内容组织与产物形态 / D 反馈闭环与学习回路 / E 性能与资源 / F 可靠性与韧性 / G 架构与可扩展性。
- 每条统一字段：**机制名 / 原理 / 为什么有效 / 成本 / 风险 / 时机**（[v0.4]=可并入当前版本 / [v0.5]=下一版本 / [V1.0]=已排远期 / [远期]）。
- **投喂注意**：这节的正确用法是"已知答案集"，要求 AI：① 提出清单外的新机制；② 对清单内机制提出更优实现路径；③ 挑出冲突/冗余/违反约束的条目。**不是让 AI 复述清单**。

### §4 快速评估（ROI 排序）
- 前 15 名带可行性/影响力/创新性打分与时机建议。
- **投喂注意**：允许 AI 挑战打分（比如认为某条可行性被高估），但挑战要有依据。

### §5 开放问题（需 spike/实测）
- 7 个待验证项（环回降噪净收益、SCD 质量、ORT 配置暴露面、置信度可用性、开销实测、词级对齐替代、PPT 预热解析）。
- **投喂注意**：建议 AI 优先围绕这些问题展开——它们是最可能产出"高价值新机制"的空白区。

### §6 回顾与边界
- 重申：机制清单是 v0.4.0 **之外**的增量；全部遵循本地优先；性能类机制以"先测量后优化"为前提。
- **投喂注意**：这段是收尾校验，防止 AI 交作业时跑偏。

## 4. 投喂方式建议

| 方式 | 投喂内容 | 适用场景 |
|------|---------|---------|
| **全量投喂** | 整个 md 文件 + §0 任务书（原样） | 单模型深度头脑风暴，产出质量最高 |
| **精简投喂** | §0 + §1.4 + §1.5 + §3 + §6（其余口述） | 多模型并行发散，节省上下文预算 |
| **分域投喂** | §0 + 指定域（如仅 E 性能域）+ §1.4/1.5 | 针对某一维度深挖 |
| **挑战模式** | §0 的"任务方向 3" + §1.3/1.4/1.5 | 让 AI 审阅现有机制找漏洞 |

### 推荐 prompt 模板（全量投喂）

```
你是"熵减"桌面应用（本地课堂助手）的机制研究顾问。以下是该产品的机制摘要文档，
包含系统现状、已排期机制、已否决清单和 42 项候选机制。请完成：

1. 阅读 §1 系统快照，理解产品约束（本地优先铁律：数据不出本机、云端能力必须有
   本地兜底、Windows-only）。
2. 阅读 §2 核心研究，作为你的事实基线。
3. 针对 §3 机制候选清单，输出三部分作业：
   a. 新增机制：提出清单外的机制（编号建议 A8/B9/C9/... 顺延），每条含
      原理/为什么有效/成本/风险/时机（[v0.4]/[v0.5]/[V1.0]/[远期]）；
   b. 改进路径：对清单内任一条给出更小成本或更优的实现路径；
   c. 冲突审查：指出清单中与现有机制（§1.3/1.4）冲突、冗余或违反铁律的条目。
4. 优先围绕 §5 开放问题展开（这些是研究空白区）。
5. 产出格式：表格（编号/机制名/原理/为什么有效/成本/风险/ROI/时机），
   并按可行性×影响力×创新性打分排序。
6. 禁止：重复提出 §1.5 已否决清单中的机制；建议违反本地优先铁律的方案；
   复述 §3 已有条目而不做增量。
```

## 5. 推荐使用流程（多模型协作）

```
第 1 轮（发散）: 3-5 个模型各自全量投喂 → 各交一份增量机制表
第 2 轮（评估）: 汇总去重 → 按评分公式（可行性×影响力×创新性）排序
第 3 轮（收敛）: 排名前 N 的机制 → 对照 §5 开放问题 → 立项 spike/写进下版规划
```

## 6. 常见问题

- **Q: 直接丢整个文件给 AI 就行吗？** 可以，§0 已是任务书；但建议把 §0 的作业要求单独再强调一遍（见 prompt 模板），AI 对"表格里的任务说明"敏感度低于"直接指令"。
- **Q: 为什么要有"已实现/已排期/已否决"三张防重复表？** 无约束头脑风暴最常见失败模式就是重复已知答案；三张表把"已知"划清边界，逼 AI 做增量。
- **Q: 新机制怎么进版本规划？** 对照时机字段：标 [v0.4] 的并入当前版本排期；[v0.5]/[V1.0] 的写入下版规划；所有机制落地前过 §5 对应 spike。
